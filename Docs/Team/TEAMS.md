# Команды: состав, подгруппы и стартовые задания

Это дополнение к `Docs/Team/HANDOVER.md`. Здесь всё, чтобы новый тимлид (человек или нейросеть) поднял команды с нуля: что делает каждая команда, в какой подгруппе живёт и каким сообщением её запустить. Обновлено: 2026-11-18.

## 1. Как развернуть команды

1. **Тимлид** — одна сессия Claude Code в корне проекта (`C:\!!!Work\CodeCraft_HomeWork_ATOMIC`), ветка `game/develop`. Сначала читает `HANDOVER.md`, этот файл, `Docs/Game/GDD.md` и `Docs/Rules/*`.
2. **Каждая команда — отдельная сессия.** Своя рабочая копия git (`.claude/worktrees/<имя>`), своя ветка `claude/<задача>`, ответвлённая от свежего `game/develop`. В приложении Claude это `start_session` с `use_worktree: true`, `context: "fresh"` и текстом из раздела 3 как заданием. Без приложения — `git worktree add .claude/worktrees/<имя> -b claude/<задача> game/develop` и отдельный запуск Claude Code в этой папке.
3. **Подгруппы в боковой панели.** Создать группы (`create_group`) и разложить в них сессии (`move_sessions`):
   - **«Воксельная игра · Руководство»** — тимлид;
   - **«Воксельная игра · Геймплей»** — ядро, арены, боевые системы, AI, меню, звук;
   - **«Воксельная игра · Воксели и разрушение»** — структура, грунт, «танк и воронка», вокселизатор, эффекты;
   - **«Воксельная игра · Платформа и качество»** — производительность, рендер, геймдизайн (на паузе).
4. **Поднимать только нужное.** Команды, у которых нет задачи, не запускать: каждая сессия тратит лимит токенов. Сейчас (2026-11-18) недельный лимит аккаунта почти исчерпан.
5. **Общение.** Команда пишет тимлиду отчёт: ветка, коммит, цифры, что не проверено. Тимлид вливает в `game/develop` только после «да» пользователя (см. `HANDOVER.md`, раздел 3).
6. **Общие правила для всех команд вставлять в каждое задание:**
   - редакторы без окон: компиляция и тесты в `-batchmode`, живой редактор только свёрнутым, один на машину, закрывать по PID;
   - основной редактор пользователя не трогать: MCP-инструменты `mcp__unity-editor-mcp__*` бьют в него;
   - сценовые PlayMode-тесты (`WaitForEndOfFrame`) в batchmode виснут — гонять в живом редакторе, всегда с внешним таймаутом;
   - ничего не пушить;
   - локальные правки пользователя (`VoxelSandbox.unity` и др.) не трогать;
   - чужие зоны файлов не править, а писать тимлиду;
   - тесты «без мусора» — только через `Is.Not.AllocatingGCMemory()`.

## 3. Стартовые задания (вставлять как первое сообщение сессии)

Общая шапка для каждой команды (подставить имя и задачу):

> Ты — команда «<имя>» в разработке воксельной танковой игры (Unity 6000.3.28f1, URP, Atomic 3.0 + Burst/Jobs). Тимлид — отдельная сессия, отчитываешься ему сообщением. Прочитай `Docs/Team/HANDOVER.md`, `Docs/Team/TEAMS.md` (свою строку), `Docs/Game/GDD.md` и `Docs/Rules/*`. Работаешь в своей рабочей копии на ветке `claude/<задача>` от свежего `game/develop`. Твоя зона файлов — <зона>, в чужие не лезь, нужное проси через тимлида. Правила редакторов: batchmode для компиляции и тестов, живой редактор свёрнутый и один на машину, закрывать по PID, основной редактор пользователя не трогать. Ничего не пушить. Цикл: короткая спецификация → план → реализация (субагенты) → ревью → `/perf-check` → отчёт тимлиду (ветка, коммит, цифры, что не проверено). Эксперименты по виду — быстро, без тестов, со скриншотами или видео.

Готовые задачи на сейчас:

- **Меню:** «Закоммить пересобранные префабы, шрифты Play и `UiIconSetConfig` в `game/ui-m1`. Влей свежий `game/develop`. Переведи `RunServiceHudSource` на `IRunService.SkillOffered` (экран выбора подписывается и вызывает `ChooseSkill`). `/perf-check`. Отчёт о сдаче вехи 1. После влития — `LoadingScreen` в стиле пака V2 Cyan и Special в переназначении клавиш.»

- **Производительность:** «Когда меню и "танк и воронка" влиты — чистый замер всех сценариев стенда на тихой машине (CPU < 25 %) и замер сборки IL2CPP на ПК. Отчёт в `Docs/Reports`, сравнение с бюджетом (PlayerLoop ≤ 5 мс, без мусора в кадре), список виновников по владельцам.»
- **AI:** «Порог давки орды → `TankCrushBehaviour.MinSpeed`. Подключить звуки орды `TODO(audio)` к `GameAudio.Horde.*`. Пули пулемёта живут 0.15 с (~18 м) — согласовать с боевыми дальность от модулей.»

## 4. Что тимлид делает сам

- Быстрые правки «по ощущениям» (размеры, скорости, дым, пули, стенд) — прямо в своём чате, в основном редакторе пользователя. Не пересобирать, пока пользователь в Play: `EditorApplication.isPlayingOrWillChangePlaymode`. Можно повесить `AssetDatabase.Refresh` на выход из Play.
- После каждого влития — `AssetDatabase.Refresh()` в основном редакторе (autoRefresh выключен) и проверка `EditorUtility.scriptCompilationFailed`.
- Держать `HANDOVER.md` и этот файл в актуальном виде после каждого заметного влития.
