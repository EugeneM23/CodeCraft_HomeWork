# Командная разработка: передача работы

Документ для того, кто подхватывает роль **тимлида**: человека или нейросеть. Здесь всё, что нужно, чтобы продолжить с того места, где остановились. Обновлено: 2026-11-18.

## 1. Что мы делаем

Из прототипа воксельного танкового уровня (VoxelSandbox) делаем игру: рогалик из глав-арен. Игрок всегда в танке и бьётся с ордой монстров. Источник правды по игре — `Docs/Game/GDD.md`.

Стек:
- ПК;
- Unity **6000.3.28f1** (6.3 LTS), URP 17.3, профиль `URP_PC_Ultra`;
- **Atomic 3.0** (Entities, MonoEntityInstaller, extension-ключи) плюс **Burst/Jobs**, без Unity Entities;
- UI — uGUI и ScreenStack, стиль SCI-FI UI Pack Pro, голубая версия V2 Cyan;
- сервисы живут в `AppContext`. Контексты: AppContext (игра) → GameContext (уровень) → сущности;
- модули из проекта Platformer лежат в `Assets/Modules`: GameLoop (пауза), Loading, SaveSystem, ScreenStack, AudioEngine, AIKit.

Документы:
- `Docs/superpowers/specs/2026-11-17-game-production-plan.md` — общий план;
- `Docs/superpowers/specs/2026-11-18-milestone-1.md` — веха 1;
- `Docs/Rules/Performance.md` — бюджеты производительности;
- `Docs/Rules/Project.md` — порядок в проекте.

## 2. Как устроена команда

- **Пользователь** — продюсер и геймдизайнер. Он одобряет влития, смотрит видео и скриншоты, даёт правки по ощущениям.
- **Тимлид** — одна сессия Claude Code. Создаёт команды, раздаёт задачи, разводит владение файлами, вливает ветки в `game/develop`. В самом коде мелкие правки делает сам; подробнее в п. 6.
- **Команды** — отдельные сессии Claude Code. Каждая работает в своём git worktree `.claude/worktrees/<имя>`, на своей ветке `claude/<имя>` или `game/<имя>`. Общаются с тимлидом сообщениями между сессиями.

Цикл задачи в команде: краткая спецификация → план → реализация субагентами → ревью → `/perf-check` → отчёт тимлиду. В отчёте ветка, коммит, цифры и что не проверено.

Команды и их зоны:

| Команда | Зона |
|---|---|
| Ядро | `Assets/Game/Scripts/App` (забег, сохранения, справочники, контракты), модули Loading и SaveSystem, ProjectSettings |
| Арены | `Features/Arenas`, сцена `Chapter1_Arena` |
| Боевые системы | `Features/Combat`: пулемёт, навыки, модули, опыт, гильзы |
| AI | `Features/AI`, орда (`Assets/Game/Horde`), режиссёр арены, `VoxelCarcass.cs` (трупы) |
| Меню | `Assets/Game/Scripts/UI`, ангар, HUD |
| Звук | AudioEngine, `GameAudio`, банки |
| Структура | `Assets/Game/Voxels/Runtime`: тела, разрушение домов, вес обломков |
| Грунт (debris) | `VoxelDebris`, комья земли |
| «Танк и воронка» | танк в воронке, `ThrowEarth` |
| Производительность | `Tools/PerfCheck`, `Docs/Rules/Performance.md`, отчёты `Docs/Reports`, агент `.claude/agents/perf-check.md` |
| Вокселизатор | инструмент вокселизации моделей |

**Контракты** между командами — интерфейсы в `Assets/Game/Scripts/App/Contracts`. Их выкладывают отдельным коммитом. Другие команды забирают контракт как есть, через `git checkout <hash> -- <paths>`, без правок, чтобы не плодить дубли типов.

## 3. Правила (обязательные)

- **Git:**
  - интеграционная ветка — `game/develop`, главная — `HomeWork_01`;
  - вливает только тимлид, `git merge --no-ff`, и только после явного «да» пользователя. Исключение — пользователь сам сказал «делай всё до конца»;
  - **ничего не пушить** на GitHub без просьбы;
  - коммиты кончаются строкой `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Локальные правки пользователя** в основной папке не коммитить без его слова: `VoxelSandbox.unity`, `LevelDesignConfig.asset`, шрифты Roboto, `orange.mat`, `SaveSystemSettings.asset`, `Regax_Elite_Brain.asset`.
- **Platformer** и другие проекты пользователя — только читать.
- **Редакторы Unity без окон** (пользователь работает в это время):
  - компиляция и тесты — только `-batchmode`: `"C:\Program Files\Unity\Hub\Editor\6000.3.28f1\Editor\Unity.exe" -batchmode -nographics -projectPath <worktree> -runTests -testPlatform EditMode -testResults <worktree>/Logs/tests.xml -logFile <worktree>/Logs/batch.log`;
  - PlayMode-тесты, которые ждут отрисованного кадра (`WaitForEndOfFrame`, сценовые тесты VoxelSandbox), в `-batchmode` **виснут навсегда**. Их гонять только в живом редакторе. Любой прогон — с внешним таймаутом;
  - живой редактор открывать только свёрнутым: `Start-Process ... -WindowStyle Minimized`, напрямую `Unity.exe -projectPath`, не через Hub или `unity open`. На машине одновременно **один** живой командный редактор: перед открытием проверить, что нет другого командного `Unity.exe` без `-batchmode`. Закрывать сразу по PID;
  - **основной редактор пользователя** (корень проекта) не трогать. MCP-инструменты `mcp__unity-editor-mcp__*` бьют именно в него. `editor_quit` закрывает его — не использовать;
  - пока пользователь в Play, не пересобирать: перекомпиляция ломает сцену. Проверять `EditorApplication.isPlayingOrWillChangePlaymode`.
- **Основной редактор после влития.** В нём выключен autoRefresh. Нужно вызвать `AssetDatabase.Refresh()` через `script_eval`, если не Play. Если правились значения по умолчанию в префабе — переимпортировать его (`ImportAssetOptions.ForceUpdate`). Компиляцию проверять по `EditorUtility.scriptCompilationFailed`.
- **Производительность:**
  - бюджеты: 60 FPS, PlayerLoop ≤ 5 мс в среднем, без мусора (GC) в кадре;
  - мерить только при загрузке CPU ниже 25 % (стенд `Tools/PerfCheck/Bench`, сценарии `idle, drive, airstrike, crush, house, crater, mg`, а также `combat_bench`, `horde_arena_bench`, `death_bench`, `arena_bench`);
  - перед влитием ветки — `/perf-check`.
- **Тесты «без мусора»** — только через `Is.Not.AllocatingGCMemory()`: `GC.GetAllocatedBytesForCurrentThread` в редакторе всегда 0.
- **Модели и пропсы.** Воксельные модели — прямые формы по сетке, без наклонных примитивов. Игровые пропсы (рампы и т. п.) — простые боксы.
- **ИИ монстров** — «рой мяса», без умного поведения. Умный ИИ пользователь сделает сам позже.

## 5. Как продолжить тимлиду

1. Прочитать этот файл, GDD, план вехи, `Docs/Rules/*`.
2. Посмотреть сессии команд в приложении Claude (группа воксельной игры). У каждой есть история; продолжать её, а не создавать новую.
3. `git log --oneline game/develop -20` и `git worktree list` — понять, что влито.
4. Ждать отчётов команд, проверять цифры, просить «да» у пользователя, вливать по одной ветке, после каждого влития — Refresh основного редактора.
5. Новые задачи давать командам с полным контекстом в сообщении: цель, ветка-основа, зона файлов, что не трогать, правило редакторов, что прислать.

## 6. Предпочтения пользователя

- Пишет по-русски. Ответы короткие, по делу, без воды.
- Быстрые правки «по ощущениям» (размер, скорость, дым, пули) — делать **сразу в чате тимлида**, в основном редакторе, без передачи командам. Крупные фичи — командам.
- Числа боевых систем берутся из значений по умолчанию в коде (`TankBaseSettings`, `WeaponSettings`): ассета `CombatConfig` в Resources нет.
- Эксперименты с видом — максимально быстро, без тестов. Показывать видео или скриншоты.
- Пока пользователь играет в песочнице, проверять живое состояние через `script_eval` (записать выстрелы и позиции), а не гадать.
