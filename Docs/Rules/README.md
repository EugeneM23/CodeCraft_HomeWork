# Правила проекта и их проверка

- [`Performance.md`](Performance.md) — цель 60 FPS на среднем ПК, бюджеты кадра, сценарии и порядок замера, правила кода.
- [`Project.md`](Project.md) — папки, нейминг кода и ассетов, сборки, тесты, документы, git.

## Как запустить проверку

В любой сессии Claude Code этого проекта:

```
/perf-check                      текущая рабочая копия, всё
/perf-check game/ui static       ветка game/ui, только статические правила (~1 мин)
/perf-check game/develop all     ветка интеграции: правила и замер VoxelSandbox
```

Что происходит:

1. Команда находит рабочую копию ветки. Если замер нужен, она находит и редактор, открытый на этой копии.
2. Если нужен Play, команда спрашивает:
   - редактор уже в Play — можно ли мерить прямо в нём;
   - Play не идёт — можно ли в него войти на минуту.

   Чужие сцены и Play без спроса она не трогает.
3. Запускается агент `perf-check` (`.claude/agents/perf-check.md`):
   - Статический обход — `Tools/PerfCheck/static_check.sh`. Его можно запустить и руками: `bash Tools/PerfCheck/static_check.sh --base game/develop`.
   - Ручной обзор изменений ветки.
   - Замер — `Tools/PerfCheck/Bench/perf_bench.cs`: простой, езда, авиаудар, давка Regax, около 45 с.
4. Отчёт пишется в `Docs/Reports/<дата>-perf-<ветка>.md`, цифры — в `Docs/Reports/perf-history.jsonl`. Следующий замер сравнивается с ними.

Вердикты:
- **БЛОК** — выход за бюджет, новые GC-аллокации в простое и езде, новые нарушения правил кода и порядка. Тимлид такую ветку не вливает.
- **ВНИМАНИЕ** — рост больше 10 % внутри бюджета, рост долга. Ветку можно влить, причину надо назвать.

## Исключение из правила кода

Строку, которая нарушает правило осознанно, помечают в конце комментарием `// perf-ok: <почему>`. Например: `private void Update() // perf-ok: ticks during pause (menu)`. Агент проверит, что причина правдоподобна.

## Когда запускать

- Команда — перед отчётом тимлиду о готовности ветки.
- Тимлид — перед влитием ветки в `game/develop` и после него.
- Команды Unity 6.3 и рендера — до и после перехода, с исходным замером `Docs/Reports/2026-11-17-perf-baseline.md` в качестве точки отсчёта.

По расписанию проверка не запускается: так решил пользователь 2026-11-17.
