## 2. Что показала сверка (коротко)

- **Код нарушает собственные правила там, где пользователь это заметил.** Тактика шага 87 (`Pick Up`, `Throw`,
  `Take Cover`, `Use / Load Turret`, `High Ground`, `Charge`) — восемь монолитных блоков «найти + забронировать +
  дойти + сделать» со своими числами; на следующий день после шага 86 («графу всё равно, какое оружие; числа приёма —
  у оружия») `Throw` завёл второй исполнитель удара. Настройки решения и блока дублируются (инвариант 10 — один
  владелец). Учебник §24 / §24.1 (умные объекты: объект регистрируется сам, владеет местом и сценарием; в графе —
  `FindSmartObject` / `UseSmartObject`) и спек модуля AIKit.md §8 описывают ровно то, что просит пользователь.
- **Скрытые процессы, которых нет на полотне:** проверки места атаки в галочках `Fight` / `Chase` / `Flank` и
  просьба места внутри `Circle` (`InCharge`); `AgentPerception` идёт у каждого персонажа, хотя графы видят через
  `Detection` (у всех персонажей стенда `TargetLayers = Nothing` — он не видит ничего); персонаж сам толкает факты в
  аниматор; числа тела копируются на доску (§8.2: копий настроек на доске не держать).
- **Шаг 79** (реакции и правый клик = окно поиска) был спроектирован и не сделан; его «реакции поверх мозга»
  противоречат шагу 89 (всё решает мозг) — берём идеи, не устройство.
- **Ошибки, найденные по пути:** правый клик «Add Sensor» кладёт `Time Of Day`, `Senses`, `Squad Sight` внутрь
  `Detection`; `Remove Frame` на рамке мозга удаляет сам мозг; тело ноды печатает имя C#-класса (`AttackTask`,
  `ChaseReasoner`); `GraphSerializer.Write` теряет ярлыки, изгибы и свёртку при каждой записи из кода; `Also Tag`
  сенсора на полотне не показан, а работает; в `AgentPerception` конусы смотрят в мировой +X (2D-наследие).

## 3. Принципы шага (по учебнику)

1. **Полотно — программа** (шаг 89): всё, что управляет персонажем, видно — нода, провод, настройка на ноде или явная
   пометка («target: Brain's»). Вопрос не создаёт состояния (инвариант 6).
2. **Решение говорит «когда и зачем», блок — «что сделать» общим глаголом** (`Find`, `Move To`, `Interact`,
   `Attack`), **а «как именно» — данные владельца:** оружие владеет приёмами, выстрелом и расходом; умный объект —
   местом, досягаемостью и сценарием; умение — своими частями (§16, §20.1, §24.1; шаг 86).
3. **Один владелец у значения** (инвариант 10, §38 №4): параметры персонажа читаются вживую (`Get`), а не копируются
   на доску; настройки не дублируются между решением и блоком (общая нода `What` идёт проводом в оба).
4. **Модель не знает анимацию** (C22, §20.1): тело пишет своё состояние, аниматор читает его раз в кадр и ничего не
   пишет в геймплей; всё, что телу нужно от клипов (root motion, тайминги лазания), идёт через интерфейс, который
   объявляет тело (инверсия зависимости).
5. **Компонент персонажа — без данных сцены и без копий** (C18, §8.2, §24): объекты мира находит граф, цель дают
   сенсоры, места знает мир (объект сам говорит, чей он).
6. **Имя ноды — её тип по умолчанию**, пользователь может дать подпись руками; сборщики и код имён не дают.
7. **Строку руками не вводят** (§8.1, §32.2): ключ выбирается из списка, источник списка — проект, а не открытый
   персонаж.
8. **Решение — только между действиями** (§20б.4 п.1, §18.2 п.3): начатый удар и умение не прерываются ничем, включая
   реакции. Расхождение с §20 («урон — реакция поверх всего») названо: так решено в шагах 67 и 79.

## 4. Решения по правкам

### 4.1 Меню нод — одно, с поиском (C1, C9)

- **Одно меню** = окно с поиском (`SearchWindow` + `NodeLibrary`) для трёх входов: правый клик по пустому месту,
  пробел, пин, отпущенный в пустоту (список, отфильтрованный по пину, как сейчас). Выпадающего меню «Add Sensor /
  Add Node» больше нет; правый клик по ноде, проводу, рамке — свои меню, как раньше. Нода встаёт там, где кликнули.
  Подменю `Add Condition / Add Input` у `Branch`, `AND`, `OR` заменяются тем же окном, отфильтрованным по условиям.
  Сборка списка — в одном месте (`Editor/Graph/NodeMenu.cs`), чтобы тест мог его прочитать.
- **Ошибка сенсоров:** форма зрения (`Radius`, `Cone`, `Zone`, `Radius (Line Of Sight)`, `Calls For Help`) кладётся в
  `Detection`; отдельные сенсоры (`Time Of Day`, `Senses`, `Squad Sight`) — сами по себе (`GraphDocument.AddSensor`).
  Группу сенсоров пользователь просил не перекраивать — она остаётся как есть.
- **Группы — из атрибута ноды, не из таблицы редактора** (§31.2, §3.3, AIKit.md §4.4: «узел появляется в меню без
  правки редактора»). `[AIKitNode]` `Path` = полный путь в меню (папки = группы, лист = название) + необязательный
  `Order`. Таблица `GraphViewCanvas.Groups` и `NotOffered` удаляются; цвет заголовка — по роду ноды (мозг, решение,
  блок по группе, сенсор, условие, данные), а не по подстроке пути. Тест: каждая нода полотна стоит в группе.
- **Дерево групп** (C9, «логика ИИ — в списке AI»; учебник §0.1 — слой решения отдельно от исполнения):

```

    Reactions      (решения-реакции, 4.10)

                   Climb To, Stand, Step, Dash

                   Charge, Call For Help, Block, Flinch
```

- В поиске одинаковые названия решения и блока (`Chase`, `Attack`, `Use Ability`…) различаются значком рода
  (решение / блок / сенсор / условие / данные). Мозг не предлагается, если он в графе уже есть; решения отряда — только
  для `Squad Brain`, решения персонажа — только для `Brain` (как проблема `WrongBrain`).

### 4.2 Названия нод (C3)

- Название = лист пути атрибута; `id` ноды не меняется, поэтому графы грузятся без миграции (§31.1, C.5).
- Переименования: `Strike` → **`Attack`** (блок, `aikit.task.attack`); решение `Fight` → **`Attack`**
  (`aikit.reasoner.fight`) — «если это атака, по умолчанию „атака“»; `AND` / `OR` в реестре вместо `All` / `Any`.
  Ноды, которые уходят (4.6, 4.7), не переименовываются, а удаляются. Остальные названия (`Kite`, `Flank`,
  `Square Off`, `Perform`…) — общие слова жанра, не собственные имена; не трогаются.
- **Имя C#-класса нигде не показывается:** `AgentNode.DisplayName` = подпись пользователя, иначе название типа из
  реестра (кэш на тип), никогда `GetType().Name`. Полоса с именем класса в теле ноды (`AttackTask`) убирается;
  подписи полей не обрезаются (ширина по самой длинной).

### 4.3 Подпись ноды руками (C4)

- Новое поле `AgentNode.Label` (сериализуется в данных ноды, пусто = «по типу»). `Name` остаётся служебным и
  по-прежнему приводится к типу (`NameByType` в сборщиках и при открытии), поэтому старые `Name: Strike` сами
  становятся `Attack` и не превращаются в чужие подписи.
- Полотно: двойной клик по заголовку (или «Rename» в меню ноды) → поле ввода; Enter — сохранить, Esc — отмена, пусто —
  снова по типу; «Name By Type» — сбросить. У подписанной ноды под заголовком мелко её тип: что это за нода, видно
  всегда. Undo через `GraphDocument.RenameNode`.
- Подпись видна везде, где сейчас `DisplayName`: ярлыки «→», «not from», трасса решений, проблемы графа, имя над
  головой в Play. Сборщики и код подписей не ставят никогда.
- **Правило проекта меняется** (CLAUDE.md, «Нода называется своим типом»): «по умолчанию — тип; пользователь может
  подписать ноду руками; сборщики и Claude имён не дают».

### 4.4 Выпадающие списки вместо строк (C5)

- **Источник — проект, а не открытый персонаж** (`Editor/Graph/NodeOptions.cs`, кэш, обновление при изменении ассетов):
  слоты приёмов — все `WeaponAsset` проекта; оружие — `Next` + имена `WeaponAsset`; действия — состояния с тегом
  `Action` во всех `AnimatorController` проекта + действия приёмов, рывков, доставания (только редактор; модель знает
  лишь имена — C22); группы мест — «(общая)» + пулы выстрелов и `AttackSlotCapacity`; теги — теги проекта. Открыт
  персонаж — варианты, которых нет у его оружия, помечены.
- Каждое поле-выбор рисуется списком (`Popup`, длинные — окном с поиском), никогда свободным текстом; значение, которого
  нет в списке, остаётся и помечено «(not found)»; пустое значение там, где оно что-то значит: «(first move)»,
  «(common)», «(none)».
- Новые атрибуты: `[ActionName]` (все поля-действия), `[PoolName]` (поля `Pool`), `[FreeText]` (только сообщение
  `Debug Log`). Тест-сторож: у каждого публичного строкового поля ноды есть атрибут выбора.
- Умение и предмет — **ссылки на ассет**, а не строки (4.5, 4.7); ссылки на ассеты в графе хранятся таблицей
  `Objects` ассета графа (есть, не использовалась) — нужна поддержка списков и тесты записи-чтения.
- Скрытые настройки — на полотно: `Also Tag` сенсора; `Zone` у формы `Zone` в `Detection` получает пин.
- Проблемы графа: ключ, которого нет нигде в проекте (слот, действие, пул), — предупреждение на ноде.

### 4.5 Умения в графе, из частей (C6, C23)

По учебнику §16 (умение — данные, `Id` = клип, длительность — из контента, пауза — от конца), §17 (фильтр → оценка
→ стратегия → жетон), §18.2 п.1 (свой пул у типа атаки), §19.1, §20.3–20.4.

- **У персонажа списка умений нет.** Персонаж готовит исполнителей (`AbilityRunner`, состояние на персонажа) по
  умениям, которые называет его граф, при `SetGraph`; игровые исполнители-код (`IAbilityRunner`) регистрируются как
  раньше.
- **`AbilityAsset` — из частей** (тот же скрипт, тот же GUID; `[SerializeReference]`, в инспекторе «+ часть»):
  - условия: дальность (мин–макс), линия взгляда, земля, пауза (`Cooldown`, от конца), задержка в начале боя;
  - очередь: `At Once` (свой пул), вес и штраф повтора — для общего решения;
  - тайминг: `Wind Up`, `Recovery` (запасные числа, пока клип не говорит сам — §20.3);
  - доставка (одна): `Strike` (удар в досягаемости), `Shot` (прямой снаряд), `Lob` (по дуге в точку), `At Point`,
    `Self`;
  - эффекты (список): `Damage`, `Area Damage` (радиус + тег, жертвы через `AgentContext.Objects`, без скана мира);
  - отклики (список): `Ground Mark` (метка на земле, пока летит), с обязательным `End` при отмене (§20.4).
  Подклассы с крючками `OnStrike` уходят; своё умение-код возможно через `IAbilityRunner`.
- **Решение `Use Ability`** (`aikit.reasoner.use-ability`) — конкретное умение (ссылка на ассет): держится, когда
  умение готово для цели мозга (пауза, свой пул, дальность, линия, тело), держится, пока умение идёт. Пин `Timer`
  убирается: пауза — у умения (один владелец); граф пользователя мигрирует (4.14).
- **Решение `Use Any Ability`** (новое) — свой набор умений (строки на ноде: «Grenade 4–9 m · w1 · rests 6 s», в
  Play — «готово / отдыхает 3.2 s / далеко / чужая очередь»); держится, когда готово хоть одно (без случайности в
  вопросе); взятое — выбирает одно (фильтр, вес, `Top 2` по умолчанию, §4.6) и держит выбор, пока у власти.
- **Блок `Use Ability`** — ссылка на умение; пусто — **умение решения** (пометка на ноде «ability: decision's», как
  «target: Brain's»). Решение передаёт выбор цепочке через `AgentContext.ChosenAbility` (новый крючок
  `ReasonerTask.Taken`, снимается в `LeftCharge`). Пустой блок вне цепочки решения-умения — проблема графа.
- Стенд: `Grenade.asset` — части `Range 4–9`, `Line`, `Cooldown 6`, `Lob`, `Area Damage 2`, `Ground Mark 2`;
  `GrenadeAbility` уходит; пункт «Give Grenades To Every Third Skeleton» уходит (кто бросает — решает граф).
- Расхождение с §32.1 (архетип перечисляет умения): единица «тип врага» здесь — граф.

### 4.6 Атака решает оружие; камень — однозарядное оружие (C14)

По учебнику §16, §18.3 (числа дистанций — у роли/оружия), §20.1; шаг 86 («граф говорит „атакуй“, оружие хранит
параметры»).

- **Один исполнитель удара** — `AttackRunner`. `ThrowTask` и `ThrowReasoner` удаляются.
- `WeaponAsset`: `Uses` (0 — без конца; камень — 1: после последнего приёма оружие исчезает, в руку возвращается
  прежнее; счёт — у персонажа, не в ассете); у выстрела (`WeaponShot`) — форма полёта `Arc` (0 — прямо, как стрела;
  камень ≈0.15 — навесом туда, где стояла цель, попадание в `Hit Radius` при падении) и флаг «летит сама модель в
  руке» (камень) вместо префаба (стрела). `IThrowLauncher` / `ThrownFlight` сливаются в `IProjectileLauncher`
  (адаптер выбирает прямой полёт или дугу).
- Камень на земле — умный объект (4.7): взаимодействие с ним = взять как оружие (`Rock.asset`: приём `Attack 1`,
  `Reach 12`, `Wind Up 0.5`, `Recovery 0.4`, `Damage 1`, выстрел `Speed 14`, `Hit Radius 1`, `Arc 0.15`, пул пустой,
  `Uses 1`).
- **Решение `Attack`** (бывш. `Fight`) получает «в досягаемости моего оружия»: при `Closer = 0` порог — дальность
  приёма оружия в руке (так и показано на ноде), числа скелета остаются как есть.
- **`Charge`** — тоже приём, а не числа графа (C14 «просмотри всю логику»): числа рывка (`ChargeTime`, `Distance`,
  `Speed`, `Recovery`, действия) переезжают в данные оружия (`WeaponMove` с данными рывка), блок `Charge` читает их,
  как `Dash` читает `Dashes`. `Kite` остаётся блоком движения, его полоса по умолчанию — от дальности оружия.

### 4.7 Поиск и взаимодействие: умные объекты (C15, C16, C18)

По учебнику §24 (один шлюз вместо сканирования: объект регистрируется сам, бронь с TTL, журнал недостижимости,
цепочка «авторский список → зона → где угодно»), §24.1 (Sims-модель, `FindSmartObject` / `UseSmartObject`), §18а
(укрытие), §23.4 (запрос позиции с запасными вариантами), §9.4.

- **Слой объектов мира** (`Runtime/Core/Objects`):
  - `IInteractable`: кто может пользоваться сейчас (`CanBeUsedBy` — слово самого объекта в момент использования),
    по одному или всем сразу, место для этого персонажа (`PlaceFor(user, threat)`) и досягаемость, **сценарий**
    (`Begin` / `Tick` / `End`, состояние — в памяти ноды `Interact`).
  - Реестр `WorldObjects`: объекты регистрируются сами (`OnEnable` / `OnDisable`), запрос — по типу компонента и/или
    тегу в радиусе; бронь с TTL (снимается при уходе решения и смерти); журнал недостижимости на агента. Заменяет
    `Bookings` на жетонах боя для объектов (§21.4: станции — отдельная ось, не `Engagement`). `TagObjectFinder`
    остаётся для `Detection`.
  - Объекты: `PickableItem` (+ `Weapon` — что даёт взятие: камень → оружие; + время и действие взятия), `ItemSource`,
    `Turret` (сценарии «встать к турели» и «зарядить, если несёшь патроны»), `Perch`, новый `Cover` (место за
    укрытием от угрозы, `Behind`), новый `AI Place` (место мира: вид — дом, работа, площадь, зона патруля…; владельцы
    — список персонажей; пусто — общее).
- **Ноды** (как описал пользователь):
  - решение **`Search For`** — «мозг решил искать»: держится, когда есть подходящий объект, которым **я** могу
    воспользоваться (слово объекта), в пределах `What`; плюс вход `Condition` (4.8); уход решения снимает бронь.
  - **`What`** — нода данных «что искать»: тип компонента (`Pickable Item`, `Cover`, `Turret`, `Perch`, `AI Place`,
    любой компонент, который регистрируется в реестре), тег, вид места, «только моё», радиус, полоса от цели. Идёт
    проводом **и в решение, и в блок поиска** (один владелец).
  - **`Find`** — «как искать»: `Nearest` (известные объекты, мгновенно), `Look Around` (только то, что видно глазами),
    `Wander` (бег по случайным точкам в радиусе, пока не увидит). Найденное — проводом в переменную доски (выход
    `Found`, как у сенсора); бронирует; пропускает недостижимые; выходы `Found` / `Nothing Found`.
  - **`Move To`** — тот же блок; если цель — умный объект, идёт к его месту для этого персонажа и считает приход по
    его досягаемости; `Pace`; «нет пути» — в журнал недостижимости.
  - **`Interact`** — выполняет сценарий объекта (камень → оружие в руке; ящик → в руки; склад → выдаёт; турель →
    встать или зарядить; укрытие / насест → занять, лицом к угрозе). Граф не решает, что будет.
  - Другие действия «по приходу» (превратиться, взорваться…) — будущие блоки рядом с `Interact`.
- **Что уходит:** `Pick Up`, `Throw`, `Take Cover` (блок и решение), `Use Turret` / `Load Turret` (блоки),
  `Fetch`, `Use Turret`, `Reload Turret`, `High Ground` (решения), `High Ground` (блок) → всё это `Search For` +
  `What` + `Find` + `Move To` / `Climb To` + `Interact`. Остаются `Drop`, `Kite`, `Charge` (4.6).
- **Сценарии стенда:**
  - камень: `Search For` (What: Pickable Item, tag Rock) → `Find (Nearest)` → `Move To` → `Interact` → конец; камень
    в руке — камень больше никому из «меня» не подходит (слово объекта), `Search For` отпускает, мозг берёт `Attack`
    → бросок → оружие израсходовано → снова `Search For`.
  - укрытие: `Search For` (What: Cover, полоса Min–Max от цели) → `Find` → `Move To` → `Interact` (занять) →
    `Attack` → `Done` → снова `Find` (перепроверка укрытия видна петлёй; держит текущее, пока оно годно — гистерезис
    §18а.2 п.4, не чаще раза в 0.5–1 с — п.2).
  - турель: `Search For` (What: Turret, свободна, есть патроны) → `Find` → `Move To` → `Interact` (стрелять, пока
    решение держится); заряжающий: `Search For` (What: склад) → … → `Interact` (взять ящик) → `Find` (What: турель)
    → `Move To` → `Interact` (зарядить).
- **Объекты сцены уходят из компонента** (C18, C19): поле `_bindings`, раздел «Scene objects», выбор объекта сцены в
  поле ноды и на доске. Замены: `Patrol Area` без зоны и так патрулирует вокруг старта (точки `Point A` / `Point B`
  никто не читает — переменные удаляются из графа); зона патруля, турель, места жителей — `AI Place` / объекты,
  которые находит граф (`Find` с «только моё» — авторский список §24 переезжает с персонажа на объект: объект
  говорит, чей он). Цель — только сенсоры. `AI Squad` своих привязок пока не теряет (правка была про персонажа) —
  записано в «Что осталось».

### 4.8 Условие на решении; место атаки — видимым блоком (C7)

По учебнику §17 (жёсткий фильтр **до** выбора), §4.3–4.4 (оси с правом вето), §18.1 («враг каждый кадр спрашивает
свой слот»), §18.2, §3.2 (дешёвый гейт первым), инвариант 6 (условие только читает).

- **Вход `Condition` у каждого решения** (как у `Branch`): решение — кандидат, только если держатся его собственные
  настройки **и** подключённое условие; провода нет — лишнего условия нет. Отказ в Play: «only if <фраза> — no», узел
  условия показывает живое значение. Это же — крючок для параметров и состояний (4.9).
- **Условие `Attack Slot`** (чистый вопрос, не создаёт `Engagement`): `Is` — `mine` / `mine, I attack first` /
  `mine, someone attacks first` / `not mine`; пул — выбор из списка; цель — мозга (пометка).
- **Блок `Ask For Attack Slot`** — видимая просьба места (мгновенный, `Got` / `Waiting`, пул): держит место на
  кольце и просит жетон. У решений появляется пин **`On Tick`**: его цепочка мгновенных блоков идёт раз в размышление,
  пока решение у власти (там, где сейчас работает скрытый `InCharge`) — так `Circle` просит место видимо.
- **Удаляется скрытое:** `Needs Attack Place` у `Attack` / `Chase` / `Flank`, `Only When Not First` у `Flank`,
  `Ask For Place` / `Pool` / встроенное «есть место — не держусь» у `Circle`, факты `HasAttackPlace` /
  `IsFirstToAttack` мозга. Скрытые проверки других решений — тоже на полотно: «оружие стреляет» у `Kite` (и бывших
  `Take Cover` / `High Ground`) — условием `Is` (4.9); у `Change Weapon` — строка на ноде «нужно 2 оружия»; у
  `Climb` — проблема графа, если тело не лазает.
- Проблема графа: условие места читается, а просит места никто — «nobody asks for an attack slot».
- Миграция без пересборки графов (4.14): старые галочки (и отсутствующий ключ — старое значение по умолчанию было
  «да») превращаются в подключённые узлы `Attack Slot`; `Circle` с `Ask For Place` — в `Ask For Attack Slot` на его
  `On Tick`.

### 4.9 Параметры и состояния — `Get`, `Is`, раздел персонажа на доске (C11, C12, C13)

По учебнику §8.2 (копий настроек на доске не держать), §0.1 (узлы не читают компоненты игры в обход фактов — только
интерфейс модуля, раз в размышление, видимо), §17 п.2 (исключительный приём — условием: «цель блокирует»), §20.1
(одна модель состояния для графа и аниматора), §26а (полёт и вода — другой адаптер тела, тот же мозг), инвариант 8
(модуль не знает игру).

- **Модель статуса** (`Runtime/Core/Agent/CharacterStatus.cs`): `ICharacterStatus` — числа (`CharacterStat`:
  `Health`, `Max Health`, `Health %`, `Speed`, `Run Speed`, `Turn Speed`, `Acceleration`, `Height`, `Radius`) и
  состояния (`CharacterState`: `Moving`, `Running`, `In Air`, `Climbing`, `Swimming`, `Flying`, `Dashing`,
  `Attacking`, `Winding Up`, `Recovering`, `Blocking`, `Using Ability`, `Aiming`, `Healing`, `Staggered`, `Dead`,
  `Carrying`, `Inside`, `In Combat`), с явным «нет данных». `IHealth` (`Current`, `Max`) — то, что даёт игра.
  `AICharacter` реализует статус сам (тело, руки, оружие, исполнители удара и умения, `IHealth` игры на объекте);
  игрок и объекты игры — свою реализацию (стенд: `LabIslandPlayer`, `LabHitTarget`, `LabLife`). Один источник у
  каждого состояния (`AttackRunner` — фаза удара, тело — движение, и т.д.).
- **`Get`** — нода данных (чистый «геттер», без входа потока): вход `Of` (провод от переменной-объекта; пусто — «Me»,
  так и написано в заголовке), выбор параметра (числа статуса + отношения, которые модуль считает сам: `Distance`,
  `Angle From My Facing`, `Faces Me`), выход — число. Подключается к `Compare` (входы A/B), `Set` (снимок в
  переменную), `Debug Log`. Ответ кэшируется на размышление; «нет данных» — не ноль.
- **`Is`** — условие: объект (пусто — «Me») + состояние из списка → `Branch`, `AND` / `OR`, вход `Condition`
  решения. Пример: `Attack` → `Branch (Is Target Blocking)` → `Heavy`.
- **`Set Parameter`** — блок для своих изменяемых параметров (`Run Speed`, `Turn Speed`, `Acceleration`) с вариантом
  «вернуть исходное»; жизни графу не пишутся.
- **Доска:** раздел **«Character»** — параметры и состояния персонажа строками (только чтение; в Play — живые
  значения; без персонажа — список из модели статуса); строка, перетащенная на полотно, — нода `Get` (или `Is`).
  **Копирование чисел тела и умений на доску (`IAgentNumbers`, `PublishNumbers` / `ApplyNumbers`, шаг 34)
  удаляется** — цель шага 34 (читать и менять параметры из графа) сохраняется через `Get` / `Set Parameter`; переменная
  `Grenade Cooldown` в графе пользователя остаётся обычной переменной графа (6).

### 4.10 Реакции на действия игрока — решения мозга (C8)

По учебнику §19.1 (телеграф → окно → наказание), §19.2 (опрос, пока цель в телеграфе; ≤3 м, спереди; шанс 0.7 +
0.15 × недавние попадания; задержка 0.1–0.35 с с перепроверкой; уклон в сторону или назад, никогда к атакующему;
ритм контратак), §19.4, §20б.4 п.5 (реакции вне очереди, с шансом), §38 №15, №35–37; шаг 89 (реакция = решение мозга
с приоритетом, не слой поверх).

- **Решения-реакции** (группа `AI / Decisions / Reactions`), общая основа: событие ловится по фронту, шанс бросается
  один раз на событие (рандом агента), задержка реакции (по умолчанию 0.1–0.35 с) с перепроверкой в момент
  срабатывания, `Cooldown`, держится до конца своей цепочки; флаг **«вне очереди»** — берётся сразу, без минимального
  времени решения 0.3 с, но **никогда посреди удара или умения**; на ноде и в правилах мозга это написано.
  - `Target Attacks` — цель в замахе (`Winding Up`), в `Range` (3 м), спереди; шанс растёт от недавних попаданий по
    мне. Цепочка: `Random` → `Dash` (вбок / назад) / `Block`.
  - `Target Opens Up` — цель восстанавливается после удара, лечится, оглушена или упала → наказать (`Dash` вперёд →
    `Attack`).
  - `Target Aims` — цель целится или стреляет в меня → уйти с линии (`Step` / `Dash` вбок; позже — укрытие).
  - `Got Hit` — по мне попали (окно после попадания, «сзади»): `Turn To Target` (на атакующего) / `Flinch` /
    `Call For Help`.
  - `Target Behind` — цель за спиной (угол > 120°) → `Turn To Target`.
  - `Health Low` — мои жизни ниже порога (с запасом).
- **Блоки:** `Block` (держать блок `Hold` секунд; состояние `Blocking`), `Flinch` (действие `Hit`, тело стоит);
  уклон — существующий `Dash` (от угрозы).
- **Канал попаданий:** `AICharacter.TakeHit(in HitInfo)` — игра (её жизни) сообщает о попадании; `DirectStriker`
  сам сообщает персонажу-жертве. Память попаданий (кто, когда, откуда, «давление») — в контексте агента; форма
  `Hit By` в `Detection` (видит последнего ударившего `Remember` секунд — §9.3 «урон будит всегда»).
- **Стенд:** у игрока островов — удар по клавише с телеграфом (≈0.5 с замах; бьёт ИИ в досягаемости), блок, лечение
  (для `Target Opens Up`), статус `ICharacterStatus`; жизни `IHealth`. Реакции в граф пользователя добавляет только
  отдельный пункт меню (дописывает, не пересобирает).
- Позже (не в этом шаге): уклон от снаряда предсказанием (§19.3), события союзников (§10), эскалация против глухой
  защиты (§18.2 п.8).

### 4.11 Персонаж: анимация отдельно, лазание из клипов, восприятие в сенсоре (C20, C21, C22)

По учебнику §20.1 (три слоя: тело пишет состояние, аниматор читает; доска ИИ — не доска аниматора), §20.2
(адаптер аниматора заменяем; действие = состояние по имени с тегом `Action`; root motion — настройка тела), §20.3
(числа — из клипа, редакторская утилита вынимает их; число в данных — запасной путь), §13.2–13.4 (проходимость и
прохождение ребра — от тела), §9.1–9.6.

- **`AI Animator`** — новый компонент в своей сборке `AIKit.Animation` (`Adapters/Mecanim`, ссылается только на
  `AIKit`), ставится на объект `Animator` (сам получает `OnAnimatorMove`; `AnimatorMoveRelay` уходит). Находит свой
  `AI Character` и **каждый кадр читает** его состояние (скорость — по реальному сдвигу, «в бою», оружие в руке и
  его набор клипов, лазание, фаза прыжка, текущее действие, статус 4.9) — персонаж ничего в него не толкает. Пишет
  параметры Mecanim (имена, тюнинг — его поля: всё, что было в разделе `Animation`).
- **Обратная связь — только через интерфейсы, которые объявляет модель:** канал действий (`IActionAnimator`:
  `Play` / `Stop` / `IsPlaying` / `Swing`) — `AI Animator` регистрирует себя у персонажа; root motion —
  `AgentBody.MoveByAnimation`; тайминги лазания и прыжка — новый `ITraversalMotion` (4.11 ниже). Без `AI Animator`
  персонаж работает (действия не показываются, тайминги — запасные).
- У `AI Character` уходят `_animated`, `_animation`, `Animation`, `IsAnimated`, `SetAnimated`, проталкивание фактов
  в `Update` и раздел `Animation`. Наборы клипов оружия (`WeaponAsset.Motions`) остаются у оружия — слово
  пользователя шага 86 («оружие подменяет анимации»); `AI Animator` сам меняет набор, когда меняется оружие в руке, и
  до начала действия `Weapon Draw` (риск шага 86 — смена override без сброса).
- **Лазание и прыжок (C20):** у тела остаются только возможности (`Climbs Walls`, `Jumps Over Links`). Всё про
  движение — из клипов: `AI Animator` в редакторе сам измеряет клипы подъёма, спуска и прыжка своего контроллера
  (код замера `ClimbSetup.Measure` переезжает из стенда в редакторскую сборку модуля) и хранит замер (только для
  чтения в инспекторе); тело получает его через `ITraversalMotion`. **Падение — гравитацией** (`Physics.gravity`, без
  `Fall Speed Up`; прыжок без `Jump Hop`, если клип его не даёт); прыжок по ссылке — тот же код (толчок → полёт по
  баллистике → приземление) с фазами `Jump` для аниматора. `Arc Height`, `Jump Speed`, `Min Jump Duration`,
  `Climb Time`, `Climb Speed`, `Climb Rise`, `Climb Advance`, `Climb Reach`, `Climb From Wall`, `Climb Step Speed`,
  `Jump Take Off`, `Jump Landing`, `Jump Hop`, `Jump From Edge`, `Fall Speed Up` уходят из инспектора;
  `Climb Spacing` — из радиуса тела, `Climb Check Interval` — константа; `Climbs Down By Jumping` — если у аниматора
  нет клипа спуска. Риск: лазание тюнилось и проверено прогоном на 40 подъёмов — тесты стенда (`ClimbSoakTests`,
  `ClimbBodyTests`, `ClimbSceneTests`) должны остаться зелёными; изменение падения (было ×3 по просьбе 14.11, «висит в
  воздухе») — теперь по слову пользователя «силой гравитации».
- **Восприятие (C21):** раздел `Senses` уходит из компонента. Профиль (`PerceptionProfile`: глаза, конусы, память,
  пороги тревоги) — настройки сенсора **`Senses`** на полотне (единственный, кто им пользуется: пресеты и демо);
  состояние восприятия — в памяти этой ноды; конусы — от 3D-направления тела (ошибка +X исправляется). Без сенсора
  `Senses` в графе `AgentPerception` не создаётся и ничего не крутит. `Faction` переезжает в раздел `Advanced`

### 4.12 Ярлыки связей у выхода (C2)

- Ярлык «→ имя» по умолчанию **пристыкован к своему выходному пину** (новое поле записи `LinkFree` = false: позиция
  считается от пина, перетащить нельзя); несколько ярлыков одного пина — стопкой вниз; ярлык компактный (одна
  плашка по ширине текста, без рамки ноды, пин слева). «Replace With Link» больше не ставит ярлык в точку клика.
- Сборщики после записи вызывают `GraphLinks.LinkLoops`: каждая стрелка назад (цель левее или на уровне источника)
  становится пристыкованным ярлыком. Существующие 23 графа с ярлыками стыкуются при открытии (меняется только вид;
  ярлыки пользователя в `PhalanxSwordsman` / `PhalanxArcher` — тоже, это и есть просьба C2).
- `GraphSerializer.Write` сохраняет вид при записи из кода: свёртку — по id ноды, изгибы и ярлыки — по устойчивому
  ключу стрелки (источник, вид, выход, цель, номер), а не по id записи.

### 4.13 Провода мозга не сливаются (C10)

- Каждый провод мозга к решению выходит из **своей точки на рамке мозга** — на стороне, обращённой к решению; точки
  одной стороны разнесены по порядку решений, у каждого провода — своя вертикаль (не пересекаются, не сливаются).
  Геометрия — чистая функция `GraphLayout.BrainExits` (тест без окна).
- Подключить можно **куда угодно по рамке**: провод от входа решения, отпущенный на рамке или на мозге, соединяет;
  тянуть новый провод можно с любой точки рамки.
- `Remove Frame` на рамке мозга не удаляет мозг (меню: «Delete Brain» отдельно); ноды, кроме мозга, в рамку мозга не
  втягиваются.

### 10.1 Модель не командует аниматором (C22, «очень важно»; §20.1)

Было в 4.11: узлы зовут `ActionAnimator.Play / Stop / Swing` — это команды модели слою отрисовки, ровно то, против чего
C22. **Решено:** действие — **состояние персонажа** (`AgentContext.Actions`, класс `ActionState`): узел просит

`AI Animator` раз в кадр читает его и показывает; обратно — только ответы через интерфейс, который объявляет модель

### 10.2 Скрытые проверки решений — строкой на ноде, а не `Is`

### 10.6 Приёмы: оружие и умения — одна линия (C14; §16, §20.1)

Направления «умения» (A) и оружейная часть «объектов» (O) сливаются в одно направление **M — приёмы**: один полёт
снаряда (`IProjectileLauncher`: прямо или дугой, в цель или в точку, летит префаб или **модель из руки**, сообщение о
падении — для `Area Damage` и конца метки), одни эффекты, одна запись фазы удара (`AttackPhase` пишут и
`AttackRunner`, и исполнитель умения — никогда одновременно). Камень — оружие с одним приёмом-броском (`Arc`), `Uses 1`.
**Временное оружие из мира** (камень, турель) — не в списке оружия персонажа: своё оружие на это время за спиной, как
при переноске ящика; кончилось — своё снова в руке. Это сценарий камня (C14, C15), а не смена оружия: правило «оружие
меняет только `Switch Weapon`» — про своё оружие персонажа, оно в силе. `Charge` — приём с доставкой «рывок» (числа — у
оружия), урона не наносит (как сейчас). **Турель** — временное оружие «на станке» (`Uses` = патроны): стреляет решение
`Attack` через `AttackRunner` и пул выстрелов, а не сама турель.

### 10.7 Поиск (C15, C16) — уточнения

- **`Search For` держится по нужде, а не «когда объект уже известен»:** его условие (пин `Condition`) говорит, зачем
  искать; держится, пока идёт его цепочка; после ухода и после `Nothing Found` — **отдых `Rest` секунд** (написан на
  ноде). Что искать — только у `Find` (через `What`); сам `Search For` объектов не спрашивает.
- **Камень:** `Attack` (досягаемость оружия в руке) → `Search For` (условие `NOT Is (Me) Holds Picked Weapon`) →
  `Chase` (остановка 0 = от оружия) → `Patrol`. Что прекращает поиск — видимое условие, а не слово камня. Камни не
  кончаются: на острове — куча камней (`ItemSource`, выдаёт камень-оружие); брошенный камень исчезает (C14).
- **У объекта — предложения** (§24.1): `Take`, `Use`, `Load`, `Occupy`; `What` = компонент / вид + предложение (+ тег,
  «чьё»: моё → общее → любое, радиус, полоса от цели). Турель предлагает `Use`, пока есть патроны и свободна, `Load`,
  пока не полна. Заряжающий: `Find (Turret, Load)` → `Find (склад, Take)` → `Move To` → `Interact` → `Move To` (турель)
  → `Interact`; на неудаче — `Drop`.
- **`Interact` — пин `Object`** (провод от переменной, которую написал `Find`); без провода — проблема графа и ничего не
  делает. Взаимодействие выбирается списком (`Take` / `Use` / `Load` / `Occupy`).
- **Укрытие — как камень:** цепочка кончается на `Interact` (занять); стреляет решение `Attack`; укрытие перестало
  годиться — состояние `In Cover` снято, `Search For` снова держится (§18а.2).
- **Насест (бывший `High Ground`):** `Search For` (отдых 8 с — бывший `Every`) → `Find (Perch, Occupy, полоса с
  запасом — бывший Leave After)` → `Climb To` → `Interact`. `HighGroundTests` заменяются тестами этой цепочки.
- **Любой объект** ищется без кода: общий компонент **`AI Object`** (вид из списка проекта, владельцы, радиус зоны)
  вместо отдельного `AI Place`. Форма `Zone` в `Detection` берёт `AI Object` по виду (только моё) через реестр.
- **Дом патруля** — точка, где персонаж проснулся (запоминается при старте, не «где снова начал патруль» — иначе после
  погони скелеты уходили бы за игроком); пин `Area` у `Patrol Area` — необязательный (`AI Object` с зоной). В графе
  пользователя провод `Patrol Zone` и переменные `Point A` / `Point B` снимает шаг обновления в редакторе.

### 10.8 Реакции (C8)

- **Набор:** `Target Attacks`, `Target Opens Up`, `Got Hit`, **`Health Low` (чьи: мои / цели / союзника — заказ
  пользователя 13.11)**; `Enters Zone` — после слияния (нужен `AI Object`). «Реакция — поверх мозга» (слово
  пользователя, шаг 79) заменяется «решение мозга вне очереди» по шагу 89 (полотно — программа, всё решает мозг) —
  сказать пользователю.
- **Состояние реакций** (фронт события, один бросок шанса, задержка, пауза, давление попаданий) пишется только в
  `ReasonerTask.Observe` — раз в размышление у каждого решения мозга, даже посреди своего удара; `Holds` только читает
  (вопрос не создаёт состояния). Реакция ниже по важности, чем решение, которое она должна перебить, — проблема графа.
- **Один путь попадания:** `DirectStriker` сообщает всем `IHitReceiver` жертвы, `AI Character` — один из них; игра
  своим уроном зовёт его же. Вздрагивание — отклик тела (флаг «больно», `AI Animator` играет его слоем), а не решение
  мозга; `Got Hit` — только тактика (повернуться, позвать). Ударившего видит форма `Hit By` в `Detection` (видимо).

### 10.9 Персонаж (C20, C21, C22) — уточнения

- **Числа лазания и прыжка — данные тела, измеренные из клипов** (§13.3–13.4: прохождение ребра — от тела): редакторская
  утилита (в сборке аниматора) мерит клипы контроллера и записывает в тело; в инспекторе тела вместо ~20 чисел — одна
  строка «измерено по <контроллер>: подъём 2,36 с, прыжок ✓» и кнопка «Измерить заново». Без замера — запасной путь.
  Сначала перенос замера и тест «замер = нынешние числа», потом уход полей. Падение — `Physics.gravity` (C20; было ×3 по
  просьбе 14.11). `Climb Spacing` — константа 1,5 м; «вниз прыжком» — одна видимая галочка (по умолчанию да).
- **`AI Animator`:** имена параметров — выбором из параметров своего контроллера, тюнинг свёрнут; скорость ног —
  заказанная, когда тело ходит root motion (правило `ShownVelocity`); работает после `AI Character`; смена набора клипов
  оружия — синхронно до начала действия.
- **Восприятие:** у сенсора `Senses` одно поле — ассет-профиль (`PerceptionProfile` становится ассетом; пусто — по
  умолчанию), нода показывает только его имя; состояние восприятия регистрирует на персонаже сам сенсор.

### 10.10 Полотно — уточнения

- Имя ноды: подпись пользователя → имя, данное кодом → название типа (состояние — название своей задачи), никогда имя
  класса. Названия = тип: переименовываются только расхождения «показанное имя ≠ тип» (`Strike` на `AttackTask`) и пары
  «решение / блок одной сути» (`Fight` → `Attack`, `Change Weapon` → `Switch Weapon`, `Hold The Line` → `Hold Line`);
  `Kite`, `Flank`, `Square Off` — глаголы жанра, остаются. `Branch` остаётся красным.
- Провод мозга: точка, куда пользователь его отпустил на рамке, **запоминается** (сторона + смещение); сам
  раскладываются только провода без точки и провода сборщиков.
- Ярлыки: стрелка назад, проведённая руками, тоже сразу становится ярлыком у выхода; перетащенный ярлык отстыковывается,
  «Dock To Pin» пристыковывает снова.
- Ноды данных без провода сохраняются; одна нода данных может идти в несколько входов; пин-список (несколько проводов в
  один вход — `Abilities`, `Sensors`).
- `Get` / `Is` — «чей» выбирается списком (`Me` / `Wired object`); во втором случае пустой пин — проблема графа (иначе
  выдернутый провод тихо превращал бы «здоровье цели» в «моё»).

### 10.11 Расхождения с учебником (дополнение к разделу 8)

§8.2 — пауза умения хранится у исполнителя умения на персонаже (данные — у ассета), а не на доске (кроме `Timer` графа
пользователя); §24 — авторский список «чьё» хранится на объекте (`AI Object.Owners`), а не в записи спавна (в модуле
нет записей спавна, C18 убирает данные сцены с персонажа); §21.4 — турель не отдельная ось-станция, а временное оружие;
§20.2 — вздрагивание слоем аниматора (§20.2 так и советует), а не решением; §3.4 / шаг 79 — реакции решения мозга.
