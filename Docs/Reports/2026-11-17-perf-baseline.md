# Исходный замер VoxelSandbox: точка отсчёта перед Unity 6.3 и URP

**Дата:** 2026-11-17
**Коммит:** `b136fb616` (`game/develop`; код прототипа — `126882f11`)
**Редактор:** основной, порт 7802, Unity 6000.0.38f1, Built-in RP + Post Processing v2, качество Ultra. Game view развёрнут через Maximize On Play, 2294×1291, Scene view закрыт. Burst включён.
**Машина:** Intel Core Ultra 9 275HX, RTX 5090 Laptop.
**Инструмент:** `Tools/PerfCheck/Bench/perf_bench.cs`, сценарии и порядок — `Docs/Rules/Performance.md`, разделы 3–4.

## Итог

- Средний кадр игры (PlayerLoop) — **3.1–4.5 мс**, в давке 5.2 мс. По среднему укладываемся в бюджет 5 мс, но без запаса.
- Блокирующие бюджеты нарушены в трёх местах, это **перф-долг** (раздел «Перф-долг» ниже):
  - **пики кадра:** давка Regax — 88 мс, сборка мусора — 20–31 мс;
  - **p95** в езде и авиаударе — 7.0–8.4 мс;
  - **GC-аллокации игры** в езде.
- GPU загружен слабо: 1.7–2.4 мс при бюджете 4.
- Рендер на главном потоке — 1.6–2.5 мс. Это самая крупная статья кадра.

С этим замером сравниваются переход на Unity 6.3 (команда Unity 6.3) и на URP (команда рендера). В `Docs/Reports/perf-history.jsonl` он записан первой строкой.

## Сравнение с замером 2026-11-16

`Docs/superpowers/specs/2026-11-16-voxel-performance.md`, итог «стало»: PlayerLoop — 1.8 мс в простое и 1.8–2.0 мс в езде, batches в простое — 430. Сейчас 3.1 и 4.0 мс, batches — 949.

Напрямую цифры не сравниваются:
- Тогда Game view был 1479×832 рядом со Scene view, сейчас развёрнут на 2294×1291. Пикселей в 2.4 раза больше, а это рендер и GPU.
- Тогда бомбы падали по таймеру, сейчас взрывы вынесены в отдельный сценарий.
- После 11-16 в сцену добавлены давка, кровь, «мокрая собака». История до `126882f11` сжата в один коммит, поэтому, что именно удвоило batches и shadow casters, по git не видно.

Проверить, откуда двойной рост batches: Regax в сцене (20 штук, по ~17 тыс. треугольников, свои тени), новые эффекты крови. Задача — в пункте 4 «Перф-долга».

## Перф-долг

По убыванию пользы. Владелец — по плану производства, раздел 4.

1. **Давка Regax: кадр 88 мс** (бюджет 16). Блокирует цель «60 FPS без рывков» в каждом бою.
   - **Звук.** Клипы грузятся с диска при первом `Play`, это 29 мс. Нужно включить Preload Audio Data или загружать банк при загрузке уровня. Владелец — **звук**: это входит в перенос AudioEngine и в правила банков.
   - **JIT, 25 мс.** В редакторе и Mono-сборке первый вызов кода давки компилируется на лету. В IL2CPP-сборке этого нет. Проверить в сборке. Если пик останется — прогревать давку при загрузке уровня. Владелец — **чистка**: давка остаётся в игре.
   - **~20 мс самой давки и 1 МБ GC в одном кадре.** Вероятнее всего, вокселизация трупа на лету. Это риск из плана: «для орды воксельные трупы запекаются заранее». Нужен `ProfilerMarker` на шаги давки и запечённые трупы. Владельцы — **AI** (трупы орды) и **вокселизатор** (запекание).
2. **Сборка мусора: пики 14–31 мс в езде и авиаударе.** Главный источник мусора — отладочный HUD `VoxelDemoHud` (IMGUI): 1.6 КБ каждый кадр и всплески до 225 КБ.
   - **Меню:** новый HUD на uGUI + TMP по правилам Performance.md, раздел 5.
   - **Чистка:** убрать `VoxelDemoHud` из боевой сцены.
   - Остальные GC-аллокации игры найти по маркерам и убрать. Владелец — **чистка**:
     - в езде — 60 кадров, до 36 КБ;
     - в простое — один кадр, 596 Б (бюджет 0);
     - в авиаударе — пик 12 КБ в кадре взрыва (бюджет 4 КБ).
3. **p95 7–8.4 мс в езде и авиаударе.** В основном это следствие пунктов 1–2 и всплесков теней в `Camera.Render`. Пересмотреть после них.
4. **Рендер на главном потоке — 1.6–2.5 мс; batches и SetPass выше ориентиров.**
   - Переход на URP с SRP Batcher должен заметно снизить SetPass и время отправки. Владелец — **рендер**.
   - Сравнить с этой таблицей по тем же сценариям.
   - До URP разобраться, откуда двойной рост batches против 11-16.
5. **Оставшиеся пункты** из «Не сделано» замера 11-16 остаются в силе. Главные:
   - склейка чанков домов;
   - обломки одним procedural-вызовом;
   - локальный `Split` домов.

## Как повторить

```
unity cmd --port <порт> editor.playmode start
unity cmd --port <порт> script eval --file Tools/PerfCheck/Bench/perf_bench.cs
unity cmd --port <порт> script eval --file Tools/PerfCheck/Bench/perf_bench_read.cs
```

Последнюю команду повторять, пока она не вернёт JSON: около 45 с. Или одной командой: `/perf-check game/develop all`.
