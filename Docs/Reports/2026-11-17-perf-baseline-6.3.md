# Исходный замер VoxelSandbox на Unity 6.3: точка отсчёта перед URP

**Дата:** 2026-11-17
**Коммит:** `2faa7b274` (`game/develop`: Unity 6.3, чистка, звук, ядро)
**Редактор:** отдельный, на рабочей копии `perf-0b2ee8`, порт 7806, закрыт после замера. Unity 6000.3.28f1, Built-in RP, качество Ultra, Game view 2294×1291 (Maximize On Play), Scene view закрыт, Burst включён. App включён: холодный старт ядра, режим по умолчанию.
**Машина:** Intel Core Ultra 9 275HX (24 потока), RTX 5090 Laptop. Загрузка CPU без моего редактора во время замера — 9 %, в авиаударе 10 %. Остальные семь редакторов были открыты, но простаивали.
**Инструмент:** `Tools/PerfCheck/Bench/perf_bench.cs` после правок этого дня (раздел «Что изменилось в инструменте»).
**Предыдущая база:** `Docs/Reports/2026-11-17-perf-baseline.md` — Unity 6.0, `b136fb616`, до чистки.

## Итог

- **Unity 6.3 и влитые ветки кадр заметно не ухудшили.**
  - PlayerLoop: 3.9 / 3.7 / 4.7 / 5.8 мс (простой / езда / авиаудар / давка), на 6.0 было 3.1 / 4.0 / 4.5 / 5.2.
  - Разброс между одинаковыми прогонами на 6.3 — 20–35 %, это больше разницы между версиями.
  - Рост на 15–42 %, который нашёл звук, — в основном загрузка машины. При 94 % CPU (восемь редакторов) PlayerLoop вырос в 2–3 раза. Правило «мерить только при фоне ниже 25 %» теперь записано в `Performance.md`, раздел 4, п. 3.
- **Пик давки:**
  - Загрузка звука с диска ушла: её починил звук.
  - Первая смерть Regax за сессию всё ещё стоит 59–73 мс (в двух прогонах из четырёх). Это JIT кода смерти и крови.
  - В остальных прогонах худший кадр давки — 11.5–17 мс.
- **App ядра (A/B):** измеримой цены нет. Пик простоя 18–25 мс, о котором спрашивало ядро, в тихих условиях не повторился: худший кадр простоя — 6.5–11.8 мс с App и без него.
- **GPU** — 1.8–2.7 мс при бюджете 4.
- **Рендер на главном потоке** — 1.9–2.9 мс, batches 1000–1600. Это главная цель URP.

С этим замером сравнивается переход на URP. В `Docs/Reports/perf-history.jsonl` он записан строкой `"label":"baseline Unity 6.3 …"`.

## Что изменилось в инструменте

Все правки в `Tools/PerfCheck/Bench/perf_bench.cs`, коммиты этого дня.

- **Маркеры 6.3.** В 6.3 кадр игры лежит под `UpdateScene`, рендер — под `RenderPlayModeViewCameras`. Физика, скрипты и рендер теперь ищутся по имени на любой глубине, первое совпадение на пути. Если категория не найдена ни в одном кадре, это пишется в `notes`, а не в колонку тихим нулём.
- **Ввод танка.** После чистки игрок управляет танком напрямую, контекста игрока нет. Ввод берётся у машины из `VoxelSandboxStart`, затем у `Tank_01`, затем из контекста игрока.
- **Взрыв внутри PlayerLoop.** Сценарий ставит взрыв в очередь, а `Explode` вызывается из `Application.onBeforeRender`, как у настоящей бомбы. Раньше вызов шёл из `EditorApplication.update`, и стоимость взрыва в PlayerLoop не попадала. Поэтому авиаудар в базе 6.0 занижен.
- **Maximize On Play.** В результате `maximized: false`: поле читается с окна в фокусе. При этом `screen` 2294×1291 показывает, что Game view был развёрнут.

## Как повторить

1. Убедиться, что фон CPU без своего редактора ниже 25 %.
2. В редакторе на рабочей копии `game/develop`:
   ```
   unity cmd --port <порт> editor.playmode start
   unity cmd --port <порт> script eval --file Tools/PerfCheck/Bench/perf_bench.cs
   unity cmd --port <порт> script eval --file Tools/PerfCheck/Bench/perf_bench_read.cs
   ```
   Последнюю команду повторять, пока не вернёт JSON. В 6.3 `editor.playmode start` может не вернуть ответ, хотя Play начался: проверять `EditorApplication.isPlaying`.
3. Каждый прогон — новый вход в Play. Минимум два прогона.

Или одной командой: `/perf-check game/develop all`.

**Скопированная `Library`.** У части скриптов `MonoScript.GetClass()` возвращает null, на танке нет `MonoEntity`, и bench падает на поиске ввода. Лечится переимпортом таких скриптов с `ForceUpdate`. Подробно — в заметке звука `audio-library-copy-trap.md`.
