# Арены главы 1 «Окраины» — спецификация и план (веха 1)

**Дата:** 2026-11-18. **Команда:** арены. **Ветка:** `claude/arenas-84ef85` от `game/develop` (`dc272cb08`).
**Источник:** `Docs/Game/GDD.md` §3, §10, §13; план вехи `2026-11-18-milestone-1.md`.

## 1. Что делаем

| Часть | Итог |
|---|---|
| Генератор | Арена 40 × 40 м: воксельная земля с рельефом и грязью, 1–3 дома, деревья, деревянные заборы, ворота. Каждый забег разный: всё из сида. |
| Норы | Точки появления на краю арены. AI берёт точку не ближе 15 м к танку; при открытии земля рвётся воксельным кратером. |
| Ворота | Стена на дальнем краю. До зачистки проезд закрыт невидимой преградой, после — стену таранят или простреливают, за ней триггер проезда. |
| 5 арен | Описаны данными: `ArenaDefinition` (ScriptableObject) на каждую, `ArenaChapter` — их порядок. |
| Загрузка | Одна сцена главы на весь забег; арена пересобирается на месте под шторкой (предложение ушло тимлиду). |

## 2. Устройство

Код — в сборке `Game`, папка `Assets/Game/Scripts/Features/Arenas/`, namespace `Game.Arenas`. Так арены видят контракты ядра (`ArenaId`, `IRunService`) и GameContext, а ядро видит `IArenaService`.

- `ArenaDefinition` — данные одной арены: id, число домов и деревьев, раскладка (`Scattered`, `CoverForSpitters`, `HouseBlocksGate`), рельеф, доля грязи, число нор, подсказки (`ArenaHint`: управление, давка, «снеси укрытие»), элита.
- `ArenaChapter` — список арен главы по порядку, размер участка.
- `ArenaPlan` и `ArenaPlanner` — чистый C#: из определения и сида получается план. В плане: центр арены в мире, форма рельефа и площадки, дома (вид, размер, позиция, поворот), деревья, заборы, ворота, норы, точка въезда, укрытия Плевунов. План детерминирован и проверяется EditMode-тестами без сцены.
- `ArenaBuilder` — по плану строит объекты под корнем арены: землю (`VoxelStructure` Ground под `VoxelTerrainSettings`), дома и деревья (`VoxelStructure`), заборы (`ArenaFence`, свой генератор вокселей на `VoxelBody`), ворота, невидимые борта, подложку за краем. Старую арену уничтожает целиком.
- `ArenaService : MonoBehaviour, IArenaService` — на корне сцены главы. `Build(definition, seed)`, границы, норы, ворота, события. Кладётся в GameContext ключом `Arena`.
- `ArenaGate` — стена, преграда, триггер проезда. `Open()` снимает преграду и поднимает `GateOpened`; проезд поднимает `GatePassed`.
- `ArenaBurrows` — точки нор и их открытие: `VoxelDamage.AirBlast` с малым радиусом.

### Почему центр арены в мире сдвигается

Поля грязи и оттенки травы в `VoxelTerrain` считаются шумом от мировых координат, а не от сида. Поэтому арена ставится в мировую точку из сида (до ±1500 м, по целым метрам). Так узор грязи свой в каждом забеге, без правки кода вокселей. Нужная доля грязи арены подбирается выбором точки: планировщик проверяет несколько кандидатов по сетке 2 м.

## 3. Интерфейс для AI (режиссёр)

```csharp
public interface IArenaService
{
    event Action<ArenaPlan> Built;           // арена собрана: пересчитать навигацию
    event Action<Vector3> BurrowOpened;      // для звука и AI
    event Action GateOpened;
    event Action GatePassed;                 // танк проехал ворота: ядро ведёт к следующей арене

    bool IsBuilt { get; }
    ArenaDefinition Definition { get; }
    Bounds Bounds { get; }                   // игровая часть арены (40 × 40 м, высота с запасом)
    Vector3 Entry { get; }                   // где танк въезжает
    IReadOnlyList<Vector3> BurrowPoints { get; }
    IReadOnlyList<Vector3> CoverPoints { get; } // за домами от танка: для Плевунов на арене 3

    void Build(ArenaDefinition definition, int seed);
    bool TryPickBurrow(Vector3 tank, out int burrow); // нора дальше 15 м от танка
    Vector3 OpenBurrow(int burrow);          // кратер (если нора ещё закрыта) и точка выхода
    void OpenGate();                         // по «арена зачищена»
}
```

Нора открывается один раз: повторный `OpenBurrow` той же норы кратер не делает, только отдаёт точку.

## 4. Арены вехи (GDD §10)

| № | Раскладка | Дома | Особое |
|---|---|---|---|
| 1 | `Scattered` | 1 | Подсказка управления. Ровно, мало грязи |
| 2 | `Scattered` | 1–2 | Подсказка давки. Больше грязи |
| 3 | `CoverForSpitters` | 2 | Дом между танком и норами, за ним укрытия Плевунов; подсказка «снеси укрытие» |
| 4 | `HouseBlocksGate` | 1–2 | Дом посреди арены на линии въезд — ворота |
| 5 | `Scattered` | 2–3 | Элита: просторнее, норы для малой орды |

Танк въезжает с южного края, ворота — на северном. Составы волн — у AI, в определение арены не входят.

## 5. Производительность

- Сборка арены — под шторкой, не в бою. Цель — меньше 300 мс на арену в редакторе. Если выйдет дольше, сборка делится на кадры.
- Земля 52 × 52 м и глубиной 4 м: 520 × 40 × 520 вокселей, куски по 64.
- Нора — один `AirBlast` радиусом 1.5 м и не больше 600 обломков. Нора открывается один раз за волну, не на каждого монстра.
- В бою арена ничего не тикает. Проверка триггера ворот — физический триггер.

## 7. План

1. Данные: `ArenaDefinition`, `ArenaChapter`, `ArenaPlan`, `IArenaService`.
2. `ArenaPlanner` и EditMode-тесты: детерминизм, дома не перекрываются, норы на краю и не у ворот, дом арены 4 на линии въезд — ворота, ворота на дальнем краю.
3. `ArenaFence` — воксельный забор.
4. `ArenaBuilder`, `ArenaGate`, `ArenaBurrows`, `ArenaService`; маленькая правка `VoxelStructure.Configure` (задать вид, размер и сид из кода).
5. Сцена главы `Assets/Game/Scenes/Levels/Chapter1/` (копия песочницы без города, с корнем арены), `LevelConfig`, 5 ассетов арен — редакторским построителем.
6. PlayMode-тест: сборка арены, время, нора делает кратер, ворота пропускают после открытия.
7. Скриншоты 2–3 арен, `/perf-check`, отчёт тимлиду.
