# Интерфейсы игры: экраны, HUD, ввод

**Дата:** 2026-11-17
**Статус:** черновик, на согласовании у тимлида.
**Команда:** меню (пункт 3 общего плана), ветка `game/ui`.
**Общий план:** `Docs/superpowers/specs/2026-11-17-game-production-plan.md`.

## 1. Задача

Слова пользователя: «полноценные (пока что прототипные) интерфейсы для всей игры: главный экран, настройки, магазин, выбор уровней, игровой интерфейс, лаборатория (ангар), где мы будем собирать и улучшать наш танк».

Готово, когда: все экраны открываются и связаны переходами, настройки применяются и сохраняются, HUD показывает бой в VoxelSandbox, тесты зелёные, отчёт тимлиду.

## 2. Что есть сейчас

- UI игры нет. В VoxelSandbox — отладочный HUD на `OnGUI` (`Assets/Game/Voxels/Demo/VoxelDemoHud.cs`): подсказки клавиш и цифры вокселей. Он даёт GC-аллокации каждый кадр (перф-долг в `Docs/Reports/2026-11-17-perf-baseline.md`).
- Ввод — старый `Input`: `ControllableDriveController` (WASD/стрелки — оси `Horizontal`/`Vertical`, Shift — форсаж), `ControllableFireController` (ЛКМ — пушка, ПКМ — пулемёт), `VoxelSandboxOrbit` (мышь крутит камеру при захваченном курсоре, Esc отпускает курсор, двойной щелчок колесом — сброс камеры), `VoxelAirStrike` (X), `VoxelWeatherDemo` (B — дым, N — дождь). `activeInputHandler: 2` (оба ввода) — переход можно делать по частям.
- Данные для HUD у танка уже есть: `Health` (с событиями), `WeaponCooldown` и `Ammo` у пушки и пулемёта. Брони нет — в HUD она заглушка до геймдизайна.
- Шрифт `Assets/Game/Fonts/Roboto` (ttf, есть кириллица). TMP по умолчанию — LiberationSans (без кириллицы).

## 3. Решение

### 3.1. ScreenStack

Модуль `module/ScreenStack` (`b5be2183`) копируется в `Assets/Modules/ScreenStack` целиком: `Runtime`, `Tests`, `package.json`, `README.md`, `Documentation~`. Ядро не правим. Сборка `ScreenStack`, namespace `ScreenNavigation`.

Модуль ввод не читает: «назад» передаёт владелец стека (оркестратор) по действию `UI/Cancel` (Esc).

### 3.2. Сборки и папки

| Что | Где |
|---|---|
| Экраны, оркестраторы, HUD, заглушки сервисов | `Assets/Game/Scripts/UI/` (сборка `Game`, namespace `Game`) |
| Ввод: actions-ассет и сгенерированный класс | `Assets/Game/Configs/Input/GameControls.inputactions`, класс `GameControls` в `Assets/Game/Scripts/Shared/Input/` |
| Сборщики префабов экранов (редакторский код) | `Assets/Game/Scripts/Editor/UI/` (`…Builder`) |
| Префабы | `Assets/Game/Prefabs/UI/` (`MenuUi`, `BattleUi`, по экрану) |
| Данные-заглушки (ScriptableObject) | `Assets/Game/Configs/UI/` — `LevelCatalogConfig`, `TankModuleConfig`, `ShopCatalogConfig` |
| Шрифт TMP | `Assets/Game/Fonts/Roboto/Roboto_Regular_SDF.asset`, `Roboto_Bold_SDF.asset` (динамический атлас, кириллица) |
| Сцена меню | `Assets/Game/Scenes/MainMenu.unity` |
| Тесты | `Assets/Game/Tests/UI/` (EditMode), PlayMode-тесты экранов — отдельная сборка `Game.UI.SceneTests` |

Префабы экранов собираются кодом (`UiScreensBuilder`, пункт меню `Tools/UI/Rebuild Screens`): один стиль на все экраны задаётся в одном месте (`UiStyle`), префабы воспроизводимы, правка стиля — пересборка.

Модуль ScreenStack — отдельная сборка; `Game` на неё ссылается. Адаптер `Game.ScreenStack.Adapters` не нужен: наш код только наследует `UIScreen`.

### 3.3. Стиль

Один простой стиль на всё: тёмные полупрозрачные панели (`#14181Ccc`), светлый текст, один акцентный цвет (оранжевый `#F29A2E`) для главной кнопки и выделения, серый для недоступного, красный для ошибок и урона. Roboto, кнопки 48 px высотой. `CanvasScaler` — Scale With Screen Size, опорное 1920×1080, Match 0.5: на 16:9, 21:9 и 16:10 вёрстка держится, панели прижаты к краям якорями.

Ввод в меню — мышь (наведение подсвечивает, `SelectOnPointerEnter`), Esc — назад. Клавиатурная навигация работает через `EventSystem` как побочный эффект, отдельно не полируется.

Текст интерфейса — на русском (пользователь русскоязычный). Локализацию не вводим; все строки экранов лежат в префабах и данных, вынести их в таблицу потом несложно.

## 4. Экраны и переходы

### 4.1. Сцена меню (`MainMenu`)

Один стек, оркестратор `MenuFlow`. Корень — главный экран (`CanGoBack = false`).

```
Главный ──Играть──► Выбор уровня ──Начать──► [IGameFlow.StartLevel] → сцена уровня
   │                    └──Ангар──► Ангар
   ├──Ангар──────────► Ангар ──Магазин──► Магазин
   ├──Магазин────────► Магазин ──Купить──► Подтверждение (оверлей)
   ├──Настройки──────► Настройки ──Назначить клавишу──► Ожидание клавиши (оверлей)
   └──Выход──────────► Подтверждение (оверлей) ──Да──► [IGameFlow.Quit]
Esc / «Назад» на любом экране — Pop.
```

Сверху на экранах меню, кроме настроек, — полоска с балансом (кредиты) и названием экрана.

**Главный экран.** Слева колонка кнопок: Играть, Ангар, Магазин, Настройки, Выход. Справа фон (пока однотонный с названием игры; позже — 3D-ангар за меню). Внизу версия сборки.

**Выбор уровня.** Слева список карточек уровней: название, сложность, награда, замок для закрытых. Справа описание выбранного уровня, цель, кнопки «Начать» (акцент) и «В ангар». Закрытый уровень показывает, что нужно для открытия.

- Слоты слева (набор слотов — из данных). Выбор слота показывает внизу модули этого слота: установленный, купленные, некупленные (ведут в магазин).
- Наведение на модуль показывает справа разницу характеристик (зелёным/красным).
- «Установить» меняет модуль в слоте, «Улучшить» поднимает уровень модуля за кредиты. Нет денег — кнопка серая с ценой красным.
- Итоговые характеристики считает `TankLoadoutUseCase` из данных модулей. Применение к танку в бою — по готовности ядра и геймдизайна (сейчас танк в бою берёт свои значения из `TankInstaller`).

**Магазин.** Сверху вкладки по слотам (Пушки, Пулемёты, Корпуса, Двигатели, Гусеницы, Броня). Сетка карточек: название, 2–3 главные характеристики, цена, «Купить» или «Куплено». «Купить» открывает оверлей подтверждения с ценой и балансом после покупки. Справа — подробности выбранной карточки.

**Настройки.** Вкладки «Графика», «Звук», «Управление». Внизу «Применить», «По умолчанию», «Назад». Уйти с несохранёнными изменениями — оверлей «Применить изменения?».

- Графика: разрешение (список `Screen.resolutions` без дублей), режим окна (полный экран, окно без рамки, окно), качество (уровни `QualitySettings`), вертикальная синхронизация, ограничение FPS (нет, 60, 120, 144).
- Звук: ползунки «Общая», «Музыка», «Эффекты», «Интерфейс», «Окружение» (0–100). Каналы — предварительные, окончательный список даёт команда звука.
- Управление: таблица «действие — клавиша». Щелчок по клавише → оверлей «Нажмите клавишу… (Esc — отмена)». Клавиша занята другим действием той же карты — действия меняются клавишами, строка подсвечивается. «Сбросить» у строки и «Сбросить всё». Ползунок чувствительности мыши.

### 4.2. Бой (уровень, сейчас VoxelSandbox)

Префаб `BattleUi` со своим стеком, оркестратор `BattleFlow`. Корень стека — HUD (`CanGoBack = false`).

```
HUD ──Esc──► Пауза (оверлей) ──Продолжить / Esc──► HUD
               ├──Настройки──► Настройки (тот же экран, что в меню)
               ├──Заново─────► Подтверждение ──► [IGameFlow.RestartLevel]
               └──В меню─────► Подтверждение ──► [IGameFlow.ReturnToMenu]
Конец боя [IBattleResultSource.Finished] ──► Итоги (Replace, HUD скрыт)
Итоги: «Ещё раз» → RestartLevel, «В ангар» → ReturnToMenu(Hangar), «Следующий» → StartLevel(next)
```

При открытой паузе или итогах курсор свободен, ввод танка выключен (карта `Tank` отключается), игра стоит через `IPauseService`. На HUD курсор захвачен, как сейчас в VoxelSandbox.

- Прочность — из `Health` танка по событию изменения, броня — заглушка (полоса из данных, пока не меняется).
- Перезарядка пушки — полоса и дуга вокруг прицела из `WeaponCooldown` пушки; пулемёт — патроны из `Ammo`.
- Счётчики: убитые Regax из цели уровня и время боя — через интерфейс `IBattleStats` (сейчас — подсчёт смертей сущностей с тегом врага в VoxelSandbox).
- Мини-подсказки — клавиши берутся из текущих привязок Input System (после переназначения подсказка показывает новую клавишу). Гаснут через 15 с, F1 — показать и скрыть.
- FPS и отладочные цифры вокселей (бывшие строки `VoxelDemoHud`) — в отладочном блоке, F3, по умолчанию скрыт.
- Текст обновляется только по изменению значения или не чаще 4 раз в секунду, числа — через `TMP_Text.SetText(format, value)`: ноль аллокаций в кадре (правило `Docs/Rules/Performance.md`, раздел 5).

**Пауза.** Оверлей по центру поверх затемнения: «Продолжить», «Настройки», «Заново», «В меню», «Выйти из игры».

**Итоги боя.** «ПОБЕДА» / «ПОРАЖЕНИЕ», цель уровня, время, убито Regax, разрушено вокселей, награда кредитами (и бонусы строками). Кнопки «Ещё раз», «В ангар», «Следующий уровень» (если есть и открыт).

- **Подтверждение** — заголовок, текст, «Да» / «Нет»; Esc = «Нет».

## 5. Ввод (Input System)

Ассет `GameControls.inputactions`, генерация C#-класса включена.

| Карта | Действие | Тип | Клавиша по умолчанию |
|---|---|---|---|
| `Tank` | `Drive` | Value Vector2 | WASD и стрелки (композит) |
| | `Boost` | Button | Left Shift |
| | `FireMain` | Button | ЛКМ |
| | `FireSecondary` | Button | ПКМ |
| | `Look` | Value Vector2 (delta) | мышь |
| | `ResetCamera` | Button | двойной щелчок колесом (`MultiTap`) |
| | `Pause` | Button | Esc |
| | `ToggleHints` | Button | F1 |
| | `ToggleDebug` | Button | F3 |
| `UI` | `Navigate`, `Submit`, `Cancel`, `Point`, `Click`, `RightClick`, `MiddleClick`, `ScrollWheel` | стандарт `InputSystemUIInputModule` | Cancel — Esc |
| `Sandbox` | `AirStrike`, `Smoke`, `Rain` | Button | X, B, N (отладка песочницы) |

- Переназначение — `InputActionRebindingExtensions.PerformInteractiveRebinding`. Мышь как вторая клавиша для `FireMain`/`FireSecondary` допускается. Pause, Look и карта `UI` не переназначаются.
- Переопределения сохраняются строкой `SaveBindingOverridesAsJson()` в настройках (раздел 6) и грузятся при старте до включения карт.
- Один экземпляр `GameControls` на игру — сервис `IGameInput` (до AppContext — заглушка-синглтон в UI-сборке, потом ядро кладёт его в AppContext).

**Перевод управления танком** со старого `Input` на действия: `ControllableDriveController`, `ControllableFireController`, `VoxelSandboxOrbit` читают `IGameInput`. Команда чистки сейчас переписывает это управление на «прямо танк» — переводить надо уже её код, иначе конфликт. Предложение: я готовлю `IGameInput` и actions-ассет, а перевод делаю отдельным коммитом сразу после влития чистки в `game/develop` (вопрос 2 в разделе 9).

## 6. Сервисы-заглушки и связи с другими командами

Экраны говорят с игрой только через интерфейсы. `IGameFlow`, `IPauseService`, `ISettingsStore`, `IPlayerProgress`, `GameSettings` — контракты команды ядра (`Assets/Game/Scripts/App/Contracts/`, коммит ядра `dae0ff312`, перенесён в `game/ui` как есть). Пока ядра нет — простые реализации в `Scripts/UI/Stubs/`, доступ через временный `AppServices`; потом ядро даёт настоящие через AppContext, меняется только `AppServices`.

| Интерфейс | Что делает | Заглушка сейчас | Потом |
|---|---|---|---|
| `IGameFlow` | `StartLevel(levelId)`, `RestartLevel()`, `ReturnToMenu(screen)`, `Quit()`, `RequestedMenuScreen`, `IsBusy` | `SceneGameFlow`: `SceneManager.LoadScene`, id уровня → сцена по каталогу уровней | поток Boot → меню → уровень ядра |
| `IPauseService` | `Pause()`, `Resume()`, `IsPaused`, `PauseChanged` | `Time.timeScale = 0` | GameLoop ядра |
| `ISettingsStore` | `Current`, `Load()`, `Save()` (пишет, применяет графику, `Changed`) | JSON `settings.json`; громкости и клавиши UI применяет по `Changed` | SaveSystem ядра |
| `IPlayerProgress` | кредиты, модули и уровни модулей, установленные по слотам, открытые и пройденные уровни; `Changed`; сохраняет сам | JSON `progress.json` | SaveSystem ядра |
| `IAudioVolumes` | громкость канала 0–1 | общая — `AudioListener.volume`, остальные запоминаются | микшер команды звука |
| `IUiSounds` | `Hover`, `Click`, `Back`, `Open`, `Purchase`, `Error` | пусто | команда звука подключает звуки |
| `IBattleStats`, `IBattleResultSource` | счётчики боя, конец боя (победа/поражение, награда) | VoxelSandbox: смерти врагов и гибель танка; победа — убито N Regax | правила уровня от ядра и геймдизайна |

**Формат настроек** — `GameSettings` ядра: `graphics` (`width`/`height` 0 — текущее разрешение, `refreshRateHz`, `windowMode`, `qualityLevel` −1 — уровень проекта, `vSync`, `frameRateLimit`), `audio` (`master`, `music`, `effects`, `ui`, `ambient`), `controls` (`mouseSensitivity`, `bindingOverrides` — `SaveBindingOverridesAsJson()`). Слот модуля в прогрессе — строка `TankSlot.ToString()`.

**Данные-заглушки** (заменит геймдизайн; поля простые, чтобы заменить значения, а не код):
- `LevelConfig` — `id`, название, описание, сцена, сложность 1–3, цель (убить N), награда, условие открытия (предыдущий уровень). Каталог — `LevelCatalogConfig`. Сейчас два уровня: «Песочница» (VoxelSandbox) и закрытый «Карьер» (та же сцена).
- `TankModuleConfig` — `id`, слот (`TankSlot`: Gun, MachineGun, Hull, Engine, Tracks, Armor), название, цена, уровни улучшения (цена и прибавки `TankStats` на уровень). Каталог — `ShopCatalogConfig`. По 2–3 модуля на слот.
- `TankStats` — прочность, броня, скорость, урон пушки, перезарядка, темп пулемёта.

## 7. Производительность

- HUD без `OnGUI`, без аллокаций в кадре; Canvas HUD разбит на статичный и часто меняемый (прицел, перезарядка), чтобы не перестраивать весь.
- `VoxelDemoHud` убирается со сцены VoxelSandbox (заменяется блоком F3 в HUD) — перф-долг «IMGUI-HUD» уходит.
- Новый сценарий замера `menu` (раздел 3 `Performance.md`): 4 с на главном экране и 4 с в ангаре — шаг в `Tools/PerfCheck/Bench/`.

## 8. Как проверяем

- EditMode: `GameSettings` (сериализация туда и обратно, версии), `TankLoadoutUseCase` (сумма характеристик), покупка и улучшение в `PlayerProgress` (нет денег, уже куплено), переназначение клавиш (конфликт — обмен, сохранение и загрузка переопределений), применение настроек графики к заглушке.
- PlayMode (`Game.UI.SceneTests`): все переходы меню из раздела 4 (каждый экран открывается, Esc возвращает), пауза над HUD останавливает время и выключает карту `Tank`, HUD показывает прочность и перезарядку танка в VoxelSandbox.
- Скриншоты каждого экрана (1920×1080 и 2560×1080) — пользователю.
- `/perf-check` ветки: нет аллокаций в простое и езде; сценарий `menu`.
