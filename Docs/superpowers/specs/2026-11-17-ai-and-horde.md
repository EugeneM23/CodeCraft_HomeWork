## 3. Навигация по разрушаемой земле

### 3.1 Выбор: своя сетка по вокселям и поле потоков, а не NavMesh

| | Перестройка NavMesh по чанкам | **Своя сетка высот + поле потоков** |
|---|---|---|
| Пакеты | Нужен `com.unity.ai.navigation` (`NavMeshSurface`), его в проекте нет | Ничего нового: Burst, Collections, Mathematics уже есть |
| Перестройка после воронки | Сбор источников (меши коллайдеров чанка) на главном потоке + асинхронная сборка тайла. Поверхность вокселей рваная, треугольников много | Пересчёт высот только в квадрате изменённого чанка, Burst. Ожидаю десятки микросекунд |
| Орда | `NavMeshAgent` на тысячи монстров не годится: агент — компонент со своей симуляцией на каждого | Одно поле потоков к танку на всех. Цена не зависит от числа монстров |
| Элитные | `NavMeshAgent` из коробки (адаптер AIKit) | Свой `INavigator` для AIKit поверх той же сетки: поиск пути A* на Burst |
| Дома | Нужно отдельно гасить тайлы | Дом — высокий столб на сетке, через него не пройти. Сломали — столб стал ниже, проход открылся сам |

Выбираю **свою сетку**: одна структура данных на орду и элитных, обновление по изменённым местам дёшево, пакет NavMesh не нужен. Адаптер NavMesh из AIKit переносим, но в игре не используем.

**Замер стоимости** (п. 7, шаг 2) снимаю в своём редакторе до начала мозга: перестройка сетки после одной воронки, поле потоков на всю карту, A* на 100 м; для сравнения — `NavMeshBuilder.UpdateNavMeshDataAsync` по тайлу земли той же площади. Если своя сетка окажется дороже NavMesh, вернусь к выбору и сообщу.

### 3.2 Устройство

- **`HordeNavGrid`** (сборка `Game.Horde`, Burst): квадратные ячейки **0.5 м** по XZ на весь уровень. В ячейке — высота поверхности (`float`) и признак «проходима». Ячейка непроходима, если перепад высоты с соседом больше шага монстра (0.6 м) или над поверхностью нет места на рост.
- **Как узнать высоту:** лучи вниз (`RaycastCommand` пачкой, на рабочих потоках) по слою земли и домов. Воксели напрямую не читаем: у `VoxelBody` нет открытого доступа к сетке, а коллайдер чанка и так отражает раскопки. Карта 200×200 м — 160 000 лучей при загрузке, один чанк 6.4×6.4 м — 169 лучей.
- **Когда обновлять:** нужен сигнал «коллайдер чанка поменялся» с границами чанка. **Просьба к вокселям (через тимлида):** в `VoxelWorld` добавить событие `ChunkCollidersChanged(Bounds)` в месте, где новый коллайдер чанка встаёт на место. Около 10 строк, без изменения поведения. Сделаю сам в своей ветке, если вокселизатор согласен; иначе — их правка.
- **Поле потоков** (`HordeFlowField`): поиск в ширину / Дейкстра от ячейки цели по проходимым ячейкам, Burst, на рабочем потоке. Пересчёт — когда цель сменила ячейку или сетка изменилась, не чаще 5 раз в секунду. Результат — направление в каждой ячейке.
- **Путь для элитного:** `VoxelGridNavigator : INavigator` (сборка адаптеров) — A* по той же сетке до любой точки, со сглаживанием по прямой видимости на сетке. Перепланирует, когда сетка изменилась на пути. Если цель — танк, может просто брать направление из поля потоков.

## 4. Элитный Regax на AIKit

### 4.1 Сборка и папки

`Assets/Game/Scripts/Features/AI/` — сборка **`Game.AIKit.Adapters`** (ссылки: `Game`, `Game.Voxels`, `Game.Horde`, `AIKit`, `AIKit.NavMesh`, Atomic, Mathematics). `Game` на неё не ссылается. Тесты — `Assets/Game/Tests/AI/` в своей сборке `Game.AIKit.Adapters.Tests` (EditMode) и PlayMode-тест сцены.

```
Features/AI/
  AIAPI.cs                   ключи сущностей AI, [EntityExtensionsAPI]
  Common/                    AIWorld на уровне, тик, сканер целей, события взрывов
  Navigation/                VoxelGridNavigator
  EliteRegax/                инсталлер, тело (AgentBody), атака, граф поведения
  Horde/                     мост: орда как Atomic-сущность, урон, давка
```

### 4.2 Тело: `AtomicAgentBody`

AIKit всегда работает через свой компонент `AICharacter`, его не заменить. Ставим `AICharacter` на префаб Regax и даём ему свои части через `SetParts(actuator, navigator)`:

| Что AIKit просит | Наша реализация |
|---|---|
| `IAgentActuator` (виртуальный геймпад) | `AtomicActuator`: `Move(dir)` → `MoveDirection` сущности, `Face(dir)` → `RotateDirection`, `Stop()` обнуляет. Скорость и поворот — наши `MoveSpeed`/`RotationSpeed`. Прыжков нет |
| `INavigator` | `VoxelGridNavigator` (п. 3.2) |
| Зрение `ISightProbe` | `PhysicsEyes3D` из адаптера NavMesh: лучи по слоям земли и домов |
| Сканер целей `ITargetScanner` | `PlayerTankScanner`: отдаёт `Transform` сущности игрока из `PlayerContext.GetCharacter()`. `FindGameObjectsWithTag` не используем — он аллоцирует |
| Удар | `IAbilityRunner` «Bite» (`RegaxBiteRunner`): вызывает наше оружие `Regax_Hand` (`GetFireAction`). Урон танку идёт через наш `DamageUseCase`, как сейчас |
| `IHitReceiver` | `AtomicHitReceiver` на сущностях с `Health`: `ReceiveHit(HitInfo)` → `DamageUseCase.TakeDamage`. Нужен, если позже оружие задаётся ассетом AIKit. Обратно: наш `DamageTakenEvent` Regax → `AICharacter.ReceiveHit`, чтобы мозг знал, кто его бьёт |
| `IHealth` | `AtomicHealthView`: читает наш `Health` |

**Высота над землёй.** Сейчас Regax двигается `transform.position +=` и не следит за землёй, а земля роется. Элитный ставится на высоту ячейки сетки (с плавным подъёмом), без физики. Rigidbody у элитного становится кинематическим. Давка танком работает и с кинематическим: `TankCrushBehaviour` ищет жертву через `OverlapBox`.

### 4.3 Тик

- `AIWorldBehaviour` на `GameContext`: в своём тике вызывает `world.BeginStep(dt)`, затем `agent.Step(dt)` у всех зарегистрированных агентов. `AICharacter` — в режиме `Manual`, `AIWorldRunner` в сцене нет.
- До готовности GameLoop ядра это тик Atomic-мира (`IEntityTick`). Когда ядро вольёт GameLoop, мир Atomic перейдёт на него, и AI вместе с ним — правок у нас не будет.
- Бюджет решений AIKit: не больше 8 «думаний» за шаг (`MaxDecisionsPerStep`).

### 4.4 Мозг

Граф поведения — ассет `Regax_Elite_Brain` (редактируется в окне графов AIKit). Строим его из кода редакторским сборщиком на основе пресета `BehaviorPresets.MeleeChaser`, чтобы ассет можно было пересобрать.

1. **Нет цели** — бродит у точки появления.
2. **Видит танк** — идёт к нему по сетке, в обход домов и ям.
3. **В радиусе удара** (по краю корпуса танка, как в нынешнем AI) — удар «Bite», пауза.
4. **Взрыв рядом** (в радиусе ×1.5 от радиуса взрыва) — короткое оглушение, затем отскок от центра взрыва на 3–5 м, затем снова к танку. Попадание по нему — то же без отскока.
5. **Цель пропала** (танк уничтожен) — к последнему месту, потом бродит.

**Сигнал взрыва.** Сейчас события взрыва нет. **Просьба (через тимлида):** в `ExplosionUseCase.Explode` и `VoxelAirStrike` вызвать статическое событие `ExplosionEvents.Exploded(Vector3 point, float radius)` (новый файл в `Features/Explosions`). Две строки в чужих файлах. Его слушают элитные и орда.

Анимация: нынешний `CharacterAnimInstaller` читает скорость и атаку сущности — это работает и с AIKit. Адаптер Mecanim AIKit переносим, но пока не подключаем.

Старый AI (`Features/Character/EnemyCharacter/AI`) удаляю, когда элитный заработает; в VoxelSandbox все Regax стоят на месте (`_standStill`), так что старым AI сейчас никто не пользуется. Делаю это последним коммитом, чтобы не пересечься с чисткой.

## 5. Орда

### 5.1 Сборка

`Assets/Game/Horde/` — `Runtime` (сборка **`Game.Horde`**: Burst, Collections, Mathematics, без `Game`), `Tests`, `Shaders`. Сетка навигации и поле потоков живут здесь же, их читают и элитные.

### 5.2 Данные и кадр

Монстр — индекс в `NativeArray`: позиция, скорость, направление, здоровье, состояние (идёт, бьёт, умирает), кадр анимации, разброс скорости. Кадр:

1. **EarlyUpdate:** забрать результат прошлого кадра (как у `VoxelWorld`), без ожидания в том же кадре.
2. `HordeSpatialHashJob` — ячейки 1 м, соседи для расхождения.
3. `HordeSteerJob` (parallel, Burst) — направление из поля потоков + разделение с соседями + торможение у танка. Высота — из сетки.
4. `HordeContactJob` — давка: монстр внутри повёрнутого прямоугольника корпуса танка при скорости танка выше порога → смерть. Удар по танку: монстр у корпуса копит урон, сумма за кадр уходит в наш `Health` танка одним вызовом.
5. Урон по области (взрыв): очередь запросов «сфера, урон», обрабатывается в задаче.
6. `HordeRenderJob` — матрицы и кадр анимации живых в буфер для отрисовки, отсечение по камере.

Маркеры профайлера: `Horde.Simulate`, `Horde.Render`, `Horde.FlowField`, `Horde.NavGrid`.

### 5.3 Смерть и трупы

Никакой вокселизации на лету. Смерть = монстр выпадает из симуляции, на его месте:
- брызги крови из нашего `VoxelSpray` (лимит на кадр, остальные смерти этого кадра — без брызг);
- **заготовленный труп:** заранее запечённый воксельный меш позы смерти (2–3 варианта), рисуется инстансингом, лежит N секунд и тонет в землю. Не `VoxelBody`, без физики. Запекание — инструментом вокселизатора, по готовности; до него — меш, запечённый моим редакторским скриптом через `SkinnedVoxelizer`.

### 5.4 Отрисовка

- `Graphics.RenderMeshIndirect` (или `RenderMeshInstanced` пачками), данные экземпляров в `GraphicsBuffer`.
- **Запечённая анимация** (VAT): бег, удар и стойка Regax запекаются в текстуру позиций вершин. Шейдер берёт кадр по номеру экземпляра. Шейдер — для URP (рендер переходит на него) с запасным проходом Built-in на время, пока URP не влит.
- Меш: Regax сейчас ~17 тыс. треугольников. Для толпы нужен лёгкий: 1–2 тыс. Беру упрощённый LOD (Mesh LOD Unity 6.x или ручное упрощение). Тени у толпы — только у ближних, по замеру.

### 5.5 Для игры — одна Atomic-сущность

`HordeEntity` в `GameContext` (мост в `Features/AI/Horde`): спавн волн, живые/убитые, события «монстр убит» (для наград и звука), урон по области. Звук орды — через команду звука: события, а не 1000 источников.

### 5.6 Замер

Сценарий **horde** в `Tools/PerfCheck/Bench` (раздел 3 правил): VoxelSandbox, орда N монстров появляется кольцом вокруг танка, 8 с, танк едет вперёд-назад. Прогоняю N = 250, 500, 1000, 2000, 4000, 8000 и смотрю отдельно CPU (PlayerLoop, `Horde.*`) и GPU. Ответ: наибольшее N, при котором средний PlayerLoop ≤ 5 мс и GPU ≤ 4 мс, плюс где упирается (симуляция, отрисовка, давка).
