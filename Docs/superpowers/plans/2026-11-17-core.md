## Общие правила для исполнителей

- Код и комментарии — по-английски, стиль — `Docs/Rules/Project.md` (поля `_camelCase`, константы `UPPER_SNAKE`,
  один тип на файл, namespace = rootNamespace сборки, никаких `…Manager/…Helper/…Utils`).
- Atomic — по `Docs/AtomicGuide` (особенно `11-entities-install.md`, `15-codegen.md`). Инсталлеры исполняются и в
  Edit Mode (`MonoEntity.Compile`): побочные эффекты (Instantiate, подписки, файлы) — только за
  `AtomicUtils.IsPlayMode()` или в поведениях `Init`.
- Методы `GetX()/AddX()` для ключей `AppContextAPI` генерирует Roslyn-генератор; писать их руками не нужно.
- Модули в `Assets/Modules/*` не правим. Читать их README и код можно.
- Unity не запускать и не перекомпилировать: компиляцию и тесты гоняет ведущая сессия. Пиши аккуратно, сверяй
  сигнатуры по исходникам.
- Каждый новый `.cs` без `.meta` — Unity создаст сам. Не коммитить: коммитит ведущая сессия.
- Тесты: EditMode — `Assets/Game/Tests/App/...` (сборка `Game.Tests`, добавь ей ссылки на модули);
  PlayMode — новая сборка `Game.App.SceneTests` в `Assets/Game/Tests/App/PlayMode/` (Editor-only,
  `UNITY_INCLUDE_TESTS`, `autoReferenced: false`, как `Game.Voxels.SceneTests`).

## Задача A. Тики через GameLoop

1. `Game.Voxels`: `VoxelTicks` (статический хаб), интерфейсы `IVoxelUpdate`, `IVoxelLateUpdate`, `IVoxelFixedUpdate`
   (методы `VoxelUpdate(float dt)` и т. п.). Хаб: `Add(object)`/`Remove(object)` из `OnEnable`/`OnDisable`
   компонентов; списки по фазам, отсортированные по `[DefaultExecutionOrder]` класса (кэш по типу), при равенстве — по
   порядку добавления; удаление во время прохода безопасно; исключение одного — `Debug.LogException`, остальные
   тикают. `bool Driven { get; set; }`, `float Time` (Driven — время владельца, иначе `UnityEngine.Time.time`),
   `void SetTime(float)`, `Update/LateUpdate/FixedUpdate(float dt)`. Сброс статики на входе в Play
   (`RuntimeInitializeOnLoadMethod(SubsystemRegistration)`).
2. Перевести компоненты `Assets/Game/Voxels/Runtime/`: `VoxelWorld`, `VoxelRain`, `VoxelSmoke`, `VoxelTrackRuts`,
   `VoxelRammer`, `VoxelSettle`, `VoxelDrip`, `VoxelSmokeSource`, `VoxelImpactFracture`. Тело Unity-метода → метод
   интерфейса; Unity-метод: `if (!VoxelTicks.Driven) VoxelLateUpdate(Time.deltaTime);`. `Time.time` → `VoxelTicks.Time`
   (в FixedUpdate-методах тоже). `Time.fixedDeltaTime` оставить. Поведение без владельца — ровно как раньше.
   Правки минимальные: файлы правит и команда чистки.
3. Сборка `Game.GameLoop.Adapters` (`Assets/Game/Scripts/Adapters/GameLoop/`, rootNamespace
   `Game.GameLoop.Adapters`, ссылки `GameLoop`, `Game.Voxels`, `Atomic.Entities`):
   - `AtomicTickBridge : IUpdateListener, IFixedUpdateListener, ILateUpdateListener, IDisposable` — один раз через
     reflection находит internal `Atomic.Entities.TickableManager` (статическое свойство `Instance`, приватные
     `Update/FixedUpdate/LateUpdate`), выключает компонент менеджера (`enabled = false`) и зовёт его методы через
     закрытые делегаты `Action` из своих фаз. Менеджер создаётся лениво и пересоздаётся на новый Play — проверяй
     `== null` (Unity-null) каждый тик и переподключайся. Нет типа/метода — `Debug.LogError` один раз и ничего не
     трогать (Atomic тикает сам). `Dispose` — включить менеджер обратно.
   - `VoxelTickBridge : IUpdateListener, IFixedUpdateListener, ILateUpdateListener, IDisposable`,
     `[DefaultExecutionOrder(5000)]`, конструктор `(IGameLoop loop)`: ставит `VoxelTicks.Driven = true`; в `OnUpdate`
     сначала `VoxelTicks.SetTime(loop.Time)`, потом `VoxelTicks.Update(dt)`; остальные фазы — свои. `Dispose` —
     `Driven = false`.
4. `Game` (`Assets/Game/Scripts/App/Ticking/`): `GameTicks` — `static bool TryAdd(object listener)` /
   `Remove(object)` (`AppContext` есть и у него есть `GameLoop` → добавить, вернуть true), `static float Time`
   (цикл есть → `loop.Time`, иначе `UnityEngine.Time.time`). Наличие AppContext проверять без исключения
   (`MonoEntitySingleton.Instance` бросает) — найди безопасный способ в исходнике `MonoEntitySingleton`.
   Перевести `Features/Mud/MudSurface.cs` (LateUpdate), `Shared/Vfx/ExplosionFlash.cs` (Update),
   `Features/Voxels/VoxelAirStrike.cs` (Update): реализуют `ILateUpdateListener`/`IUpdateListener`, в `OnEnable` —
   `_looped = GameTicks.TryAdd(this)`, в `OnDisable` — `Remove`, Unity-метод работает при `!_looped`; `Time.time`
   → `GameTicks.Time`. Сохранить существующие `[DefaultExecutionOrder]`.
5. `GameLoopInstaller : MonoEntityInstaller<AppContext>` (`App/Ticking/`): поле `GameLoopRunner _runner`; в Play Mode
   кладёт `context.AddGameLoop(_runner.Loop)`, добавляет в цикл `AtomicTickBridge` и `VoxelTickBridge`; в
   `Uninstall` — удаляет и `Dispose`.
6. Тесты: EditMode `Game.Voxels.Tests` — `VoxelTicksTests` (порядок по атрибуту, удаление во время прохода, Driven
   и время). PlayMode `Game.App.SceneTests` — `AtomicTickBridgeTests` (MonoEntity с поведением-счётчиком тиков:
   тикает через цикл, на `loop.Pause` стоит, после `Dispose` тикает сам), `VoxelTickBridgeTests`.

## Задача B. Поток игры, уровни, экран загрузки

Папка `Assets/Game/Scripts/App/Flow/` и `App/Levels/`, `App/Loading/`.

1. `SceneReference` (`[Serializable]`: строка `_path`; в редакторе — `SceneAsset` через `#if UNITY_EDITOR` поле и
   `OnValidate`/PropertyDrawer в `Game.Editor` — достаточно простого: сериализованный `SceneAsset` editor-only +
   путь, который обновляется в `ISerializationCallbackReceiver.OnBeforeSerialize` под `#if UNITY_EDITOR`).
2. `LevelConfig : ScriptableObject` (`CreateAssetMenu "Game/Level"`): `Id`, `DisplayName`, `IReadOnlyList<SceneReference>
   Scenes`, `int ActiveSceneIndex`, `bool Contains(string scenePath)`. `LevelCatalog : ScriptableObject`:
   `IReadOnlyList<LevelConfig> Levels`, `SceneReference MainMenuScene`, `LevelConfig Find(string id)`,
   `LevelConfig FindByScene(string scenePath)`, `bool IsMenuScene(string path)`.
3. Операции (наследники `Loading.LoadingOperation`): `UnloadSceneOperation(string path, float weight = 1)`,
   `SetActiveSceneOperation(string path)` (вес 0).
4. `LevelLoader`: `LoadingOperation Load(LevelConfig level)` — дерево: первая сцена Single, остальные — Parallel
   Additive (`LoadSceneOperation(path, LoadSceneMode.Additive)`), затем активная сцена;
   `LoadingOperation LoadMissing(LevelConfig level)` — для холодного старта: только незагруженные сцены набора
   аддитивно + активная; `LoadingOperation Unload(LevelConfig level)` — аддитивные сцены набора, кроме активной.
5. `ILoadingScreen { void Show(bool instant); void SetProgress(float value); void Hide(); bool IsShown { get; } }`;
   `LoadingScreen : MonoBehaviour, ILoadingScreen` — uGUI: `CanvasGroup` (затемнение, fade на unscaled-времени),
   `Image` с `fillAmount` или `Slider` для прогресса; блокирует ввод, пока показан.
6. `GameState { Starting, MainMenu, Level }`. `GameFlow : IAppTickable` — конструктор
   `(LevelCatalog catalog, LevelLoader loader, ILoadingScreen screen)`. Внутри `LoadingRunner`. Публично:
   `event Action<GameState> StateChanged`, `event Action<GameState, GameState> TransitionStarted` (откуда, куда —
   на него автосохранение пишет прогресс), `event Action LoadingStarted`, `event Action<bool> LoadingFinished`,
   `GameState State`, `LevelConfig CurrentLevel`, `bool IsBusy`, `float LoadingProgress`;
   `bool Boot()`, `bool OpenLevel(LevelConfig)`, `bool RestartLevel()`, `bool ExitToMainMenu()`, `void Quit()`
   (в редакторе — `EditorApplication.isPlaying = false` под `#if UNITY_EDITOR`), `void EnterOpenScene(Scene scene)`
   (холодный старт: меню — сразу `MainMenu`; сцена уровня — `LoadMissing`, затем `Level`). Ошибка перехода —
   `Debug.LogError`, состояние прежнее, экран скрывается. `Tick` тикает раннер и шлёт прогресс экрану.
   Экран — `screen.Show` на старте перехода, `Hide` после. Переход на сцену с паузой: перед стартом перехода снимать
   все паузы не нужно — уровень выгружается; но `GameFlow` получает `IGameLoop` (необязательный параметр
   конструктора) и вызывает `ResumeAll()` после перехода, чтобы новая сцена не стартовала на паузе.
7. `AppInstaller : MonoEntityInstaller<AppContext>` (`App/`): поля `LevelCatalog _catalog`, `LoadingScreen _loadingScreen`,
   `AppTicker _ticker`. Play Mode: `AddAppTicker`, `AddLevelCatalog`, `AddLevelLoader(new LevelLoader())`,
   `AddLoadingScreen`, `AddGameFlow(new GameFlow(...))`, `ticker.Add(flow)`. Цикл берёт из контекста
   (`GameLoopInstaller` стоит раньше в списке инсталлеров) — если нет ключа, без него.
8. `AppBootstrap : MonoBehaviour` (сцена `Boot`): поле `AppContext _appPrefab`. `Awake`: если `AppContext` уже есть
   (безопасная проверка, см. задачу A.4) — warning и выход; иначе `Instantiate`, затем `GetGameFlow().Boot()`.
   Статический `AppContext CreateApp(AppContext prefab)` — общий с холодным стартом.
9. `EditorColdStart` (`#if UNITY_EDITOR`, в сборке `Game`, `App/Flow/`): как в Platformer — `BeforeSceneLoad`:
   активная сцена — меню или сцена уровня из каталога, AppContext нет → создать приложение (префаб и каталог найти
   через `AssetDatabase` по пути `Assets/Game/Prefabs/App/App.prefab`, константа); `AfterSceneLoad` —
   `flow.EnterOpenScene(scene)`. Тестовые сцены (`InitTestScene*`), `Boot` и прочие сцены — не трогать.
   Флаг-меню `Tools/Game/Cold Start` (EditorPrefs) для отключения — в `Game.Editor`.
10. `PauseHotkey : MonoBehaviour` (`App/Pause/`) — Esc (`Keyboard.current.escapeKey.wasPressedThisFrame`, Input
   System) держит/отпускает паузу `loop.Pause(this)`/`Resume(this)`; `public static bool Enabled = true` для меню.
   `LevelExitHotkey` — F10 → `ExitToMainMenu()` (отладка). `MainMenuStub : MonoBehaviour` — две кнопки uGUI
   («Играть» → `OpenLevel(catalog.Levels[0])`, «Выход» → `Quit()`), кнопки назначает инспектор.
11. Тесты: EditMode — `GameFlowTests` (фейковый `ILoadingScreen`, дерево с фейковыми операциями: подменить загрузчик
   можно через интерфейс `ILevelLoader`, если нужно — сделай `LevelLoader` реализацией `ILevelLoader`, а ключ
   `AppContextAPI.LevelLoader` поменяй на интерфейс), `LevelCatalogTests`. PlayMode — `LevelLoaderTests`: две
   тестовые сцены `Assets/Game/Tests/App/PlayMode/Scenes/CoreTestLevel_A.unity`, `_B.unity` (создаст ведущая
   сессия; тест грузит их по пути — в редакторе `LoadSceneOperation` грузит вне Build Settings), проверка прогресса
   0→1, активной сцены, выгрузки.

## Задача C. Настройки и прогресс

Папка `Assets/Game/Scripts/App/Saves/`. Модуль SaveSystem: `Saving.SaveLoadService(ISaveStorage, string gameVersion)`,
`FileSaveStorage`, `InMemorySaveStorage`, `GameSerializer<T, TData>` — сверься с исходником в `Assets/Modules/SaveSystem/Runtime/Core/`
(версии секций, миграции, конструкторы).

1. Данные (`[Serializable]`, публичные поля camelCase): `AudioSettingsData` (`Dictionary<string,float> volumes`,
   `bool muted`), `GraphicsSettingsData` (`qualityLevel`, `resolutionWidth`, `resolutionHeight`, `refreshRateHz`,
   `fullScreenMode`, `vSync`, `targetFps`), `ControlsSettingsData` (`bindingOverridesJson`, `mouseSensitivity`,
   `invertY`), `SettingsData` (три поля). Значения по умолчанию — «как сейчас»: громкости 1, качество — текущее
   `QualitySettings`, разрешение — текущее, `mouseSensitivity` 1. Ключи шин — константы в `AudioBusKeys`
   (`MASTER = "Master"`, `MUSIC`, `SFX`, `UI`, `AMBIENCE`).
2. `GameSettings` — сервис: `SettingsData Data`, удобные `GetVolume(string bus)`/`SetVolume`, `event Action Changed`,
   `NotifyChanged()`, `Apply()` (качество, разрешение+режим, vsync, targetFrameRate; в редакторе разрешение не
   трогать), `Save()`, `Load()`. Внутри — свой `SaveLoadService` и `SettingsSerializer : GameSerializer<...>`.
3. `ProgressData`: `Dictionary<string,int> currencies`, `List<string> unlockedLevels`, `List<string> completedLevels`,
   `Dictionary<string,int> upgrades`, `Dictionary<string, Newtonsoft.Json.Linq.JObject> extensions` (или строка JSON —
   выбери то, что сериализатор модуля держит без боли). `PlayerProgress` — сервис: методы из спецификации
   (`GetCurrency/AddCurrency/TrySpend`, `IsLevelUnlocked/UnlockLevel`, `MarkLevelCompleted/IsLevelCompleted`,
   `GetUpgradeLevel/SetUpgradeLevel`, `T Get<T>(string key)` + `void Set<T>(string key, T value)` для расширений),
   `event Action Changed`, `bool IsDirty`, `Save()`, `Load()`, `ResetProgress()`.
4. Хранилища: `SaveStores` (статический класс-фабрика) — `ISaveStorage Settings()` → `FileSaveStorage` в
   `Path.Combine(Application.persistentDataPath, "Settings")`, `Progress()` → `".../Saves"`. Сервисам хранилище
   передаётся в конструктор (тесты дают `InMemorySaveStorage`). Версия игры — `Application.version`.
5. `ProgressAutosave : IAppTickable, IDisposable` — `(PlayerProgress progress, GameFlow flow, float delaySeconds)`:
   сохраняет `delaySeconds` реального времени после последнего `Changed`; на `flow.TransitionStarted` — сразу;
   `flow` может быть null. `AppLifecycleSaves : MonoBehaviour` (на App-префабе) — `OnApplicationFocus(false)`,
   `OnApplicationPause(true)`, `OnApplicationQuit` → `progress.Save()` если грязный, `settings.Save()`.
6. `SaveInstaller : MonoEntityInstaller<AppContext>`: `[SerializeField] float _autosaveDelay = 3f`,
   `AppLifecycleSaves _lifecycle`. Play Mode: создать и загрузить `GameSettings` (сразу `Apply()`), `PlayerProgress`;
   `AddSettings`, `AddProgress`; автосохранение в `AppTicker` (`context.GetAppTicker()` — `AppInstaller` стоит раньше)
   с `flow` из контекста, если есть.
7. Тесты EditMode (`Game.Tests`, `Assets/Game/Tests/App/Saves/`): круговая запись/чтение настроек и прогресса через
   `InMemorySaveStorage`, неизвестная валюта = 0, `TrySpend` без денег, расширение `Get<T>` переживает сохранение,
   автосохранение по задержке и по переходу, файл старой версии секции читается (миграция — хотя бы каркас v1).
