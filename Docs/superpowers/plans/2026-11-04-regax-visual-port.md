# Regax (Rapax) Visual Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the enemy's zombie look with the Rapax creature from the SPrototype project — mesh, skeleton, animations, hit and death effects — leaving every line of this project's gameplay logic untouched.

**Architecture:** Assets are copied file-by-file with their `.meta` files so GUIDs survive, then repaired for this project's render pipeline. A new `Regax.prefab` is generated by an editor script from `Zombie.prefab`, swapping only the visual subtrees and re-pointing the installer references that moved. The animator reaches the creature through a weapon-side override controller, because `SwitchAnimatorBehaviour` takes the runtime controller from the weapon, not from the prefab.

**Tech Stack:** Unity 6000.0.38f1, Built-in Render Pipeline, Atomic Entities framework, OmniShade (built-in variant), KriptoFX VolumetricBloodFX, RPG_VFXPack.

**Spec:** `Docs/superpowers/specs/2026-11-04-regax-visual-port-design.md`

## Global Constraints

- Source project: `C:\!!!Work\SPrototype`. It is read-only — nothing is written there.
- Every copied asset is copied together with its `.meta` file, byte for byte. GUIDs must not change, or the references between the copied assets break.
- **This project is Built-in Render Pipeline** (`ProjectSettings/GraphicsSettings.asset` has `m_CustomRenderPipeline: {fileID: 0}`, and `Packages/manifest.json` has no `com.unity.render-pipelines.*`). The source project is URP 17. No URP asset may be copied without being repaired.
- Third-party content lives in `Assets/3rdParty/<Vendor>/`, following the existing folders there (`EffectCore`, `FXIFIED`, `HighlightPlus`, `Kevin Iglesias`, `OmniShade`, `PixPlays`, `RifleAnimsetPro`). The spec said `Assets/Game/3rdParty`; that folder does not exist and the convention above wins.
- No gameplay logic changes. `Zombie.prefab`, `GameScene.unity` and everything under `Assets/Game/Scripts` outside `Editor/` stay as they are.
- The documentation folder in this repository is `Docs` with a capital D.
- Unity is open on this project (`Temp/UnityLockfile` exists) and there is no MCP bridge to it, so the editor script is run by the user from the menu. Batch mode would fail on the lock.
- Git: commit after each task. Attribution line on every commit: `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`

**Reference — what the investigation established:**

- `Zombie.prefab` root children: `<Skeleton>` (holds the `Animator` and the `AnimationEventReceiver`), `<Skin>` (the `SkinnedMeshRenderer`), `<Collider>`, `<Audio>`, `<Weapons>`, `<VFX>` (children `BulletDamageBlood`, `MeleeDamageBlood`, `DeathBlood`, `DeadBlood`), `<PatrolPoints>`.
- Installer references that point into the visual subtree, and so have to be re-pointed:
  `EnemyAnimInstaller._animator` to `Animator on <Skeleton>`;
  `EnemyAnimInstaller._animationReceiver` to `AnimationEventReceiver on <Skeleton>`;
  `EnemyVfxInstaller._bulletBlood/_meleeBlood/_deadBlood/_deathBloodVfx` to the four `<VFX>` children;
  `EnemyVfxInstaller._rootTransform` to `Transform on <Skeleton>`;
  `EnemyVfxInstaller._groundPoint` to `Transform on Spine_01` — **a zombie bone, the only reference into the skeleton itself**;
  `EnemyCoreInstaller._weaponRoot` to `Transform on <Weapons>`;
  `EnemyCoreInstaller._characterRoot` to `Transform on Zombie` (the root).
- Rapax body material `M_Rapax`: `_MainTex` is `T_Rapax_TintRed_BaseColor.png`, `_NormalTex` is `T_Rapax_Normal.png`, `_LightmapTex` is `T_Rapax_Occlusion.png`, `_EmissiveTex` is `T_Rapax_Green_Emissive.png`. Both shaders are the same asset with identical property names, so repointing is lossless.
- `Rapax_Red.prefab`: root `Rapax`, one `SkinnedMeshRenderer` on a child `SK_Rapax`, one material.
- `HitImpact_VFX_Zombie.prefab`: three ParticleSystems (`Wave`, `Particles`, `Glow`). Its two Shader Graphs target `UniversalTarget` and will not compile here, but both graphs are trivial — sample a texture, multiply by vertex colour — so built-in particle shaders reproduce them.
- `Blood7_02.prefab`: `BFX_Blood.shader` and `BFX_Decal.shader` are hand-written built-in-pipeline CG shaders. They work here unchanged.
- Both source VFX prefabs carry the source project's own `Entity` MonoBehaviour (script GUID `a6b8b812c65e45c6bb1ce2958d1943a5`, from `_Project/Scripts/Modules/Components/Entity.cs`). That is logic and must be stripped, not ported.
- `Zombie_Hand.prefab` holds `_animController` set to `AC_Zombie` (GUID `cb7def12ed591468ebdc46c5accc3cdb`). `AC_Zombie` declares `TakeDamage`, `Death`, `Attack` (triggers), `IsMoving` (bool), `MoveX`, `MoveZ` (floats) and has states `Idle`, `Idle (0)`, `Move (1)`, `Attack`, `TakeDamage`, `Death`.

### Task 4: Generate `Regax.prefab`

**Files:**

**Interfaces:**
- Consumes: `M_Rapax` and `SK_Rapax.fbx` (Task 1); `HitImpact_VFX_Zombie.prefab` and `Blood7_02.prefab` (Task 2); `Regax_Hand.prefab` (Task 3).
- Produces: `Assets/Game/Prefabs/Characters/Regax.prefab`, loaded by Task 5.

The builder starts from `Zombie.prefab`, so the whole Atomic layer — `MonoEntity` plus `EnemyCoreInstaller`, `EnemyAnimInstaller`, `EnemyVfxInstaller`, `EnemyAudioInstaller`, `CharacterBuffInstaller` and all their serialized tuning — carries over untouched. Only the visual subtrees are replaced, and only the references that pointed into them are rewritten. Keeping the `<Skeleton>`, `<Skin>`, `<Collider>`, `<Audio>`, `<Weapons>`, `<VFX>` and `<PatrolPoints>` GameObjects themselves, and replacing their contents, is what keeps the rest of the wiring valid.

- [ ] **Step 1: Write the builder**

A static class in `namespace Game.EditorTools` with `[MenuItem("Tools/Regax/Build Prefab")]`, doing, in order:

1. Load `Assets/Game/Prefabs/Characters/Zombie.prefab`, instantiate it with `PrefabUtility.InstantiatePrefab`, call `PrefabUtility.UnpackPrefabInstanceCompletely`, rename the root to `Regax`.
