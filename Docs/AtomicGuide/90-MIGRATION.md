# 90. Миграция на актуальную версию Atomic

## Что именно меняется

Проект сидит на пакете `com.starkre.unity-atomic-experimental` v3.0.0 (экспериментальная ветка, модули Context / Elements / Entities / Events / Extensions / Presenters). Актуальный апстрим — `com.starkre22.atomic` v3.0.0 (`https://github.com/StarKRE22/Atomic.git`, коммит `c5ca1b54` от 19.10.2026), модули Elements / Entities / Events / SourceGenerators.

Версии совпадают по номеру, но это разные пакеты. Три модуля удалены: **Context**, **Extensions**, **Presenters**. Кодогенерация переехала с редакторных yaml-вотчеров на Roslyn source generators.

Связанность проекта с удаляемым (по `using`):

| Модуль | Файлов | Статус |
|---|---|---|
| `Atomic.Entities` | 117 | остаётся, API изменён |
| `Atomic.Elements` | 69 | остаётся, API изменён |
| `Atomic.Contexts` | 25 | **модуль удалён** |
| `Atomic.Extensions` | 6 | **модуль удалён** |
| `Atomic.Presenters` | 3 | **модуль удалён** |

## Проверено вручную

Для каждого есть страница документации. Планировать работу на этих типах нельзя.

**3. Имена сгенерированных методов не меняются.** Новый генератор выдаёт `GetXxx` / `TryGetXxx` / `AddXxx` / `HasXxx` / `DelXxx` / `SetXxx` с теми же именами, что и старый. Поэтому ~184 `GetXxx`, 89 `AddXxx`, 89 `SetXxx` и 10 `HasXxxTag` вызовов компилируются без правок. Ломается только то, что `AddXxx` теперь возвращает `void` вместо `bool`, и исчезают `public const int` ключи.

## Удалённые модули и чем заменяются

### Context (whole module: C:/!!!Work/CodeCraft_HomeWork_ATOMIC/Assets/Plugins/Atomic/Context) — namespace Atomic.Contexts

**Замена.** Entity-as-context. A context becomes an IEntity-derived interface + a MonoEntity / MonoEntitySingleton component; IContextXxx lifecycle interfaces are replaced by per-domain interfaces generated by EntityDomainGenerator from [EntityDomainBehaviours(typeof(IYourContext))]; installers become MonoEntityInstaller<E> / IEntityInstaller<E>; the manual Update pump disappears (Atomic.Entities.TickableManager drives Tick/FixedTick/LateTick).

```csharp
// ---------- 1. the context TYPE ----------
// OLD  (Game/Scripts/Gameplay/PlayerContext/IPlayerContext.cs)
//   public interface IPlayerContext : IContext { }
//   public class PlayerContext : SceneContext, IPlayerContext { }
//   public class GameContext : SingletonSceneContext<GameContext>, IGameContext { }
// NEW
using Atomic.Entities;

namespace Game
{
    public interface IPlayerContext : IEntity { }
    public interface IGameContext  : IEntity { }

    // one marker class per context type -> EntityDomainGenerator emits the
    // lifecycle interfaces IPlayerContextBehaviour / Init / Enable / Disable /
    // Dispose / Tick / FixedTick / LateTick / Gizmos in THIS namespace.
    [EntityDomainBehaviours(typeof(IPlayerContext))]
    public static class PlayerContextDomain { }

    [EntityDomainBehaviours(typeof(IGameContext))]
    public static class GameContextDomain { }

    public sealed class PlayerContext : MonoEntity, IPlayerContext { }                      // was SceneContext
    public sealed class GameContext : MonoEntitySingleton<GameContext>, IGameContext { }    // was SingletonSceneContext<GameContext>
}

// ---------- 2. CONTROLLERS -> BEHAVIOURS ----------
// OLD (PlayerContext/Controllers/CharacterMoveController.cs)
//   public class CharacterMoveController : IContextInit<IPlayerContext>, IContextLateUpdate
//   { public void Init(IPlayerContext c){...} public void OnLateUpdate(IContext c, float dt) => Move(); }
// NEW — generated domain interfaces, strongly typed on both callbacks
public sealed class CharacterMoveBehaviour : IPlayerContextInit, IPlayerContextLateTick
{
    private Joystick _joystick;
    private IEntity _character;

    public void Init(IPlayerContext context)
    {
        _character = context.GetCharacter().Value;
        _joystick  = context.GetMoveJoystick();
    }

    public void LateTick(IPlayerContext context, float deltaTime) => this.Move();
}
// (IPlayerContextLateTick : IEntityLateTick<IPlayerContext>, IPlayerContextBehaviour)

// ---------- 3. INSTALLERS ----------
// OLD: public class GameContextInstaller : SceneContextInstaller<IGameContext>
//          { protected override void Install(IGameContext c) {...} }
// NEW: MonoEntityInstaller<E>  (Install is PUBLIC abstract, not protected)
public sealed class GameContextInstaller : MonoEntityInstaller<GameContext>
{
    [SerializeField] private WeaponCatalog _weaponsCatalog;
    [SerializeField] private PlayerContext _playerContext;
    [SerializeField] private MonoEntityWorld _entityWorld;      // was SceneEntityWorld
    [SerializeField] private MonoEntity _enemyPrefab;           // was SceneEntity
    [SerializeField] private Transform _spawnPoint;

    public override void Install(GameContext context)
    {
        context.AddEntityWorld(_entityWorld);
        context.AddWeaponCatalog(_weaponsCatalog);
        context.AddPlayerContext(_playerContext);

        // AddController(x)  ->  AddBehaviour(x)
        context.AddBehaviour(new EnemySpawnBehaviour(_enemyPrefab, _spawnPoint));

        // EntityFilter now takes IReadOnlyEntityCollection<E> + triggers
        context.AddEnemyFilter(new EntityFilter(
            _entityWorld,
            entity => entity.HasEnemyTag(),
            new TagEntityTrigger<IEntity>()));
    }

    public override void Uninstall(GameContext context) { /* new hook, optional */ }
}
// [Serializable] IContextInstaller<IPlayerContext> (e.g. CharacterSystemInstaller)
//   -> [Serializable] IEntityInstaller<IPlayerContext>, dropped into
//      MonoEntityInstallerConfigurable's [SerializeReference] IEntityInstaller[] _installers.
// context.AddController<CharacterMoveController>()
//   -> context.AddBehaviour<CharacterMoveBehaviour>()   // Extensions_Behaviours: T AddBehaviour<T>() where T : IEntityBehaviour, new()

// ---------- 4. THE RUNNER / ENTRYPOINT IS DELETED ----------
// OLD GameContext/EntryPoint.cs manually pumped:
//   Start(): _gameContext = GameContext.Instance; _gameContextInstaller.Install(_gameContext);
//            _gameContext.Init(); _gameContext.Enable();
//   Update(): _gameContext.OnUpdate(Time.deltaTime);  FixedUpdate/LateUpdate/OnDestroy likewise
// NEW: nothing. MonoEntity.Awake() -> Register()+Install() (installOnAwake, sceneInstallers list),
//      Start() -> Init()+Enable()+TickableManager.Instance.Register(this),
//      OnDisable() -> Disable()+Unregister, OnDestroy() -> Dispose().
//      The installer is referenced from the MonoEntity component's `sceneInstallers` list
//      (field carries [FormerlySerializedAs("installers")]).
//      SceneContextRunner / ContextRunner have no replacement and are not needed.

// ---------- 5. things with NO replacement ----------
// IContext.Parent / child-context tree, ResolveValue/TryResolveValue (parent-chain lookup)
//   -> plain composition: keep the child context as a value on the parent
//      (context.AddPlayerContext(_playerContext)) and read it explicitly.
// [ContextInject] + IContext.Construct()/Inject()/Instantiate() reflection DI
//   -> removed entirely. Read dependencies in Init(context).
// The Events module's IEventBus is the replacement only for the "put an IEvent on the
//   context so other systems can listen" pattern, not for context values.
```

### Extensions (C:/!!!Work/CodeCraft_HomeWork_ATOMIC/Assets/Plugins/Atomic/Extensions) — namespace Atomic.Extensions

**Замена.** Aspects were absorbed into Atomic.Entities (namespace move, same signatures). Entity action/predicate/function asset wrappers and the *_EntityInstaller family are gone — use Atomic.Elements InlineAction / InlinePredicate / InlineFunction, MonoAction*, ScriptableConst, and hand-written MonoEntityInstaller<E>. PlayerPrefs variables moved into Elements.

```csharp
// OLD: using Atomic.Extensions;  public class MoveSpeedAspect : ScriptableEntityAspect { ... }
// NEW: identical body, different namespace + optional typed variant
using Atomic.Entities;   // <- was Atomic.Extensions

[CreateAssetMenu(fileName = "MoveSpeedAspect", menuName = "BuffSystem/Aspect/MoveSpeedAspect")]
public sealed class MoveSpeedAspect : ScriptableEntityAspect        // or ScriptableEntityAspect<IEntity>
{
    [SerializeField] private float _multiplier;
    public override void Apply(IEntity entity)   { if (entity.TryGetMoveSpeed(out var s)) s.Value *= _multiplier; }
    public override void Discard(IEntity entity) { if (entity.TryGetMoveSpeed(out var s)) s.Value /= _multiplier; }
}
// .asset files keep working: ScriptableEntityAspect.cs.meta guid is unchanged
// (297444fb47114e1384b57625c6d7d4b7 in both trees).
//
// Atomic.Extensions.IEntityAspect              -> Atomic.Entities.IEntityAspect / IEntityAspect<E>
// EntityAspectComposite / ScriptableEntityAspectComposite / ScriptableEntityAspectDefault
//   -> no replacement; write a ScriptableEntityAspect that loops an IEntityAspect[] field.
// TagEntityAspect / ValueEntityAspect / BehaviourEntityAspect / ElementEntityAspect -> removed.
// IEntityAction / IEntityActionAsset* / IEntityPredicate* / IEntityFunctionAsset -> removed;
//   use Atomic.Elements.IAction<IEntity>, InlinePredicate<IEntity>, MonoActionConfigurable, etc.
// ReactiveInt_EntityInstaller, Timer_EntityInstaller, Event_EntityInstaller, ... (14 files)
//   -> removed; write the value into a MonoEntityInstaller<E>.Install().
// Atomic.Extensions.IntPrefsVariable/FloatPrefsVariable/StringPrefsVariable
//   -> Atomic.Elements.IntPrefsVariable/FloatPrefsVariable/StringPrefsVariable/BoolPrefsVariable
//      (Elements/Scripts/Variables/Proxy/PlayerPrefs/)
```

### Elements/Scripts/Reactive (IReactive, IReactive<T..>, BaseReactive, Subscription, Reactive extensions)

**Замена.** Elements/Scripts/Events: ISignal / ISignal<T..> (event-based) + Subscription structs + Extensions.Subscribe/Unsubscribe extension methods.

```csharp

//   public interface IReactive<out T> { void Subscribe(Action<T> a); void Unsubscribe(Action<T> a); }
//   variable.Subscribe(OnChanged);
// NEW: an event on the interface + extension methods that return a disposable
```

## Кодогенерация: yaml → source generators

OLD SYSTEM (two near-duplicate editor-time generators)
- C:/!!!Work/CodeCraft_HomeWork_ATOMIC/Assets/Plugins/Atomic/Entities/Editor/EntityAPI/{EntityAPIAsset,EntityAPIManager,EntityAPIController,EntityAPIGenerator,EntityAPITemplate,IEntityAPIConfiguration}.cs and the parallel Context/Editor/Core/ContextAPI* files.
- EntityAPIManager/ContextAPIManager run AssetDatabase.FindAssets("EntityAPI"|"ContextAPI"), keep every *.yaml/*.yml whose FIRST line matches `^header\s*:\s*(EntityAPI|ContextAPI)$`, and EntityAPIController/ContextAPIController re-run UpdateFile() from EditorApplication.update every 1.5 seconds.
- EntityAPIAsset is a hand-rolled line parser (not a YAML parser): it reads `namespace:`, `className:`, `directory:`, `entityType:`/`contextType:`, `aggressiveInlining:`, then `- item` lines under `imports:` / `tags:` / `values:`; value lines must match `^(\w+)\s*:\s*((?:\w+\.)*\w+)(\?|\*|(\[,*\])|(<[^<>]+>))?$`.
- EntityAPIGenerator.GenerateContent writes `{directory}/{className}.cs` as a NON-partial `public static class` containing `public const int {Name} = {EntityUtils.NameToId(name)};` per tag/value plus Has/Add/Del{Tag}Tag and Get/TryGet/Add/Has/Del/Set{Name} extension methods on the configured `entityType`. Project artifacts: Game/Scripts/Gameplay/CodeGen/{EntityAPI,GameContextAPI,PlayerContextAPI}.cs and Game/Scripts/Gameplay/Ability/AbilityAPI.cs — all four .cs files are checked in next to their .yaml.

NEW SYSTEM (three Roslyn incremental generators + two analyzers, prebuilt DLLs)
- EntityAPIGenerator (Assets/Plugins/Atomic/SourceGenerators/EntityAPIGenerator.dll, source under Project~/EntityAPIGenerator): CreateSyntaxProvider finds classes attributed [EntityExtensionsAPI]; EntityAPIParser.Transform reads every STATIC single-variable field whose type is in namespace Atomic.Entities and is named TagKey (0 or 1 type args) or ValueKey (1 or 2 type args); CodeEmitter.Emit writes `{ClassName}.g.cs` as `public static partial class {ClassName}` in the same namespace.
- There is NO ContextAPI generator. A context is just an entity type, so a ContextAPI yaml becomes an [EntityExtensionsAPI] class whose keys are ValueKey<IYourContext, T>.
- EntityDomainGenerator (EntityDomainGenerator.dll) reads [EntityDomainBehaviours(typeof(TEntity))] and emits the nine lifecycle interfaces. There was no yaml equivalent — the old `entityType:`/`contextType:` field only chose the `this` parameter of the extension methods; the new attribute additionally generates the behaviour interfaces.
- EventAPIGenerator (EventAPIGenerator.dll) is the same machinery for [EventExtensionsAPI] + EventKey<TBus,...> fields.
- Generation happens at COMPILE time, in memory. EntityAPIGenerator.ShouldRun() bails out when Assembly.GetEntryAssembly() == null (i.e. IDE background analysis) and when the compilation is Atomic.Entities itself or does not reference it. So the generated code is NOT a file you can open or commit; define ATOMIC_OUTPUT_SOURCEGEN_FILES to dump it to Temp/GeneratedCode/.

FIELD-BY-FIELD MAPPING OF THE YAML
  header: EntityAPI | ContextAPI   -> [EntityExtensionsAPI] attribute on the class
  namespace: Game                  -> the enclosing C# `namespace Game { }`
  className: EntityAPI             -> the class name; MUST now be `public static partial class`
  directory: Assets/Game/...       -> gone; the file lives wherever you put the source file
  entityType: IEntity              -> the FIRST generic argument of each key (TagKey<IEntity>, ValueKey<IEntity,T>)
  contextType: IPlayerContext      -> same: ValueKey<IPlayerContext, T>
  aggressiveInlining: true         -> [EntityExtensionsAPI(AggressiveInlining = true)] (default true)
  imports: - UnityEngine ...       -> ordinary `using` directives in the source file
  tags: - Player                   -> public static readonly TagKey<IEntity> Player = new(nameof(Player));
  values: - Health: int            -> public static readonly ValueKey<IEntity, int> Health = new(nameof(Health));
  (no yaml equivalent)             -> [Unsafe] on a field, or [EntityExtensionsAPI(Unsafe = true)] on the class,
                                      to emit GetValueUnsafe<T>/RefXxx() instead of GetValue<T>

## Риски (12)

### Риск 1

The vendored upstream snapshot is INCOMPLETE relative to its own documentation. Docs reference types that have no implementation file in C:/!!!Work/_AtomicUpstream/Assets/Plugins/Atomic: `EntitySingleton<E>` (Docs/Entities/Entities/EntitySingleton.md, with SetFactory/DisposeInstance/ResetInstance), `InlineEntityFactory` (Docs/Entities/Factories/InlineEntityFactory.md), and `MultiEntityFactory` (test files MultiEntityFactoryTests.cs / MultiEntityFactoryStub.cs exist but no production class). Any migration plan that leans on those will not compile. Re-clone https://github.com/StarKRE22/Atomic.git at a known tag and diff against this snapshot before committing to it.

### Риск 2

Entity key IDs are no longer stable. The old EntityUtils/ContextUtils used `new PropertyName(name).GetHashCode()`, which is deterministic across runs — that is why the generated files contain literals like `public const int Damageable = 563499515;`. The new default IEntityKeyAlgorithm is SequentialEntityKeyAlgorithm: ids are 1,2,3... in first-use order and EntityKeyStore resets on entering play mode. Anything that persisted a raw int key (save files, ScriptableObject fields typed `int` holding a key, analytics, network payloads) is now wrong. Audit for stored ints before migrating; if you need stability, call EntityKeyStore.SetAlgorithm with a hash-based algorithm at startup (the Events module ships Fnv1A/SHA256 equivalents; Entities ships only Sequential, so you may have to write one).

### Риск 3

Generator setup is silent-fail. EntityAPIGenerator.ShouldRun() returns false whenever Assembly.GetEntryAssembly() == null, which is exactly IDE background analysis — so Rider/VS will show every GetXxx/AddXxx as unresolved even when the build is fine, and conversely a missing `RoslynAnalyzer` asset label or a checked platform box produces zero generated code with no error pointing at the cause. Verify via Temp/GeneratedCode/ (ATOMIC_OUTPUT_SOURCEGEN_FILES) rather than IntelliSense.

### Риск 4

The generated API is no longer a file in the repo. The old workflow produced reviewable, diffable .cs files next to the yaml; the new one generates in memory on every compile. Loss of that artifact means (a) no git history for API changes, (b) CI/build machines must have the analyzer DLLs correctly labelled or the whole project fails to compile, and (c) debugging stepping into generated extensions depends on the generator emitting source. Plan for the DLLs being binary blobs you cannot rebuild without the Project~ sources and .NET SDK 8+.

### Риск 5

Serialized-reference breakage is partial, which is the dangerous kind. Component/asset GUIDs were deliberately preserved for the renames the project actually uses (MonoEntity, MonoEntityInstaller, MonoEntityWorld, MonoEntityProxy, ScriptableEntityAspect, Event, Variable, ReactiveVariable), but EntityView (89cddd8c->244330ad), EntityViewCatalog (8e594ac9->7eb7f35b), EntityFilter (ac8506fb->9fb7c7e5) and SceneAction->MonoAction (1ba5fb5e->aea0ba47) all got new GUIDs. Separately, [SerializeReference] payloads store the full type NAME, so every renamed plain class behind a [SerializeReference] field (BaseEvent->Event, BaseVariable->Variable, BaseFunction->..., any IContextInstaller[] arrays) will deserialize as null even though the defining file's GUID is unchanged. Open and re-save every scene and prefab, and diff the YAML.

### Риск 6

`Cooldown` name collision. The project has its own Modules.Cooldown (Assets/Modules/Cooldown/Cooldown.cs) and the EntityAPI.yaml declares `LifeTime: Cooldown` and `WeaponCooldown: Cooldown`. Atomic.Elements now also defines Cooldown/ICooldown/RandomCooldown/ThreadSafeCooldown. Any file with both `using Atomic.Elements;` and `using Modules;` becomes ambiguous. Qualify or alias explicitly in the new EntityAPI.cs and at every call site.

### Риск 7

Lifecycle inversion is a behavioural, not compile-time, change. Today EntryPoint.cs deterministically orders Install -> Init -> Enable and pumps Update/FixedUpdate/LateUpdate for the whole context. After migration, MonoEntity.Awake does Register+Install, Start does Init+Enable+TickableManager.Register, and tick ORDER becomes registration order inside TickableManager with no priority control (EntityUpdatePriority/PriorityEntitySystem only order systems, not entities). Anything that relied on GameContext initialising strictly before PlayerContext, or on LateUpdate running after a specific MonoBehaviour, can break silently. Use DefaultExecutionOrder, ScriptableEntityBootstrapper, or explicit useUnityLifecycle=false + manual driving for the few places order matters.

### Риск 8

IEntityWorld lost Init()/Dispose() propagation and Initialized. The old world initialised and disposed its entities; EntityWorld<E> only has Enable/Disable/Tick and enables entities on add when the world is enabled. Code that assumed adding an entity to the world initialised it will now add an uninitialised entity. Each entity must be Init()-ed by its own MonoEntity.Start() or explicitly.

### Риск 9

Factories now require an IArgs type parameter everywhere (IEntityFactory<TEntity,TArgs>). This is pure ceremony for the common case (NoArgs.Default) but it changes every factory signature, and ScriptableEntityFactory's editor-time Compile() calls `this.Create(default)` — if your Create implementation dereferences args it will throw in the editor on OnValidate.

### Риск 10

Value-type keys lose the old boxing-avoidance story and gain new footguns. `ref T GetValueUnsafe<T>(int) where T : class` is class-only, so [Unsafe]/RefXxx cannot be applied to the yaml entries typed `float`, `LayerMask`, `Vector3` (JumpForce, DamageLayer, PositionOffset). Values are still stored as `object` in an int->object map, so struct values still box; the win comes from avoiding the dictionary re-lookup, not the boxing. Do not promise a perf gain you cannot get for those keys.

### Риск 11

Scope and volume. 77 IContext occurrences, 54 SceneEntity, 27 installer subclasses, 26 context-lifecycle implementations, 20 BaseEvent files, plus four API definitions — this is a single atomic (no pun) cut-over: the project will not compile at all between step 2 and step 12, so there is no incremental-verification path and no way to run the existing tests mid-migration. The old module also shipped its own test suites (Context/Tests, Entities/Tests, Elements/Tests) which are replaced wholesale by the upstream ones, so your safety net changes under you at the same moment. Branch, budget for a long red build, and consider doing steps 4-6 (codegen + context->entity) on a throwaway copy first to validate the generator pipeline before touching the real tree.

### Риск 12

The new asmdef sets allowUnsafeCode: true for Atomic.Entities (old was false). If the project has IL2CPP/AOT or managed-stripping settings tuned around no-unsafe assemblies, or a CI policy against unsafe code, that needs sign-off.
