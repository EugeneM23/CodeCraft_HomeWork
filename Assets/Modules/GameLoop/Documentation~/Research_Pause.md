# Исследование: честная пауза и игровой цикл

Задача пользователя (24.10.2026): игровой цикл с паузой **без `Time.timeScale`**, пауза должна быть **честной**;
собрать лучшие практики, написать документацию и сделать гибкий, простой и понятный инструмент.
Решения по итогам — в [GameLoop.md](GameLoop.md).

## 1. Что такое «честная» пауза

**Честная пауза** — мир игры не продвигается ни на шаг: логика не тикает, физика не шагает, анимации, частицы, звук,
камера и таймеры стоят. Снятие паузы продолжает всё с того же места, как будто паузы не было: та же скорость тела,
тот же кадр анимации, та же фаза тряски камеры, тот же остаток кулдауна. Меню при этом живёт своей жизнью.

**Нечестная пауза** — `Time.timeScale = 0`. Игровое время обнуляется, но мир не выключен: Unity продолжает звать
`Update`, ввод читается, код, который двигает без `deltaTime`, двигает, звук играет, а всё, что идёт по
`unscaled`-времени, идёт. Пауза держится на том, что *каждый* скрипт сам правильно пользуется временем.

## 2. Что на самом деле делает `Time.timeScale = 0`

| Останавливает | Не останавливает |
|---|---|
| `Time.deltaTime` = 0 → движение, умноженное на него | Вызовы `Update` и `LateUpdate` — код в них работает |
| `FixedUpdate` и шаг физики | Ввод: нажатие в паузе срабатывает в `Update` или после снятия |
| `Time.time` | Движение без `deltaTime`, мгновенные действия по кнопке |
| `Animator` в режиме Normal, частицы на scaled-времени | Звук и `AudioSettings.dspTime` (нужен `AudioListener.pause`) |
| `WaitForSeconds`, `Invoke` | `WaitForSecondsRealtime`, `unscaledDeltaTime`, твины с `ignoreTimeScale` |
| | Шейдеры на собственном времени, видео |

Плюс `timeScale` — **один глобальный рычаг на всю игру**: им же делают замедление (slow-mo) и хит-стоп, и две системы,
трогающие его, перетирают друг друга; после загрузки сцены он сам не сбрасывается.

Источники: [GameDev Beginner — The right way to pause](https://gamedevbeginner.com/the-right-way-to-pause-the-game-in-unity/),
[uhiyama-lab — Implementing Pause Correctly](https://uhiyama-lab.com/en/notes/unity/unity-pause-implementation-guide/),
[Game Developer — Pausing and time management in Unity](https://www.gamedeveloper.com/programming/pausing-and-time-management-in-unity),
[форум Unity — Pause using Timescale=0](https://discussions.unity.com/t/pause-using-timescale-0/729343).

## 3. Как это делают

### 3.1. Unity-сообщество

- **`timeScale` + исключения.** Самый частый совет: пауза — `timeScale = 0`, меню — на `unscaledDeltaTime`,
  `Animator.updateMode = UnscaledTime`, `ParticleSystem.main.useUnscaledTime`, звук — `AudioListener.pause`, а для
  звуков меню `AudioSource.ignoreListenerPause`. Работает, пока каждый скрипт дисциплинирован; ввод и `Update` идут.
- **Глобальный флаг.** Статический `IsPaused`, который геймплейные скрипты проверяют в начале `Update`. Просто, но
  проверка размазана по всему коду, забытая проверка — дыра.
- **Выключение компонентов** (`enabled = false`, `animator.speed = 0`). Честно останавливает `Update`, но дёргает
  `OnDisable`/`OnEnable` со всеми побочными эффектами (отписки, сброс ввода, перезапуск клипа при включении).
  `Rigidbody2D.simulated = false` выкидывает тело из мира — контакты рвутся, приходят `OnCollisionExit`.
- **Свой update manager.** Один объект получает `Update` от Unity и сам раздаёт его подписчикам через интерфейс;
  это прямо советует [руководство Unity 6.5](https://docs.unity.com/en-us/engine/6000.5/manual/scripting/managing-update-order/events-per-frame-optimization.md)
  (там же — почему: вызов native → managed на каждый `Update` дорог, см.
  [10000 Update() calls](https://unity.com/blog/engine-platform/10000-update-calls)). Пауза тогда — менеджер просто не
  раздаёт тики. Это основа «честной» паузы в Unity.
- **Свой Player Loop** ([PlayerLoop API](https://docs.unity3d.com/6000.0/Documentation/Manual/player-loop-customizing.html)):
  вставить свою систему в цикл движка. Мощно, но низкоуровнево, и `Update` у `MonoBehaviour` всё равно зовёт сам
  Unity — пауза всё равно требует, чтобы игровой код жил не в `Update`.
- **Часы и слои времени** (ассет Chronos: глобальные и локальные часы, у каждого объекта своя шкала времени —
  [обзор](https://github.com/CyberSys/ChronosTimeControl)). Гибко (замедлить только врагов), но тяжело: каждую
  подсистему — анимацию, частицы, навигацию, звук — приходится подключать к часам.

### 3.2. Godot

`SceneTree.paused = true` — пауза на уровне движка. У каждого узла `process_mode`: `Inherit` (как у родителя),
`Pausable` (стоит в паузе), `WhenPaused` (работает только в паузе — меню), `Always`, `Disabled`. Не тикающему узлу не
приходят `_process`, `_physics_process` и ввод; анимации, звук и частицы сами встают и продолжают; **физика стоит
целиком**. Сигналы при этом доходят. Режим наследуется по дереву — меню паузы одной настройкой на корне.
([Godot docs — Pausing games](https://docs.godotengine.org/en/stable/tutorials/scripting/pausing_games.html))

### 3.3. Unreal

`SetGamePaused` останавливает мир: тики акторов и компонентов не идут, если у них не стоит `bTickEvenWhenPaused`
(`SetTickableWhenPaused`). Пауза — флаг мира, исключения — явная настройка объекта.
([UE API — bTickEvenWhenPaused](https://docs.unrealengine.com/4.26/en-US/API/Runtime/Engine/Engine/FTickFunction/bTickEvenWhenPaused/index.html))

### 3.4. Game Programming Patterns (Nystrom)

[Update Method](https://gameprogrammingpatterns.com/update-method.html): цикл раздаёт `update(dt)` объектам. Важные
решения: кто владеет циклом; **добавление и удаление во время обхода** (новые — со следующего прохода, удалённые —
пометить и вымести после); неактивные объекты не тикают; порядок обхода определяет, кто видит чьё новое состояние.

### 3.5. Хит-стоп и замедление

Хит-стоп — та же пауза на 50–100 мс; обычно её делают глобальным `timeScale` и таймером на реальном времени, и
обычные советы — не морозить UI и звук ([bugnet — hitstop](https://bugnet.io/blog/how-to-fix-hitstop-or-freeze-frame-feeling-off),
[wayline — game feel](https://www.wayline.io/learn/game-feel/1)). Значит, пауза должна уметь несколько независимых
«держателей», а таймер, снимающий паузу, — идти по реальному времени.

## 4. Подводные камни и как их закрыть

| Камень | Решение |
|---|---|
| Кнопка, закрывшая меню, прыгает в игре | Карта ввода `Player` выключена на время паузы (уже так), а тики контроллера не идут |
| Физика: без `timeScale` она шагает | `Physics2D.simulationMode = Script` на время паузы — мир стоит целиком, контакты и скорости целы; `simulated = false` не годится |
| `simulationMode`, изменённый в Play Mode, остаётся в Project Settings | Вернуть прежний режим при снятии паузы и при уничтожении цикла |
| `Animator`, legacy `Animation`, `ParticleSystem`, свой `SpriteAnimator` идут сами | «Морозилки»: на паузе остановить, на снятии вернуть; пропускать те, что на unscaled-времени (это меню) |
| Звук | Движок звука — `Pause`/`Resume`; без него — `AudioListener.pause` (+ `ignoreListenerPause` у звуков меню) |
| Корутины, `WaitForSeconds`, `Invoke`, DOTween | В игровом коде не использовать; таймеры — полями, тикают от цикла |
| Камера: демпфирование и тряска (Cinemachine) идут по своему времени | `CinemachineCore.UniformDeltaTimeOverride = 0` в паузе, `CurrentTimeOverride` — игровое время цикла |
| Несколько причин паузы (меню, потеря фокуса, загрузка, хит-стоп) | Пауза — набор держателей: каждый ставит и снимает свою, игра идёт, когда держателей нет |
| Пауза пережила объект, который её поставил | Уничтоженный держатель отпускает паузу сам |
| Добавление/удаление слушателей во время тика (спавн, смерть, пул) | Новые — со следующего прохода, удалённые — сразу перестают тикать |
| Исключение в одном объекте рвёт цикл | Ловить на каждом слушателе и логировать, как Unity |
| Порядок обновления (мотор раньше механик) | Порядок — `[DefaultExecutionOrder]` класса, как у Unity |
| Время игры и автосейв | Считать по игровому времени цикла |
| Шейдеры на `_Time` | Идут и в паузе; игровым шейдерам с анимацией — своё глобальное время (у нас таких нет) |

## 5. Вывод для проекта

1. **Свой игровой цикл** вместо `Update`/`FixedUpdate`/`LateUpdate` у игрового кода: компоненты подписываются
   интерфейсами, цикл раздаёт тики с `dt`. Пауза — цикл не раздаёт тики. Это решает `Update`, ввод, таймеры,
   корутины-по-времени разом и **честно**.
2. **`Time.timeScale` не трогаем** — он остаётся 1 (и свободен для замедления, если понадобится).
3. **Всё, что Unity двигает сама**, морозят маленькие слушатели паузы («морозилки»): физика, Animator, legacy
   Animation, частицы, `SpriteAnimator`, звук, Cinemachine. Новая такая подсистема — новая морозилка.
4. **Пауза — с держателями** (меню, загрузка, потеря фокуса…), уничтоженный держатель отпускает сам.
5. **UI и сервисы** живут на обычном `Update` и `unscaledDeltaTime` — им пауза не нужна (как `WhenPaused`/`Always`
   в Godot: всё, что не в цикле, работает всегда).
6. **Тесты**: тестовый стенд шагает тот же цикл, что и игра, — без рефлексии и с проверкой паузы.
