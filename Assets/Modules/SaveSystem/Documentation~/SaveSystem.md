# SaveSystem — плагин сохранений

**Статус:** плагин готов (части 1–3) 2026-10-24. Часть 4 — простой путь (префаб «кинул и работает», режимы
компонентов All Fields / Selected, значения и объекты из обычного кода, управление слотами, меню слотов, хранилища
под любые БД и серверы, сжатие и шифрование) — [SaveSystem_Part4.md](SaveSystem_Part4.md). Исследование (практики, платформеры, Easy Save 3)
— [Research_SaveSystems.md](Research_SaveSystems.md). Код домашки как есть — `_Import/HomeWork06_SaveSystem/`
(ветка `HomeWrok_06_SaveSystem` репозитория `CodeCraft_HomeWork`, коммит `c614fda5`), его разбор — приложение A.
Пошаговый план реализации — [SaveSystem_Plan.md](SaveSystem_Plan.md), пишется после согласования этого документа.

Общий модульный плагин сохранений для наших проектов: один компонент для простого пути, полное состояние
объектов (физика, анимация, частицы, поля своих скриптов, заспавненные и уничтоженные объекты), надёжное
хранилище со слотами и версиями. Устройство и имена — из домашки (сериализатор на ключ, каталог сериализаторов,
набор сериализаторов объекта), код переписывается без Zenject, Odin и UniTask.

## 1. Цель и критерий готовности

**Плагин готов, когда:**

- в демо-сцене `Sandbox_SaveSystem.unity` после «сохранить → всё поменять → загрузить» восстановлено всё:
  - позиции и скорости тел `Rigidbody2D` и `Rigidbody`, включая уснувшие;
  - состояние `Animator` (состояние слоя, время в нём, параметры);
  - время и воспроизведение `ParticleSystem`, а с флажком — и живые частицы;
  - поля `[Save]` своего скрипта, включая ссылки на другие объекты и ассеты;
  - заспавненный в игре префаб снова на месте, уничтоженный объект сцены снова уничтожен;
- в игре `[Services]` держит систему сохранений, F5 сохраняет, F9 загружает (в эдиторе и development-сборке),
  игрок восстанавливается с позицией, скоростью и анимацией;
- испорченный `save.json` — загрузка с `save.json.bak` и предупреждение; испорчены оба — новая игра, файлы
  переименованы в `.corrupt`; файл от более новой версии игры не загружается и не перезаписывается;
- все тесты зелёные.

**Работа идёт тремя частями.** Каждая заканчивается зелёными тестами и рабочей игрой:

1. **Ядро** (`SaveSystem`): слоты, запись, версии и миграции, сервис, глобальные системы через
   `GameSerializer<TService, TData>`, компонент `SaveLoadSystem`, подключение к `GameServices`, F5/F9.
2. **Объекты** (`SaveSystem.Objects`): `Saveable`, скрытый реестр, ID, каталог сериализаторов компонентов, поля
   `[Save]`, секции сцен, уничтоженные и заспавненные, загрузка перезагрузкой сцены; Transform и включённость.
3. **Unity-типы и ссылки**: Rigidbody2D и Rigidbody, Animator, ParticleSystem, AudioSource, SpriteRenderer;
   ссылки на объекты, префабы и ассеты; демо-сцена; `Saveable` на игроке.

## 2. Решения

| Тема | Решение |
|---|---|
| Назначение | Общий плагин для наших проектов (не для Asset Store): переносимый модуль с README и тестами; 2D и 3D — насколько код общий |
| Простой путь | Один компонент `Saveable`: ID и список компонентов объекта и его детей с флажками; по умолчанию отмечено всё, что умеет сохраняться |
| Поля своих скриптов | Только помеченные `[Save]`. Настройки из Inspector не сохраняются — тюнинг чисел в обновлении не перетирается старыми сейвами |
| Особые случаи | `ComponentSerializer<TComponent, TData>` для компонента, `GameSerializer<TService, TData>` для глобальной системы; плагин находит их сам |
| Коллекции | Никаких объектов-реестров в сцене: `Saveable` регистрируется сам, реестр спрятан в плагине; каталоги префабов, ассетов и сцен эдитор собирает сам |
| Загрузка | Перезагрузка сохранённой сцены и применение данных к ней |
| Ссылки | На `Saveable`, их компоненты и детей, на префабы и на ассеты из выбранных в настройках папок (по GUID) |
| Частицы | Воспроизведение (играет, пауза, стоп, время, зерно); живые частицы — флажок |
| Слоты | Папка `Saves/slot_N/`: `save.json`, `meta.json`, `save.json.bak` |
| Формат | Читаемый JSON без шифрования; конверт с `formatVersion`, у секций — своя версия `v`; миграции N→N+1 |
| Запись | Временный файл → `File.Replace` с `.bak`; откат на `.bak`; испорченное → `.corrupt` |
| Когда сохранять | Настраивается на `SaveLoadSystem`: выход, пауза приложения и потеря фокуса, таймер по игровому времени (только при изменениях), вызов из кода. Чекпоинты — дело игры |
| Отладка | F5/F9 — в игре (только эдитор и dev-сборки); меню плагина *Tools → Save System* |
| Ветка | `feature/save-system` от актуальной ветки (сейчас `feature/enemy-ai`) в основной рабочей копии: Unity и MCP привязаны к ней, отдельный worktree потребовал бы второго эдитора с полным импортом. Старт — когда работа над врагами в этой папке закончена |
| Домашка | Берём устройство и имена; `_Import` удаляем после переноса |

## 3. Устройство

```
код игры ──► ISaveLoadService  (SaveLoadSystem на [Services]: настройки, триггеры сохранения)
                  │
          SaveLoadService ──► ISaveStorage (FileSaveStorage: Saves/slot_N/…)
             │         │
             │         └── глобальные секции ◄── GameSerializer<TService, TData>  (инвентарь, квесты…)
             │
             └── секции сцен ◄── состояние сцены (внутри плагина) ◄── скрытый реестр ◄── Saveable
                                                                                           │
                          каталог сериализаторов компонентов ◄─────────────────────────────┘
                          (Transform, Rigidbody2D, Animator, ParticleSystem…, поля [Save], свои)
```

## 4. Сборки и размещение

```
Assets/Game/Scripts/Modules/SaveSystem/                 — package.json, README.md
├── Runtime/Core/      (сборка SaveSystem,          namespace Saving)          — ссылка: Newtonsoft.Json
├── Runtime/Objects/   (сборка SaveSystem.Objects,  namespace Saving.Objects)  — ссылка: SaveSystem
├── Editor/            (сборка SaveSystem.Editor)                               — обе рантайм-сборки
└── Tests/Editor (SaveSystem.Tests), Tests/Runtime (SaveSystem.Tests.Runtime, тестовые сцены)
```

- Ядро не знает об объектах сцены: годится и для чисто глобальных данных (профиль, прогресс).
- Сериализаторы Unity-типов компилируются, только если в проекте включён нужный модуль движка
  (`versionDefines` на `com.unity.modules.physics`, `physics2d`, `particlesystem`, `animation`, `audio`) —
  плагин собирается и в проекте без 3D-физики.
- `Packages/manifest.json` — `com.unity.nuget.newtonsoft-json` 3.2.2 явно (сейчас пакет приходит транзитивно,
  резолвер уже выбрал 3.2.2).
- Плагин не зависит от `Game` и от `ServiceLocator`; в сервисы его регистрирует `GameServices`.
- Odin и `[Min]` не используем; ограничения — в `OnValidate`.

## 5. Ядро — `SaveSystem`

### 5.1. Формат на диске

```
<persistentDataPath>/Saves/
└── slot_0/
    ├── save.json                 — данные слота
    ├── save.json.bak             — предыдущая запись (со второй записи)
    ├── meta.json                 — для меню слотов
    ├── save.premigration.json    — копия до первой миграции формата (если была)
    └── *.corrupt                 — испорченные файлы, если были
```

`save.json` — конверт с секциями. Ключи плагина начинаются с `$` (свои ключи с `$` начинать нельзя), секция
сцены — `scene/<GUID сцены>`:

```json
{
  "formatVersion": 1,
  "gameVersion": "1.0",
  "sections": {
    "$scenes": { "v": 1, "data": { "active": { "path": "Assets/Game/Scenes/Game.unity", "guid": "3f9a…" } } },
    "inventory": { "v": 2, "data": { "items": [ "sword", "potion" ] } },
    "scene/3f9a…": {
      "v": 1,
      "data": {
        "objects": {
          "b4e1…": {
            "active": true,
            "components": {
              "Transform": { "v": 1, "data": { "localPosition": { "x": 3.5, "y": 1.0, "z": 0.0 } } },
              "Rigidbody2D": { "v": 1, "data": { "linearVelocity": { "x": 2.0, "y": -4.1 }, "isAwake": true } },
              "Health": { "v": 1, "data": { "_current": 7 } },
              "Visual/SpriteRenderer": { "v": 1, "data": { "sprite": { "asset": "9c1d…" }, "flipX": true } }
            }
          }
        },
        "destroyed": [ "c7d2…" ],
        "spawned": [
          { "id": "e8f3…", "prefab": "a0b9…", "parent": null, "active": true, "components": { } }
        ]
      }
    }
  }
}
```

`meta.json`:

```json
{
  "formatVersion": 1,
  "gameVersion": "1.0",
  "savedAtUtc": "2026-10-23T14:05:00Z",
  "playTimeSeconds": 1834.2,
  "summary": { "level": "Game" }
}
```

**Правила формата:**

- `formatVersion` — версия устройства конверта, `v` — версия данных секции. Файл и секции новее текущих не
  читаются (раздел 10).
- Секции без зарегистрированного сериализатора (другие сцены, выключенные системы) сохраняются как есть и
  пишутся обратно.
- JSON с отступами; имена членов — camelCase, ключи словарей — как есть.
- Newtonsoft: `ObjectCreationHandling.Replace`, `TypeNameHandling.None`; в данных нет полных имён типов сборок.
- Конвертеры Unity-структур: `Vector2/3/4`, `Vector2Int/3Int`, `Quaternion`, `Color`, `Color32`, `Rect`, `Bounds`
  (иначе Newtonsoft зацикливается на `Vector3.normalized`).

### 5.2. Глобальные сериализаторы

Интерфейс из домашки, расширенный версией и порядком:

```csharp
public interface IGameSerializer
{
    string Key { get; }                           // section key, unique among registered serializers
    int Version { get; }                          // current data version, starts at 1
    int Order { get; }                            // restore order, lower first
    JToken Capture();
    JToken Upgrade(JToken data, int fromVersion); // one step: fromVersion -> fromVersion + 1
    void Restore(JToken data);                    // data is already at Version
}
```

`GameSerializer<TService, TData>` — как в домашке, только сервис приходит в конструкторе, а не через `[Inject]`:

```csharp
public sealed class InventorySerializer : GameSerializer<Inventory, InventoryData>
{
    public InventorySerializer(Inventory inventory) : base(inventory, key: "inventory", version: 2) { }

    protected override InventoryData Serialize(Inventory inventory) => new(inventory.ItemIds);
    protected override void Deserialize(Inventory inventory, InventoryData data) => inventory.Set(data.Items);

    protected override JToken Upgrade(JToken data, int fromVersion) => fromVersion switch
    {
        1 => InventoryMigrations.RenameField(data, "ids", "items"),
        _ => base.Upgrade(data, fromVersion)
    };
}
```

`SerializerGroup` — общий цикл для глобальных секций и для компонентов объекта (вместо дубля
`SaveLoadProvider`/`SaveLoadService` из домашки): проверить версии, смигрировать копию данных по шагам, применить
по возрастанию `Order`; исключение одного не останавливает остальных.

### 5.3. `SaveLoadService` — ядро на чистом C#

```csharp
public interface ISaveLoadService
{
    int CurrentSlot { get; }
    bool IsLoading { get; }
    bool IsReadOnly { get; }                     // slot from a newer game or failed migration: never overwritten
    double PlayTime { get; }
    IDictionary<string, string> Summary { get; } // written to meta.json

    event Action<SaveOutcome> Saved;
    event Action<LoadOutcome> Loaded;            // after the scenes are restored too

    void Register(IGameSerializer serializer);   // applies its section from the snapshot right away, if present
    void Unregister(IGameSerializer serializer); // does not capture
    void Capture();                              // registered serializers -> snapshot, no disk write
    SaveOutcome Save(bool onlyIfChanged = false);
    LoadOutcome Load();                          // current slot: disk -> snapshot -> registered serializers
    void SelectSlot(int slot, bool keepData = false); // clears the snapshot unless keepData ("save as")
    IReadOnlyList<SlotInfo> GetSlots();          // reads meta.json only
    void DeleteSlot(int slot);
}
```

- **Снимок.** Сервис держит в памяти секции текущего слота. `Save` обновляет секции зарегистрированных
  сериализаторов и не трогает остальные — данные других сцен не стираются.
- **Регистрация применяет данные сразу:** система, появившаяся после чтения слота, получает свою секцию в момент
  регистрации. Повторный ключ — `ArgumentException`.
- **`Save(onlyIfChanged: true)`** не пишет, если новый текст `save.json` совпал с последним записанным или
  прочитанным (`Unchanged`); для пустого слота точка сравнения — пустой конверт, так что пустой снимок на диск не
  попадает. Обычный `Save()` пишет всегда.
- **Порядок записи:** `save.json`, затем `meta.json`, каждый атомарно. Обрыв между ними оставит старый `meta.json`
  при новом `save.json` — безвредно.
- **Загрузка — сначала проверка, потом применение:** разобрать конверт → проверить версии формата и секций, наличие
  сохранённой сцены (в сборке — в Build Settings; в эдиторе — любая сцена проекта, она грузится через
  `EditorSceneManager.LoadSceneInPlayMode`) → смигрировать копии → только если всё прошло, заменить снимок,
  применить глобальные секции по `Order`, перезагрузить сцену (раздел 6.5). Время игры и `Summary` — из `meta.json`.
- **Блокировка.** Во время загрузки `Save` возвращает `Blocked`; в слот «только для чтения» сохранение не пишет;
  «только для чтения» снимается выбором слота.
- **Слоты.** `SelectSlot(slot)` начинает слот заново (снимок, время игры и `Summary` очищаются, прежний слот не
  сохраняется); `SelectSlot(slot, keepData: true)` оставляет снимок — «сохранить как» в другой слот.
- `SaveOutcome`: `Saved`, `Unchanged`, `Blocked`, `Failed`. `LoadOutcome`: `Loaded`, `Recovered`, `Empty`,
  `Corrupted`, `NewerVersion`, `MigrationFailed`, `Failed` (хранилище бросило исключение при чтении),
  `SceneNotFound` (сохранённой сцены нет в сборке).

### 5.4. Хранилище

`ISaveStorage` — в духе Unity Platform Toolkit, чтобы позже подключить Steam или консоли адаптером: перечислить
слоты, прочитать файл слота или его резервную копию, атомарно записать файл с сохранением прежней версии в `.bak`,
переименовать испорченный файл в `.corrupt`, удалить слот. Граница — текст файла; точные сигнатуры — в плане.

- `FileSaveStorage(root)` — `root/slot_N/`. Запись: `<file>.tmp` в той же папке → `Flush(true)` →
  `File.Replace(tmp, file, file.bak)`; первая запись — `File.Move`. Ошибка ввода-вывода выходит наружу как
  `IOException`, файл на диске цел.
- `InMemorySaveStorage` — словарь с той же семантикой `.bak`, для тестов.

### 5.5. `SaveLoadSystem` — компонент на `[Services]`

- Поля: ассет настроек `SaveSystemSettings` (раздел 6.6), папка (`Saves`), слот при старте (`0`), загрузить при
  старте (по умолчанию нет; у нас — да), сохранять при выходе (да), при паузе приложения и потере фокуса (да),
  период автосейва (`30` с, `0` — выключен; в `OnValidate` 0 или не меньше 5).
- `[DefaultExecutionOrder(-9000)]`: после `GameServices` (−10000), до объектов сцены.
- Сервис запускается при первом обращении: создаёт `FileSaveStorage(persistentDataPath/<папка>)` и выбирает
  стартовый слот. До этого тест может подменить хранилище (`UseStorage`) и настройки (`Configure`); после — оба
  бросают `InvalidOperationException`. Загрузка при старте — в `Start`.
- Реализует `ISaveLoadService`, делегируя `SaveLoadService`; регистрирует сериализаторы слоя объектов.
- `Update` → `Tick(Time.deltaTime)`: время игры и таймер автосейва по игровому времени; с `TickManually` их тикает
  владелец — в игре `GameServices` от игрового цикла, так что честная пауза их останавливает ([GameLoop.md](GameLoop.md));
  по таймеру — `Save(onlyIfChanged: true)`.
- Пауза приложения, потеря фокуса — `Save(onlyIfChanged: true)` (на мобильных и в вебе это может быть последний
  шанс); выход — `Save()`, синхронно.
- `LoadScene(path)` — смена сцены без потери изменений: сначала `Capture`, потом загрузка (раздел 6.5).
- Успешные сохранения в консоль не пишет; `Recovered`, `Corrupted`, `NewerVersion`, `MigrationFailed`,
  `SceneNotFound`, `Failed` — предупреждение или ошибка.

## 6. Объекты — `SaveSystem.Objects`

### 6.1. `Saveable`

Компонент на объекте, который надо сохранять. Пользователь добавляет его — и всё:

- **ID** — GUID (`N`, 32 hex-символа):
  - у объекта сцены назначается в эдиторе (`OnValidate`): пустой или повторный в открытых сценах — новый, записанный
    как override экземпляра префаба;
  - у ассета префаба ID пустой;
  - у объекта, созданного в игре (`Instantiate`, в том числе копия объекта сцены), — новый в `Awake`.
- **ID префаба** — GUID ассета префаба (у варианта — свой), эдитор запекает его в ассет. По нему заспавненный
  объект создаётся заново при загрузке; объект без ID префаба (копия не-префаба) восстановить нельзя —
  предупреждение.
- **Список компонентов** — компоненты объекта и его детей до вложенного `Saveable` (тот сохраняет себя сам), для
  которых есть сериализатор: встроенный, свой или поля `[Save]`. По умолчанию отмечено всё, что умеет сохраняться;
  включённость (`enabled`) отмеченных компонентов и `activeSelf` объекта и отмеченных детей сохраняются всегда.
  Ключ компонента — путь от `Saveable` и имя типа: `Transform`, `Visual/SpriteRenderer`, при нескольких одного типа —
  `Collider2D#1`.
- **Вложенные `Saveable` заспавненного объекта** восстанавливаются вместе с ним и получают свои сохранённые ID по
  пути от корня.
- Объект, заспавненный в игре, сохраняется, пока активен: выключенный считается вернувшимся в пул.

### 6.2. Скрытый реестр

- `Saveable` регистрируется в `Awake` и снимается в `OnDestroy`.
- При загрузке сцены (`sceneLoaded`, до `Start`) плагин сам обходит её корни и собирает все `Saveable`, включая
  выключенные, — это исходный набор сцены. Объектов-реестров в сцене нет.
- Объекты в `DontDestroyOnLoad` попадают в секцию `$persistent`: сцена их не пересоздаёт, поэтому данные
  применяются к живым объектам по ID сразу, в фазе объектов; недостающие заспавненные создаются заново.
- Статическое состояние сбрасывается при старте Play Mode (`SubsystemRegistration`) — работает и без перезагрузки
  домена.

### 6.3. Сериализаторы компонентов

Каталог «тип компонента → сериализатор» (как `SerializerCatalog` в домашке), собирается сам: плагин находит все
сериализаторы в сборках, которые ссылаются на `SaveSystem.Objects`. Приоритет: свой сериализатор → встроенный →
поля `[Save]`.

**Свой сериализатор** — как `TransformSerializer` в домашке:

```csharp
public sealed class SpriteAnimatorSerializer : ComponentSerializer<SpriteAnimator, SpriteAnimatorData>
{
    protected override SpriteAnimatorData Serialize(SpriteAnimator animator) =>
        new(animator.CurrentClipId, animator.Time);

    protected override void Deserialize(SpriteAnimator animator, SpriteAnimatorData data) =>
        animator.Play(data.ClipId, data.Time);
}
```

Версия и `Upgrade` — как у `GameSerializer`.

**Поля `[Save]`** — для своих скриптов без кода сериализации:

```csharp
public class FallingPlatform : MonoBehaviour
{
    [SerializeField] private float _fallDelay = 0.5f; // setting: not saved

    [Save] private State _state;
    [Save] private float _timer;
    [Save("_start")] private Vector2 _startPosition;  // stored under its former name
}
```

- Поля любой видимости, в том числе унаследованные; не `static`, не `const`, не `readonly`. Свойства — нет.
- Типы: примитивы, строки, перечисления, Unity-структуры, массивы, `List<T>`, `Dictionary` с ключом-строкой,
  числом или перечислением, `[Serializable]`-классы и структуры по значению (по правилам Unity: публичные поля и
  `[SerializeField]`), ссылки на Unity-объекты — раздел 6.4.
- Версия полям не нужна: добавить или удалить поле безопасно (нет ключа — значение не трогается, лишний ключ
  пропускается); переименовать — `[Save("старое имя")]`; сменить тип — свой сериализатор с `Upgrade`.
- Метаданные полей — рефлексией один раз на тип, дальше из кэша.

**Встроенные сериализаторы** — то, что игра меняет в рантайме; остальное — настройки, они не сохраняются:

| Компонент | Что сохраняется |
|---|---|
| `GameObject` | `activeSelf` |
| `Transform` | Локальные позиция, поворот, масштаб; родитель — ссылкой, если он `Saveable` или внутри него |
| `Rigidbody2D` | Тип тела, `simulated`, позиция и поворот тела, скорость, угловая скорость, сон, `gravityScale`, `constraints` |
| `Rigidbody` | `isKinematic`, `useGravity`, скорость, угловая скорость, сон, `constraints` |
| `Animator` | По слоям: состояние, время в нём, вес слоя; параметры `float`/`int`/`bool` (триггеры не читаются); `speed` |
| `ParticleSystem` | Играет / пауза / стоп, время, зерно — восстанавливается перемоткой `Simulate`; с флажком — живые частицы (`GetParticles`/`SetParticles`) |
| `AudioSource` | Клип, время, играет / пауза, громкость, высота, `mute` |
| `SpriteRenderer` | Спрайт, цвет, `flipX`, `flipY` |
| `Collider`, `Collider2D` | `enabled` |

Нужно больше — свой сериализатор для этого типа, он вытеснит встроенный.

### 6.4. Ссылки

| На что | Как хранится |
|---|---|
| `Saveable`, его компонент или ребёнок | ID объекта + путь + ключ компонента |
| Префаб | ID префаба |
| Ассет (Sprite, ScriptableObject, AudioClip, Material…) | GUID из таблицы ассетов папок, выбранных в настройках |
| Ассет, созданный в игре (новый материал) | Не поддерживается: `null` и предупреждение — сохраняйте его свойства |
| Обычный C#-объект | По значению, общие ссылки не отслеживаются |

Ссылка, которую не удалось найти при загрузке, — `null` и предупреждение.

### 6.5. Загрузка и сохранение сцены

**Сохранение:**

1. `OnBeforeSave` у компонентов отмеченных объектов (`ISaveCallbacks`).
2. По каждой загруженной сцене: данные живых `Saveable`; `destroyed` = исходный набор минус живые — считается
   в момент сохранения, а не в `OnDestroy` (он срабатывает и при выгрузке сцены, и при выходе); `spawned` —
   активные объекты, созданные в игре: ID, ID префаба, родитель, данные.
3. `$scenes` — активная сцена (путь и GUID).

**Загрузка** — после проверки слота (5.3) плагин перезагружает сохранённую сцену и восстанавливает её фазами:

1. **Объекты** (`sceneLoaded`, до `Start`): уничтожить объекты из `destroyed`; заспавнить объекты из `spawned`
   из каталога префабов с прежними ID и родителями (неизвестный префаб — предупреждение, пропуск); выставить
   `activeSelf`. Выключенным объектам (их `Start` не придёт) данные компонентов раздаются сразу.
2. **Данные** — в позднем `Start` самого `Saveable` (`[DefaultExecutionOrder(32000)]`), то есть после `Start`
   остальных компонентов: инициализация в `Start` не перетирает загруженное. Все объекты к этому моменту уже
   существуют — ссылки разрешаются с первого раза, без «загрузить дважды».
3. **Колбэки** — `OnAfterLoad` у компонентов объекта; когда данные получили все объекты, сервис поднимает
   `Loaded`.

Сущность без данных остаётся как в сцене; данные без объекта (уровень поправили) пропускаются.

**Смена сцены в игре.** Чтобы изменения уходящей сцены попали в снимок, сцену меняют через `SaveLoadSystem`
(`LoadScene` — сначала `Capture`, потом загрузка) или зовут `Capture()` сами перед загрузкой. При обычном
`SceneManager.LoadScene` изменения уходящей сцены с последнего сохранения теряются.

### 6.6. Настройки и каталоги — `SaveSystemSettings`

Один ассет на проект (у нас — `Assets/Game/Configs/SaveSystemSettings.asset`), создаётся меню и указывается в
`SaveLoadSystem`. Каталоги внутри эдитор держит в актуальном состоянии сам — при импорте, переносе и удалении
ассетов и перед сборкой:

- префабы с `Saveable`: ID префаба → префаб;
- сцены: путь ↔ GUID (ключ секции — GUID, поэтому переименование и перенос сцены сейвы не ломают);
- ассеты для ссылок: только из папок, указанных в настройках, по GUID — а не все зависимости сцены, как у Easy Save.

## 8. Подключение в нашей игре

- `GameServices`: поле `SaveLoadSystem`, `Register<ISaveLoadService>` в `Awake`, `Unregister` в `OnDestroy`;

- `SaveDebugHotkeys` (`Scripts/GameSystem/Services/`, на `[Services]`): F5 — `Save()`, F9 — `Load()`. Только `UNITY_EDITOR`
  или `DEVELOPMENT_BUILD`, ввод — `Keyboard.current`.
- Игрок: `Saveable` на префабе `Player` — Transform, Rigidbody2D и анимация (`SpriteAnimatorSerializer` в `Game`:

  `[Save]` отдельной задачей игры. (Сделано: ключ анимации — `Deform/Visual/SpriteAnimator`; враги — вариант игрока — сохраняются тоже, состояние ИИ — нет.)
- Демо-сцена `Scenes/Sandbox_SaveSystem.unity` (не в Build Settings — для ручной проверки, см. раздел 1).
- Чекпоинты — отдельная задача игры после плагина: триггер, который зовёт `Save()`.

**Игровая сторона после точки входа ([Bootstrap.md](Bootstrap.md), 2026-10-24).** Ход игры пользуется сейвами
через `ISavedGame` (`Scripts/GameSystem/App/SavedGame`), модуль не менялся: «New Game» и «Restart» — пустой снимок в текущем
слоте (`SelectSlot(CurrentSlot)`), «Continue» и F9 — `Load()` текущего слота шагом дерева загрузки, «Main Menu» —
`Save()`. Автосейв и сохранение при выходе, паузе и потере фокуса работают **только в уровне**: вне его объект
`SaveLoadSystem` выключен (`ISavedGame.AutoSave`), иначе выход из игры в меню записал бы в слот пустой снимок.
Загрузка при старте (`_loadOnStart`) в `[Services]` выключена — продолжает меню. F5 сохраняет только в уровне.
Демо `Sandbox_SaveSystem` выбирает свой слот 9 доской (`SaveDemoBoard._slot`), своего `[Services]` у сцены нет.

## 9. Когда сохраняем (настройки по умолчанию)

| Событие | Вызов |
|---|---|
| Выход из игры | `Save()` |
| Пауза приложения, потеря фокуса | `Save(onlyIfChanged: true)` |
| Таймер автосейва (игровое время, 30 с) | `Save(onlyIfChanged: true)` |
| Код игры (чекпоинт, F5) | `Save()` |
| «Продолжить», F9 | `Load()` |

Во время загрузки и в слот «только для чтения» не сохраняем. Блокировки на смерть, переходы и катсцены — дело
игры, когда они появятся.

## 10. Ошибки

| Ситуация | Поведение |
|---|---|
| Файла нет | `Empty`, новая игра |
| `save.json` битый, `.bak` цел | `Recovered`: битый → `.corrupt`, данные из `.bak`, предупреждение |
| Битые оба | `Corrupted`: оба → `.corrupt`, новая игра, предупреждение |
| Файл или секция новее игры | `NewerVersion`: ничего не применяется, слот «только для чтения» |
| Миграция бросила исключение | `MigrationFailed`: то же |
| Сохранённой сцены нет в Build Settings (в сборке) или в проекте (в эдиторе) | `SceneNotFound`: то же |
| Сериализатор бросил исключение при сохранении | Его прежние данные остаются, ошибка, остальные сохраняются |
| Сериализатор бросил исключение при загрузке (в том числе тип поля `[Save]` сменился) | Ошибка, данные этого компонента пропущены, остальные применяются |
| `IOException` при записи | `Failed`: файл на диске цел, снимок в памяти остаётся, следующее сохранение повторит |
| Исключение хранилища при чтении | `LoadOutcome.Failed`: ничего не применяется, слот «только для чтения» |
| Повторный ключ глобального сериализатора | `ArgumentException` |
| Повторный ID в сцене | Ошибка, второй объект получает новый ID и считается созданным в игре; заранее ловит проверка сцен |
| Префаб заспавненного объекта не найден | Предупреждение, объект пропускается |
| Компонент по ключу не найден (переименовали ребёнка, удалили компонент) | Данные пропускаются, предупреждение один раз |
| Ссылка не найдена | `null`, предупреждение |

## 13. Отложено

- Восстановление нескольких сцен, загруженных аддитивно (секции на сцену уже есть).
- Фоновая запись (`Awaitable`) и единая очередь — структура «снимок → запись» к этому готова.
- Миниатюры слотов, значок сохранения, меню слотов.
- Облако (Steam Auto-Cloud заберёт `persistentDataPath/Saves` как есть).
- Файл настроек игры — отдельно от слотов, своей задачей.
- `link.xml` для Newtonsoft — перед первой сборкой на IL2CPP.
- UI (`RectTransform`), `NavMeshAgent`, `CharacterController`; переходы `Animator` посреди смешивания.
- `[Save]` на свойствах; псевдоним для переименованного класса компонента.
- Чистка секций удалённых сцен.

## 14. Риски

- **Odin.** В «Известных шумах» Odin в 6.5 не рисует списки; у `Saveable` свой инспектор, у `SaveSystemSettings` —
  тоже свой (`CustomEditor`), чтобы не зависеть от Odin.
- **ID в `OnValidate`** не должны пачкать сцену без нужды и должны записываться как override префаба; закрывается
  тестами эдитора и проверкой сцен.
- **Точность физики:** контакты, джойнты и внутреннее состояние решателя не восстанавливаются — после загрузки
  возможен микроскачок. Документируем.
- **Animator:** переход посреди смешивания теряется, триггеры не читаются.
- **ParticleSystem:** перемотка `Simulate` на большое время дорогая; живые частицы раздувают файл — поэтому флажок.
- **Переименование класса компонента** меняет его ключ — нужна миграция.
- **`File.Replace` на Mono/IL2CPP** — проверяется тестами на Windows; другие платформы — когда станут целевыми.
- **Общая рабочая копия:** в этой же папке идёт работа над врагами — реализацию вести в отдельном worktree.
- **Путь сейвов** зависит от имени компании и продукта (сейчас `DefaultCompany` / `Lesson`) — вопрос ниже.

## Приложение A. Разбор кода домашки

**Как работало.** `SaveLoadService.Save()` собирал пустой `Dictionary<string, string>`, каждый `IGameSerializer`
клал туда JSON своих данных под ключом, `GameRepository` писал словарь в файл. Загрузка раздавала словарь обратно.
`GameSerializer<TService, TData>`: ключ — имя типа данных, сервис — через Zenject `[Inject]`, `Deserialize` по
умолчанию копировал рефлексией члены с `[SaveField]`. Мир: `EntityWorldSerializer` сохранял `id → имя конфига` и
данные компонентов каждой сущности; загрузка — `DestroyAll()` и спавн всех заново. Автосейв —
`GameSaveController` по таймеру, потере фокуса и выходу.

**Блокеры компиляции у нас:**

| # | Где | Проблема | Как закрыто |
|---|---|---|---|
| B1 | `GameSerializer`, `SaveLoadProvider`, `GameSaveController`, инсталлеры, `Entity`, `EntityWorld` | Zenject | Сервис в конструкторе, `SaveLoadSystem` на `[Services]`, регистрация через `GameServices` |
| B2 | `EntityWorld`, инсталлер | Odin | `EntityWorld` не нужен; свои инспекторы |
| B3 | `DedicatedServer(WIP)` | UniTask | Не переносим |
| B4 | `.asmdef` | Ссылки по GUID старого проекта | Новые asmdef со ссылками по имени |
| B5 | `Game/**` | Компоненты RTS | Не переносим |

**Баги и риски логики:**

| # | Проблема | Как закрыто |
|---|---|---|
| L1 | `Save` пересобирает словарь и затирает данные отсутствующих систем | Снимок в памяти, секции без сериализатора сохраняются |
| L2 | Ключ = имя типа данных, коллизии | Явный ключ, повторный отклоняется; ключ компонента — путь + тип + номер |
| L3 | Сейвы в `streamingAssets` (на билдах только чтение) | `persistentDataPath/Saves` |
| L4 | Запись поверх файла | `.tmp` + `File.Replace` + `.bak` |
