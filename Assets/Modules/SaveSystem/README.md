# Save System

Сохранения для Unity «из коробки». Компонентов два: **Save System** — один на сцену — и **Saveable** на объекте.
Кинул Save System в сцену — сохраняется вся сцена, на объекты ничего вешать не нужно, F5 и F9 сохраняют и загружают.
Нужна точность — переключи его на «только Saveable» и отметь на объектах, какие компоненты сохранять. Из кода —
полный контроль, слоты, версии и миграции, любые хранилища и серверы. Модуль самостоятельный: не зависит от игры,
нужен только Newtonsoft JSON (`com.unity.nuget.newtonsoft-json`; для меню слотов — uGUI и TextMesh Pro).
Проверено на Unity 6000.0 и 6000.5.

Спеки — `Assets/AI/Docs/SaveSystem.md` (части 1–3), `Assets/AI/Docs/SaveSystem_Part4.md` (простой путь, режимы
компонентов, слоты, хранилища, меню), `Assets/AI/Docs/SaveSystem_AutoCreate.md` (система создаётся сама).
Демо — `Demo/SaveSystemDemo.unity` (всё сразу) и `Demo/SaveSystemMinimal.unity`
(крутящийся кубик и кнопки Save / Load прямо на `SaveSystem`, без автосейва); не в Build Settings: открыть и нажать Play.

## Установка

Модуль разворачивается сам — любой из двух способов:

- **Package Manager (UPM):** *Window → Package Manager → + → Add package from tarball…* и файл
  `com.eugenem23.save-system-<версия>.tgz` (или *Add package from disk…* и `package.json` папки модуля). Newtonsoft
  JSON Package Manager ставит сам — это зависимость в `package.json`.
- **`.unitypackage`:** *Assets → Import Package → Custom Package…*. Нет Newtonsoft — установщик добавит пакет сам.

Все сборки модуля, кроме установщика, компилируются только с `SAVE_SYSTEM_JSON` — его задаёт `versionDefines`, когда
пакет Newtonsoft есть в проекте. Поэтому без Newtonsoft нет ошибок компиляции: собирается одна сборка
`SaveSystem.Installer` (без ссылок), добавляет пакет, и модуль компилируется следом. Если в `Assets` уже лежит свой
`Newtonsoft.Json.dll`, второй копии установщик не ставит, а задаёт `SAVE_SYSTEM_JSON` в *Scripting Define Symbols*
выбранной платформы (для остальных — вручную).

Первый запуск в проекте, где ещё нет ассета `SaveSystemSettings`: установщик создаёт его в
`Assets/Settings/Resources/` (каталоги — сразу) и открывает окно *Tools → Save System → Welcome* — что на месте,
импорт TMP Essentials (нужны только меню слотов), кнопки «добавить систему / меню в сцену», демо, README. Проект, где
настройки уже есть, первый запуск проходит молча. Признак «настроено» хранится в `UserSettings` проекта.

## Быстрый старт (без кода)

1. **Вся сцена — самый простой путь.** *Add Component → Save System* на любой объект сцены — и жми Play. Больше
   ничего: сохраняется каждый объект сцены (кроме статичных), F5 сохраняет, F9 загружает, слот грузится при старте.
   В инспекторе компонента:
   - **What to save.** *Scope*: *Whole Scene* (вся сцена) или *Saveables* (только объекты с `Saveable`). Для всей
     сцены — что брать с объекта (*Take From Objects*: положение, физика, свои скрипты, эффекты), пропускать ли
     статичные, список исключений. Подробности — в разделе «Вся сцена».
   - **Try it out.** Кнопки *Save*, *Load*, *New Game* (в Play Mode), клавиши и сводка последнего сохранения: сколько
     объектов, размер файла, время и что сохранить не удалось.
   - Ниже — где лежат сейвы, слот и загрузка при старте, когда сохранять, события и список слотов.

   Компонент можно бросить на что угодно — на уровень, на менеджера, на дочерний объект: объект останется в своей
   сцене, а работать будет созданный им `SaveSystem (live)`, который переживает смену сцен.
2. **Только выбранные объекты.** Поставь *Scope* = *Saveables* (или вообще не клади систему в сцену) и добавь
   компонент `Saveable` на объекты и префабы, которые нужно сохранять. Сцена без Save System работает так же:
   первый проснувшийся `Saveable` не находит системы и создаёт её сам (`SaveSystem (auto)`, переживает смену сцен):
   при старте загружает слот 0, оставаясь в текущей сцене (каждая сцена получает своё состояние, когда загрузится),
   сохраняет каждые 30 с игрового времени (если что-то поменялось), при паузе приложения и при выходе. Ассет настроек
   `SaveSystemSettings` редактор создаёт сам в `Assets/Settings/Resources/` — там его находит автосистема; галочка
   *Create System When Missing* у ассета её выключает. Если в проекте уже есть ассет настроек вне `Resources` (например,
   от старой версии модуля), редактор берёт его как есть, а автосистема его не найдёт и не появится: перенеси ассет в
   любую папку `Resources` под именем `SaveSystemSettings` — инспектор ассета подскажет. Появится первый `Saveable`
   посреди игры (заспавнен кодом, когда сцена уже идёт) — автосистема загрузит слот, но идущую сцену не тронет:
   сохранённое достанется следующим сценам, а секция этой сцены перезапишется при следующем сохранении. В инспекторе
   `Saveable` — все компоненты объекта и детей, **сохраняется только отмеченное**:
   - сразу отмечены `Transform` самого объекта, его тело (`Rigidbody`, `Rigidbody2D`) и твои скрипты на нём
     (скрипт без `[Save]` — в режиме *All Fields*: всё, что может);
   - дети, частицы, звук, аниматор, любой другой компонент — галочкой;
   - нужна точность — режим *Selected* и галочки у нужных полей и свойств.

   Префаб `Prefabs/SaveSystem` (*GameObject → Save System → Save System*) — система сразу в этом режиме, без клавиш.
   Первая проснувшаяся система переживает смену сцен; её можно класть в каждую сцену — копии ничего не делают сами и
   передают свои вызовы и события первой (и автосистеме тоже).
3. **Кнопки.** В `Button.onClick` перетащи объект с Save System своей сцены и выбери метод `SaveLoadSystem`:
   `SaveGame`, `LoadGame`, `SaveToSlot(n)`, `LoadFromSlot(n)`, `NewGame`, `ContinueGame`, `DeleteSlot(n)`,
   `DeleteAllSlots`, `RenameCurrentSlot(text)`. Его события `OnSaved` / `OnLoaded` / `OnFailed` — для «Сохранено!».
   Кнопки работают и после загрузки, и в других сценах: загрузка перезагружает сцену, её `SaveSystem` становится
   копией и передаёт нажатия живой системе.
4. **Меню слотов.** *GameObject → Save System → Save Slots Menu* (или префаб `Prefabs/SaveSlotsMenu`): список слотов
   с именем, датой, временем игры и сценой; сохранить, загрузить, удалить, переименовать — с подтверждением. Кнопки
   игры открывают его методами `OpenSave()` / `OpenLoad()` / `Toggle()` / `Close()`. Слоты — фиксированные (*Slot
   Count* > 0, с *First Slot*) или все сохранённые плюс строка «New slot» (0). Тексты переводятся в поле *Texts*.

Инспектор `SaveLoadSystem` показывает слоты на диске (загрузить в Play Mode, скопировать как текст, удалить) и где
лежат файлы.

## Вся сцена

*Scope = Whole Scene* сохраняет сцену без единого компонента на её объектах.

**Какие объекты.** Все объекты сцены, кроме: объекта самой системы, объектов с `Saveable` и всего под ними (они
сохраняют себя сами, по своему списку), помеченных *Static* (галочка *Skip Static Objects*), перечисленных в *Ignored
Objects* (с детьми) и объектов с тегом `EditorOnly`. Каждый объект — сам по себе: ребёнок сохраняется отдельно от
родителя, поэтому уничтоженный ребёнок остаётся уничтоженным.

**Что с объекта** (*Take From Objects*):

| Галочка | Что сохраняется |
|---|---|
| *Transforms* | Положение, поворот, масштаб — только если объект сдвинулся с момента загрузки сцены. Объекты под `Animator` не пишутся: их двигает анимация |
| *Physics* | `Rigidbody`, `Rigidbody2D`, включён ли коллайдер |
| *Scripts* | Твои скрипты: свой сериализатор, поля `[Save]`, а без них — все поля (*All Fields*, со ссылками) |
| *Effects* | `Animator`, `AudioSource`, `ParticleSystem`, `SpriteRenderer` |

Всегда сохраняется, жив ли объект и включён ли он. Объект, который стоит как в сцене и ничего из перечисленного не
несёт, в сейв не попадает совсем — его вернёт сама сцена. Рендереры, свет, камеры, UI не сохраняются: это не
состояние игры (нужно — повесь `Saveable` и отметь).

**Private Fields** (галочка под *Take From Objects*, включена). Скрипт, который сохраняется «всеми полями», отдаёт
и приватные поля без `[SerializeField]`, если в поле одно простое значение: число, `bool`, `enum`, строка, вектор,
кватернион, цвет. Это состояние, которое скрипт держит при себе: угол взгляда, который он каждый кадр пишет в
`Transform` камеры, фаза, счётчик. Не берутся: ссылки и коллекции (кэши, найденные в `Start`), `[NonSerialized]`,
`readonly`, константы. Не берётся и то, что скрипт «видел в прошлый раз»: приватное число, флаг или `enum` с именем
на `last…`, `prev…`, `old…`, `cached…`, `was…` (`m_LastAmmoRatio`, `_wasGrounded`). Скрипты сравнивают такое поле с
текущим значением и только при разнице обновляют внешний вид — свечение материала, темп частиц, надпись. Вида в
сейве нет, поэтому поле оставляется как в свежей сцене: в первом же кадре после загрузки скрипт видит разницу и
приводит вид в порядок. По той же причине не берётся приватный флаг «я уже настроился»: `bool` с `init`, `setup`
или `subscrib` в имени (`isInitialized`, `_isSetup`, `m_Subscribed`; так же — авто-свойство, которое ставит только
сам скрипт). То, что флаг охраняет — ссылки, найденные при настройке, подписки, — в сейв не попадает, и на заново
созданном объекте вернувшийся флаг заставил бы скрипт пропустить настройку и работать с пустыми ссылками (так
ломаются, например, эффекты из Asset Store). Слова вроде `started`, `awake`, `destroyed` под правило не подпадают:
ими так же часто называют состояние игры. Положение и поворот с таким именем (`m_LastRootPosition`) — состояние и сохраняются.
Если скрипт ведёт себя странно после загрузки — сними галочку или отметь его поля сам (`[Save]`, *Selected*). У
скрипта с полями `[Save]` сохраняются только они.

**Моменты времени.** Число, которое скрипт держит при себе (приватное поле или авто-свойство) и которое названо как
момент `Time.time` — `m_LastTimeShot`, `_startTime`, `TimeLastSeenTarget`, — сохраняется как «сколько секунд назад»
и возвращается относительно часов загрузки. Поэтому после загрузки с выстрела прошло столько же, сколько прошло на
момент сохранения: и в том же запуске игры, и в следующем, где часы идут с нуля. Правило по имени: в нём есть `time`
и нет слов-длительностей (`timer`, `elapsed`, `total`, `remain`, `left`, `delta`, `duration`, `cooldown`, `delay`,
`interval`, `timeout`, `lifetime`…) — такие числа сохраняются как есть. Публичные и `[SerializeField]`-поля — всегда
как есть: `MaxLifeTime` — настройка. Работает во всех режимах, кроме `[Save]` (там значение пишется как есть).

**Объект с `Saveable` в такой сцене.** Его список только добавляет к тому, что берёт режим сцены, и никогда не
сужает — враг с `Saveable` не сохраняется хуже соседнего объекта без него:

- компонент, которого нет в списке (скрипт, `Rigidbody`, `Animator`, звук, частицы — на объекте и на его детях из
  сцены), берёт режим сцены по галочкам *Take From Objects*; то, что создано под объектом в игре (вспышка выстрела),
  не пишется;
- скрипт в режиме *All Fields* отдаёт то же, что отдал бы режиму сцены (с приватными полями, если включены *Private
  Fields*);
- скрипт в режиме *Selected* отдаёт всё это плюс поля, отмеченные руками (ссылку, коллекцию — то, чего режим сцены
  сам не возьмёт).

Исключения: `Transform` и «включён ли коллайдер» пишутся только из списка. Чтобы компонент не сохранялся совсем, сними
галочку его вида в *Take From Objects* или переведи сцену в *Scope = Saveables* — там список работает как раньше.

**Ссылки.** У каждого объекта сцены есть ID, поэтому ссылка скрипта на любой такой объект (цель, владелец, список)
сохраняется и после загрузки указывает на новый экземпляр — без разметки.

**Созданное в игре** (пули, заспавненные враги). Перед сохранением система находит объекты, которых не было в
сцене. Объект с состоянием — со скриптом игры или телом — сохраняется как копия префаба, **в честь которого он
назван** (`Bullet(Clone)` → префаб `Bullet`), и после загрузки создаётся заново: его скрипты и тело — по тем же
галочкам, положение корня — всегда. Известны префабы, от которых зависит сцена, и префабы из папок `Resources` —
они и так попадают в сборку. Не узнаётся: объект, переименованный в игре; объект, собранный кодом без префаба;
копия одного из двух префабов с одинаковым именем — про каждый такой случай одно предупреждение. Надёжнее —
`Saveable` на префабе.

**Эффекты, созданные в игре** (взрыв после смерти врага, искры попадания — префаб без скриптов, только частицы и
звук; галочка *Effects*). Эффект сохраняется, пока он идёт: после загрузки он на том же месте и продолжается с того
же момента, а не начинается заново. Эффект, который уже закончился и ждёт, пока игра его удалит, не пишется.
Таймер, которым игра удаляла оригинал (`Destroy(vfx, 5f)`), сейв увидеть не может, поэтому вернувшийся эффект
система удаляет сама, как только в нём не осталось ни живых частиц, ни звука; зацикленный эффект останется до
выгрузки сцены. Эффект без известного префаба пропускается молча.

**Длинный кадр загрузки.** Сцена грузится дольше обычного кадра, и Unity отдаёт это время игре как `deltaTime`
(до `Time.maximumDeltaTime`, обычно 0,1 с) — причём два кадра подряд. Всё, что сохранено в движении, прыгнуло бы:
пуля на 300 м/с пролетает 30 метров за шаг и исчезает раньше, чем её увидят. Игра во время загрузки не шла, поэтому
система на время загрузки (с вызова `Load` и ещё два кадра после её конца) опускает `maximumDeltaTime` до
`fixedDeltaTime`, а потом возвращает прежнее значение.

**То, что игра создаёт сама при каждом старте** (оружие в руке, выданное в `Start`, пул). После загрузки сцена
стартует заново, и игра создаёт такой объект ещё раз. Сохранённая копия не встаёт рядом, а занимает его: система
ждёт, пока скрипты сцены отработают `Start`, и берёт объект с тем же именем под тем же родителем. Объект,
созданный игрой позже первого кадра, так не узнаётся и задвоится.

**Игра на DI-контейнере и пулах** (Zenject и подобные). Три правила, чтобы режим работал без разметки:

- *Родные объекты сцены — те, что были в ней, когда проснулся её Save System* (он просыпается первым в сцене,
  порядок −31000). Всё, что контекст или бутстрап создал в `Awake` — пулы, игрок, камера, — считается созданным в
  игре: сохраняется как копия префаба и после загрузки занимает объект, который игра создала снова.
- *Пустая папка — не объект.* Объект без префаба и без своих скриптов (`GamePools`, `Pool_Enemy`) сам не
  сохраняется, но то, что лежит под ним, рассматривается по одному; путь через папку пишется как родитель.
- *Чужой код — не скрипты игры.* Компоненты из сборок сторонних плагинов (папки `Plugins`, готовые dll, пакеты из
  реестра или git; список ведёт редактор в `SaveSystemSettings` → *Third Party Assemblies*) не сохраняются «всеми
  полями», как и компоненты Unity: контекст, ядро, твин сами ведут своё состояние (`_hasInstalled`), и вернуть его
  из сейва значит сломать их запуск. У скрипта игры, унаследованного от класса плагина (`MonoInstaller`,
  `MonoKernel`), берутся только его собственные поля. Нужен компонент плагина в сейве — `Saveable` и режим руками.

**Созданное под созданным** (ракета под роботом, который её выпустил; оружие в руке; полоска здоровья). Объект,
созданный в игре, сохраняет ту иерархию, что дал ему префаб. Ребёнок, которого в префабе родителя нет, — отдельный
объект: если он копия известного префаба и несёт состояние, он сохраняется сам, с ID родителя, и при загрузке
либо занимает такой же объект, который игра уже создала под родителем, либо создаётся заново (родители — раньше
детей). Если задан `SpawnHandler`, под родителем создаётся только то, что обработчик берёт на себя: оружие и UI
игра обычно собирает сама вместе с родителем, иногда позже, и объект, созданный мимо её контейнера, стал бы
сломанным двойником. Эффекты и украшения под таким объектом остаются его частью, как раньше.

Префаб объекта, заспавненного в другую сцену, чем та, что его знает (спавнер в уровне, пулы в системной сцене),
ищется по всем сценам режима. `NavMeshAgent` после загрузки переносится в сохранённое место (`Warp`), как и
`CharacterController`. Создание объекта при загрузке можно отдать игре — см. `SaveLoadSystem.SpawnHandler` ниже.
Состояние в обычных классах контейнера (здоровье, патроны) плагин не видит: его регистрируют из кода
(`saves.Register(...)`).

**Откуда ID.** Список «объект → ID» лежит в самом компоненте Save System и хранится в файле сцены; редактор
обновляет его при сохранении сцены, при входе в Play и перед сборкой (кнопка *Refresh Lists Now* — сразу). Попав в
список, объект держит ID навсегда: переименование и перенос в иерархии старые сейвы не ломают. Новому объекту ID
даётся по его месту в иерархии, так что одна и та же сцена на любой машине получает одни и те же ID.

Чего этот режим не умеет: приватные поля скрипта, которые хранят ссылку или список (см. *Private Fields* выше), —
для них `Saveable` с режимом *Selected* или `[Save]`; смену родителя у объекта сцены; таймеры `Destroy(obj, t)` у
вернувшихся объектов; списки игры, в которых она держит созданные объекты (слоты оружия), — их заполняет код игры.

## Из кода

```csharp
using Saving;
using Saving.Objects;

ISaveLoadService saves = SaveLoadSystem.Current;      // у нас в игре — ServiceLocator.Get<ISaveLoadService>()

// 1. Значения слота: ничего регистрировать не нужно
saves.Values.Set("coins", 120);
int coins = saves.Values.Get("coins", 0);

// 2. Объект целиком: [Save]-члены, а без них — все публичные поля и свойства (заполняется тот же объект)
saves.Register("stats", playerStats);                 // ScriptableObject тоже можно
saves.Register("volume", () => volume, v => volume = v);
saves.Unregister("stats");

// 3. Полный контроль: свой сериализатор с версиями и миграциями (см. ниже)
saves.Register(new InventorySerializer(inventory));

saves.Save();                                          // checkpoint, menu, F5
saves.Load();                                          // "Continue", F9
SaveLoadSystem.Current.LoadInPlace();                  // load in place, scenes stay (on the component only)

// 4. Сам компонент: клавиши, что записало последнее сохранение, чья это сцена
SaveLoadSystem system = SaveLoadSystem.Current;
system.Hotkeys = true;                                 // F5 / F9; SaveKey и LoadKey — любые F1…F12
SaveReport last = system.LastSave;                     // Outcome, Slot, Objects, Characters, Milliseconds, Problems
SaveLoadSystem ofScene = SaveLoadSystem.OfScene(gameObject.scene); // Scope и список объектов — у компонента сцены
```

**DI и пулы.** Объекты, которые загрузка создаёт заново, по умолчанию делает `Object.Instantiate` — без инъекции и
мимо пула. Отдай создание игре один раз, в инсталлере или бутстрапе:

```csharp
// Zenject: объект приходит из пула игры, с инъекцией; null — «не мой префаб», плагин создаст его сам
SaveLoadSystem.SpawnHandler = (prefab, parent) =>
    prefab.TryGetComponent(out Entity entity) ? factory.Create(entity).gameObject : null;
```

Объект, который обработчик оставил под другим родителем, переносится к сохранённому; если родителя в сейве нет,
остаётся там, куда его положила игра (папка пула). Исключение в обработчике — ошибка в консоли, объект пропущен,
загрузка идёт дальше. Обработчик один на игру и сбрасывается при входе в Play.

**Загрузка без перезагрузки сцен** (*Live Load* в инспекторе Save System, из кода — `system.LiveLoad = true`;
выключена по умолчанию). Загрузка посреди игры — кнопка, клавиша, `Load()` — оставляет сцены как есть: живые
объекты получают сохранённое состояние, созданные после сохранения уходят из игры, сохранённые, но уже исчезнувшие,
создаются заново (через `SpawnHandler`). Объект сцены в режиме «вся сцена», о котором сейв молчит (стоял как в
сцене), возвращается на место и к флагу активности из начала сцены. Контейнеры, пулы и синглтоны игры при этом не
перезапускаются — для игр, которым перезагрузка сцены ломает системы. Уходящие объекты можно вернуть в пул:

```csharp
SaveLoadSystem.DespawnHandler = target =>
{
    if (!target.TryGetComponent(out Entity entity))
        return false;            // не мой объект: плагин уничтожит его сам
    entity.Dispose();            // назад в пул
    return true;
};
```

Сцена всё же перезагружается (строка в консоли говорит почему), когда сейв сделан в другой сцене, не загружена
одна из сохранённых соседних сцен или должен вернуться объект из файла сцены, уничтоженный после сохранения, —
его может дать только сама сцена. Загрузку на старте (*Load On Start*) режим не меняет.

**Состояние в обычных классах** (классы DI-контейнера, модель за вьюхой). Компонент объекта реализует
`ISaveStateProvider` и отдаёт такие объекты — они сохраняются вместе с объектом и получают данные обратно, в те же
экземпляры:

```csharp
public class Entity : MonoBehaviour, ISaveStateProvider
{
    public void CollectState(List<object> state)
    {
        state.Add(_health);      // свои объекты; для Zenject — то, что лежит в контейнере GameObjectContext
        state.Add(_clip);
    }
}

public class Health : ISaveCallbacks       // обычный класс, не MonoBehaviour
{
    [Save] private int _current;           // есть [Save] — сохраняются только отмеченные члены
    public void OnBeforeSave() { }
    public void OnAfterLoad() => Changed?.Invoke(_current);   // запись в поле событий не вызывает: сообщи сам
}
```

Класс без `[Save]` сохраняется автоматически: публичные значения и простые значения в приватных полях и
авто-свойствах (числа, флаги, `enum`, строки, векторы); `readonly`, ссылки и списки не трогаются. Это удобно для
данных, но опасно для логики: флаги и таймеры состояний ИИ (`_isBusy`, `_timer`), возвращённые по отдельности от
самой машины состояний, её останавливают — такие классы либо не отдавай, либо отметь в них `[Save]` только данные.
Ключ в сейве — `<ключ компонента>:<имя класса>`; второй объект того же класса получает `#1`, поэтому порядок в
списке должен быть постоянным. Поле `state` у объекта появляется в сейве, только когда есть что писать.

`SaveLoadSystem.Current` — `null`, пока системы нет: без префаба в сцене она появляется с первым `Saveable`
(если ассет настроек лежит в `Resources`).
Регистрация — когда система появилась, снятие — когда исчезла; зарегистрированная после загрузки получает свои
данные сразу. С *Load On Start* слот читается в тот момент, когда к системе впервые обращаются до её `Start`: код,
который регистрируется, пока сцена просыпается (DI-контейнер, `Awake`, `OnEnable`), получает данные сразу, и вьюха,
читающая состояние в `OnEnable`, показывает сохранённую игру с первого кадра. Это раннее чтение тихое — битый или
слишком новый файл разбирает полная загрузка в `Start`, как и раньше. Если до `Start` к системе никто не обращается,
`UseStorage` и `Configure` по-прежнему работают до старта. Значения (`Values`) живут в слоте: новый слот начинает их
пустыми, загрузка заменяет. Ключи с `$` — плагина.

## Объекты сцены: `Saveable`

`Saveable` — явный список: сохраняются только отмеченные компоненты объекта и его детей (до следующего `Saveable`,
который сохраняет себя сам). Добавленный в редакторе, он сразу отмечает `Transform` объекта, его тело и твои
скрипты на нём; всё остальное — галочкой или из кода. Компонент, добавленный на объект позже, сам в список не
попадает. ID объект сцены получает сам.

```csharp
saveable.SetSaved("Visual/Animator", true);            // ключ — путь от Saveable + тип: "Transform", "Visual/Animator"
saveable.SetSaved("Rigidbody2D", false);
saveable.SetMode("Light", SaveMode.AllFields);         // режим заодно отмечает компонент
saveable.SetMembers("Visual/LineRenderer", new[] { "startWidth", "endWidth" }); // Selected
saveable.UseExplicitList(new[] { "Transform", "Health" }); // весь список разом
```

**Старые `Saveable`** (из версий до 0.5.0) работают как раньше: сохраняется всё, у чего есть сериализатор, пока
галочку не снимешь, — включая всех детей, частицы и звук, из-за чего сейв разрастается. Инспектор такого
`Saveable` предлагает кнопку *Switch To An Explicit List*: остаются `Transform`, тело и скрипты объекта и всё, чему
режим задан руками. Для всего проекта разом — *Tools → Save System → Switch Saveables To Explicit Lists* (открытые
сцены и префабы проекта; демо и тесты самого модуля не трогает); из кода — `saveable.UseExplicitList()`.

| Режим | Что сохраняется |
|---|---|
| **Auto** (по умолчанию) | Свой `ComponentSerializer`, встроенный сериализатор или поля `[Save]` — у кого что есть |
| **All Fields** | Твой скрипт — поля, которые сериализует Unity (`public`, `[SerializeField]`), и авто-свойства (`{ get; set; }`, `{ get; private set; }` — так часто хранят состояние: `CurrentHealth`), или его `[Save]`, если они есть. Компонент Unity (движок, uGUI, TextMesh Pro) — его публичные свойства простых типов. Обычный класс — публичные поля и свойства. Ссылки на Unity-объекты у своих скриптов (цель врага, владелец пули, список миньонов, класс со ссылкой внутри) сохраняются, **если сейв может их выразить** (см. «Ссылки»); иначе член не пишется вовсе, без предупреждений, и загрузка оставляет то, что дала сцена, — проводка из инспектора не затирается. В инспекторе такие члены помечены `(ref)` |
| **Selected** | Только отмеченные поля и свойства — в том числе приватное состояние (`_timer`) и ссылки; ссылка, которую сейв выразить не может, — предупреждение при сохранении |

Члены, которые ломают объект при записи (`material`, `mesh` делают копии, `aspect`, `bounds`, `centerOfMass`
замораживают автоматику), в списках не появляются. Загрузка в режимах All Fields и Selected идёт поштучно: член,
который не прочитался или не записался, — предупреждение, остальные применяются. Поля `[Save]` — как раньше «всё
или ничего». Свои скрипты пишут состояние полями: у компонентов uGUI состояние — за сеттерами, поэтому у них
сохраняются свойства.

`[Save]` — на полях и свойствах (с `get` и `set`); ключ — имя члена или заданный: `[Save("старое имя")]`. Настройки
из Inspector в режиме Auto не сохраняются — тюнинг чисел в обновлении не перетирается старыми сейвами.

Особый случай — `ComponentSerializer<TComponent, TData>` (находится сам, вытесняет встроенный и `[Save]`).
Встроенные сериализаторы:

| Компонент | Что сохраняется |
|---|---|
| `GameObject` | `activeSelf` объекта и детей с отмеченными компонентами |
| `Transform` | локальные позиция, поворот, масштаб |
| `Rigidbody2D` | тип тела, `simulated`, позиция и поворот тела, скорость, угловая скорость, сон, `gravityScale`, `constraints` |
| `Rigidbody` | `isKinematic`, `useGravity`, скорость, угловая скорость, сон, `constraints` |
| `Collider2D`, `Collider` | `enabled` |
| `Animator` | по слоям: состояние, время, вес; параметры `float`/`int`/`bool`; `speed` |
| `ParticleSystem` | играет / пауза / стоп, время (с прошедшей частью *Start Delay*), зерно (перемотка `Simulate`), множители темпа испускания (их меняют скрипты); флажок «живые частицы». Система, которая перестала испускать, но её частицы ещё летят, пишет эти частицы всегда |
| `SpriteRenderer` | спрайт, цвет, `flipX`, `flipY` |
| `AudioSource` | клип, время, играет / пауза, громкость, высота, `mute` |

Сериализатор модуля движка компилируется, только если модуль включён (`versionDefines`: `SAVE_PHYSICS`,
`SAVE_PHYSICS_2D`, `SAVE_ANIMATION`, `SAVE_PARTICLES`, `SAVE_AUDIO`). Свой сериализатор с параметрами —
`ISerializerOptions` + `SerializerOptions.IsOn` (флажки параметров — в инспекторе `Saveable`).

**Ссылки** в данных: на `Saveable`, его компоненты и детей (ID + путь + компонент), на префабы с `Saveable` (ID
префаба) и на ассеты из папок `SaveSystemSettings` (GUID; спрайт в текстуре — `GUID:localId`). После загрузки ссылка
указывает на новый экземпляр того же объекта — и для объектов сцены, и для заспавненных, в любую сторону, в списках,
массивах, словарях, классах и структурах. Каталоги ассетов, префабов и сцен эдитор обновляет сам.

Ссылку на что-то другое (объект сцены без `Saveable`, префаб без него, ассет вне папок настроек) сейв выразить не
может. Член, в котором есть такая ссылка — сама или внутри списка, словаря, класса, — не загружается целиком: остаётся
то, что дала сцена (менеджер, найденный в `Start`, звук из инспектора), список с дырой никому не нужен. Selected и
`[Save]` при сохранении предупреждают (один раз на объект), All Fields молчит. Ссылка, которая при загрузке не
нашлась, — `null` и предупреждение.

Чего ссылки не умеют (как и сериализация Unity без `[SerializeReference]`): два поля с одним и тем же обычным
C#-объектом после загрузки держат две копии; наследник в поле базового типа возвращается базовым типом; интерфейсы и
делегаты не сохраняются.

Уничтоженные объекты сцены остаются уничтоженными, заспавненные из префабов с `Saveable` на корне создаются снова с
прежними ID и родителем, `DontDestroyOnLoad` — секция `$persistent`. Дочерний объект, созданный в игре без своего
`Saveable` (оружие в руке), сам не вернётся: его данные применятся, только если игра создаст его снова до загрузки
данных (в `Start`), иначе — одно предупреждение на объект. Префаб с пропавшим скриптом (missing script) Unity не
даёт сохранить, поэтому его ID не настраиваются — эдитор пишет об этом ошибку: убери пропавший скрипт. Снимок одного объекта без сцены (тесты,
отладка) — `Saveable.CaptureState()` / `RestoreState(state)`.

**Загрузка** перезагружает сохранённую сцену: объекты — на `sceneLoaded`, данные — в позднем `Start` каждого
`Saveable` (после `Start` остальных компонентов: инициализация не перетирает загруженное), затем
`ISaveCallbacks.OnAfterLoad` и событие `Loaded`. Смена сцены без потери изменений — `Capture()` перед загрузкой.

**Несколько сцен.** Сейв помнит активную сцену и те, что были загружены рядом с ней (системная сцена, HUD — поле
`additive` секции `$scenes`; у игры из одной сцены его нет). Загрузка поднимает активную сцену, ждёт кадр, пока
отработают её скрипты, и догружает аддитивно те сцены из списка, которые игра не загрузила (и не начала грузить)
сама: сцена, которая грузит соседей в `Awake` или `Start`, второй копии не получит, а набор, собранный снаружи
(лаунчер, несколько сцен, открытых в редакторе), вернётся целиком. Сцены, которой больше нет в сборке, — одно
предупреждение. Загрузка на старте без перезагрузки отдаёт данные всем сценам, поднявшимся вместе с активной.

## Слоты

```csharp
SlotInfo info = saves.GetSlot(2);          // null — пусто; Name, SavedAtUtc, CreatedAtUtc, Scene, PlayTimeSeconds, Summary
saves.SlotName = "Перед боссом";           // имя текущего слота, пишется при сохранении
saves.RenameSlot(2, "Перед боссом");
saves.CopySlot(2, 5);
int latest = saves.GetLatestSlot();        // -1 — сохранений нет
int free = saves.GetFreeSlot();            // первый слот без файлов
saves.SelectSlot(3);                       // новая игра в слоте 3: пустой снимок
saves.SelectSlot(3, keepData: true);       // «сохранить как»
saves.DeleteSlot(3);
saves.SlotsChanged += RefreshMenu;         // записан, переименован, скопирован, удалён, импортирован
```

`SaveLoadSystem` добавляет `void`-методы для кнопок (`SaveToSlot`, `LoadFromSlot`, `NewGame` — первый свободный
слот и стартовая сцена: поле *New Game Scene*, пусто — перезагрузить активную; `NewGameInSlot`, `ContinueGame`) и
`UnityEvent`. Свою загрузку сцен для `NewGame` (затемнение) — через `LoadSceneHandler`. Поле *Start In Latest Slot* —
начать с последнего сохранённого слота.

Копия или импорт в **текущий** слот делает его «только для чтения» до `Load()`: иначе следующее сохранение записало
бы старый снимок поверх.

## Хранилища, базы данных, серверы

| Где | Как |
|---|---|
| Файлы (по умолчанию) | `persistentDataPath/<Folder>/slot_N/` — атомарная запись, `.bak` |
| PlayerPrefs | *Storage → PlayerPrefs*: WebGL и маленькие игры (WebGL держит ~1 МБ PlayerPrefs всего) |
| Своё хранилище | *Storage → Custom* + ассет-наследник `SaveStorageAsset`; из кода — `UseStorage(storage)` до старта |
| Сжатие, шифрование | Флажки *Compress* (GZip) и *Encrypt* + ключ (AES-256 + HMAC). Старые открытые сейвы читаются; выключенный шаг продолжает читаться (сжатие — всегда, шифрование — пока ключ задан), так что выключение не делает сейвы «испорченными». Ключ лежит в игре — это защита от чтения и правки файла руками, а не от взлома; открытый текст принимается ради старых сейвов — строгий режим: `TransformSaveStorage.AcceptPlainText = false` в своём хранилище |
| Сервер, облако | *Remote Storage* — ассет-наследник `RemoteSaveStorageAsset`; из кода — `UseRemote(remote)`; дальше `SaveSync` |

**База данных за три метода** — наследник `KeyValueSaveStorage` получает всю логику слотов, `.bak` и карантина:

```csharp
public sealed class SqliteSaveStorage : KeyValueSaveStorage
{
    private readonly SqliteConnection _db;
    public SqliteSaveStorage(SqliteConnection db) : base("saves/") => _db = db;

    protected override bool TryGet(string key, out string text) { /* SELECT text FROM saves WHERE key = @key */ }
    protected override void Set(string key, string text) { /* INSERT OR REPLACE INTO saves (key, text) … */ }
    protected override void Remove(string key) { /* DELETE FROM saves WHERE key = @key */ }
}

[CreateAssetMenu(menuName = "Saves/SQLite Storage")]
public sealed class SqliteStorageAsset : SaveStorageAsset
{
    public override ISaveStorage CreateStorage() => new SqliteSaveStorage(Open());
}
```

Полный контроль — свой `ISaveStorage` (шесть методов: список слотов, чтение файла и его `.bak`, атомарная запись,
карантин, удаление). Шаги текста (свой формат, своё шифрование) — `ISaveTransform` в `TransformSaveStorage`.

**Сервер** — локальное хранилище остаётся главным (сохранение не ждёт сеть), сервер держит копии. Слот целиком —
одна строка: `ExportSlot(slot)` / `ImportSlot(slot, text)`. Серверу нужно четыре метода:

```csharp
public sealed class HttpSaveServer : IRemoteSaveStorage
{
    private const string URL = "https://example.com/api/saves/";

    public async Task<IReadOnlyList<int>> ListAsync(CancellationToken token) =>
        JsonConvert.DeserializeObject<List<int>>(await Send(UnityWebRequest.Get(URL)));

    public async Task<string> DownloadAsync(int slot, CancellationToken token)
    {
        using var request = UnityWebRequest.Get(URL + slot);
        await request.SendWebRequest();
        return request.responseCode == 404 ? null : Check(request);
    }

    public Task UploadAsync(int slot, string package, CancellationToken token) =>
        Send(UnityWebRequest.Put(URL + slot, package));

    public Task DeleteAsync(int slot, CancellationToken token) => Send(UnityWebRequest.Delete(URL + slot));

    // Send: await request.SendWebRequest(), throw on an error, return the text; headers (token) go here
}
```

```csharp
var sync = new SaveSync(saves, new HttpSaveServer()) { UploadAfterSave = true }; // или SaveLoadSystem.Sync
SyncOutcome outcome = await sync.SyncAsync(slot);   // новее побеждает: Uploaded, Downloaded, UpToDate, Failed
if (outcome == SyncOutcome.Downloaded) saves.Load();
```

Сбой сервера — `Failed` и предупреждение, локальные данные не трогаются. Пример-заготовка без сети —
`FolderRemoteSaveStorage` (пакеты `slot_N.json` в общей папке).

## Файлы на диске

`<persistentDataPath>/Saves/slot_N/`: `save.json` (данные), `meta.json` (имя, время создания и сохранения, сцена,
время игры, `Summary` — для меню слотов), `save.json.bak` (предыдущая запись), `save.premigration.json` (копия до
первой миграции), `*.corrupt` (испорченные файлы). Запись — через временный файл и `File.Replace`: обрыв не портит
сейв.

## Версии и миграции

Секция хранит версию своих данных. Поменялась форма данных — поднять `version` в конструкторе и добавить шаг:

```csharp
protected override JToken Upgrade(JToken data, int fromVersion) => fromVersion switch
{
    1 => RenameField(data, "ids", "items"), // version 1 -> 2
    _ => base.Upgrade(data, fromVersion)
};
```

Файл или секция от более новой игры не загружаются и не перезаписываются: слот становится «только для чтения»
до выбора слота. Данные режимов All Fields и Selected версий не имеют: добавить или убрать член безопасно (нет ключа —
значение не трогается), сменить тип — член пропустится с предупреждением.

## Когда сохраняется

| Событие | Что делает `SaveLoadSystem` |
|---|---|
| Выход из игры | Доигрывает начатое (см. ниже), `Save()` |
| Пауза приложения | Доигрывает начатое, `Save(onlyIfChanged: true)` |
| Потеря фокуса | `Save(onlyIfChanged: true)`, дождавшись начатого |
| Таймер (игровое время, 30 с; 0 — выкл.) | `Save(onlyIfChanged: true)`, дождавшись начатого |
| Клавиша F5, кнопки `SaveGame`, `SaveToSlot` | `Save()`, дождавшись начатого |
| `Save()` из кода | Сразу, ничего не ждёт |

**Не посреди начатого.** Монетка, которая летит к банку и начисляет деньги, когда долетит; дверь, которая
открывается в конце анимации. Колбэк такой анимации — код, в сейв он не попадает, и сохранение посреди полёта
записало бы «доход готов, денег нет». Поэтому система не режет начатое: сохранения, которые она делает сама,
ждут, пока оно закончится (не дольше `MAX_WAIT_FOR_WORK` = 5 с реального времени — потом всё равно сохраняют);
выход из игры и пауза приложения доигрывают его сразу, с колбэками, и сохраняют результат; загрузка обрывает его
без колбэков — награда, начатая после сохранения, не попадает в загруженную игру, а ожидающее сохранение
отменяется. Несколько запросов, пока система ждёт, дают одно сохранение (`IsSaveWaiting`).

«Начатое» по умолчанию — твины DOTween, которые играют, имеют `OnComplete` и не зациклены навсегда: бесконечные
покачивания UI, твины на паузе и счётчик на надписи без колбэка сохранение не держат. DOTween найден через
reflection, модуль от него не зависит; без DOTween ничего не меняется. Другая библиотека анимации — свой
`IWorkInFlight` (`IsBusy`, `Finish`, `Drop`) в `SaveLoadSystem.WorkInFlight`; `null` — сохранять когда угодно.
Галочка *Finish Work Before Save* (`FinishWorkBeforeSave`, по умолчанию включена) выключает всё это у системы.
В сборке с вырезанием кода (IL2CPP, managed stripping) методы DOTween, которые игра сама не вызывает, могут быть
вырезаны — тогда система молча сохраняет как раньше.

**Полёт, который игра сохраняет сама.** Если после загрузки монетка должна быть снова в воздухе и долететь (а не
уже долетевшей), игра записывает свой полёт данными и помечает твин id `SaveLoadSystem.WORK_SAVED_BY_GAME`: такой
твин сохранение не держит и выход его не доигрывает — сейв снимает ровно текущий момент; загрузка его всё равно
обрывает, а игра запускает заново с сохранённого места:

```csharp
public class CoinMoveController : MonoBehaviour, ISaveCallbacks   // на монетке — Saveable
{
    [Save] private bool _inFlight;
    [Save] private Vector3 _flightFrom;
    [Save] private float _flightElapsed;
    private Tween _flight;

    private void Fly(Vector3 from, float elapsed)
    {
        transform.position = _flightFrom = from;
        _flight = transform.DOMove(_target.position, _duration)
            .SetId(SaveLoadSystem.WORK_SAVED_BY_GAME)
            .OnComplete(Land);                       // колбэк — код игры: его не сохранить, его запускают заново
        if (elapsed > 0f) _flight.Goto(elapsed, andPlay: true);
    }

    public void OnBeforeSave()
    {
        _inFlight = _flight != null && _flight.IsActive();
        _flightElapsed = _inFlight ? _flight.Elapsed() : 0f;
    }

    public void OnAfterLoad()
    {
        if (_inFlight) Fly(_flightFrom, _flightElapsed);
    }
}
```

## Ошибки

`Load()` возвращает `Loaded`, `Recovered` (данные из `.bak`), `Empty`, `Corrupted` (новая игра, файлы в
`.corrupt`), `NewerVersion`, `MigrationFailed`, `Failed` (последние три — ничего не применено, слот только для
чтения; так же — сейв с чужим ключом шифрования), `SceneNotFound`. `Save()` — `Saved`, `Unchanged`, `Blocked`,
`Failed` (файл на диске — прежний). `SaveLoadSystem` повторяет их событиями `OnSaved`, `OnLoaded`, `OnFailed`. Сбой
одного сериализатора пишется в консоль и не мешает остальным.
