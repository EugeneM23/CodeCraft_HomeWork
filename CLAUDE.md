# Как работать с этим руководством (инструкция для ИИ-агента)

Эта папка — не Unity-проект, а **база знаний по сетевому Unity на Photon Fusion 2**:
десять разобранных учебных проектов и собранное по ним руководство на 27 глав.
Читать её надо как справочник с произвольным доступом, а не как книгу.

Адресат этого файла — ты. Дальше — директивы, а не описание.

## 1. Железное правило

**Документ нельзя читать целиком.** 900 000 символов русского текста — это порядка
полумиллиона токенов. `Read` без `offset`/`limit` на нём — потерянная сессия.

Три следствия, обязательные к исполнению:

1. **Единица чтения — раздел главы (1–20 К символов), а не глава (41–68 К) и не часть.**
   Глава целиком — это ~25 К токенов; бери её целиком только если правишь её текст.
2. **Никогда не `grep` по документу без ограничения вывода.** Слова вроде `Networked`
   или `Runner` встречаются сотнями раз. Либо `grep -c`, либо `grep -n … | head`,
   либо `grep` в границах диапазона через `sed -n 'A,Bp' | grep`.
3. **Сначала `MAP.txt`, потом документ.** Карта стоит ~8 К токенов и экономит в разы
   больше; `grep` по карте — десятки токенов.

## 2. Протокол: три шага

### Шаг 1. Ядро — всегда

```bash
sed -n '401,485p' "РУКОВОДСТВО - Сетевые приложения на Unity.md"
```

85 строк, 3 К символов. Внутри — модель мира Fusion 2 (кто чем владеет,
`FixedUpdateNetwork()` против `Render()`, дерево выбора базового класса) и
**границы применимости**: весь код части I — это Fusion **2.0.5** в режиме
**Host Mode**.

Этот шаг не пропускается. Без него легко применить правило части I к Shared Mode,
где нет ни `INetworkInput`, ни `OnInput`, ни `GetInput()`, ни предсказания,
ни ресимуляции, ни лаг-компенсации, ни Host Migration, ни `ConnectionToken`.

### Шаг 2. Роутер → номер главы

Задача → глава: раздел `0.4` документа, `sed -n '544,570p'` (16 готовых маршрутов).
Симптом → глава: таблица `91.9`, `sed -n '13751,13776p'` (26 строк: симптом,
вероятная причина, глава). **При любом «не работает» это первая команда.**

### Шаг 3. Раздел главы → чтение

```bash
grep '^ch-06' guide/MAP.txt     # глава и все её разделы с диапазонами
sed -n '4663,5035p' "РУКОВОДСТВО - Сетевые приложения на Unity.md"
```

## 4. Анатомия главы: какой раздел под какую нужду

Разделы внутри глав **жёстко единообразны**. Это и есть механизм экономии: тебе
почти никогда не нужна глава, нужен один её раздел.

**Главы 01–15 (практика), ровно 8 разделов в этом порядке:**

| Раздел | Читать, когда | Типично |
|---|---|---|
| Какую проблему решает | ориентируешься, та ли это глава | 1–2K |
| Модель мира: кто чем владеет | **перед любым решением об авторитете** | 2–4K |
| Архитектура раздела | проектируешь раскладку классов | 2–4K |
| Реализация по шагам | **пишешь код** (здесь весь C#) | 15–40K |
| `Fusion API` этой главы | нужна подпись метода или гоча API | 2–5K |
| Настройки, без которых не работает | «код правильный, но не работает» | 3–6K |
| Антипаттерны | ревью чужого или своего кода | 2–4K |
| Чеклист: как применить | **перед сдачей фичи** | 2–4K |

В главе 15 пятый раздел называется `Realtime API этой главы` (там нет Fusion).
В главах 06 и 08 есть девятый раздел `Что изменилось относительно главы N` —
это дельта к предыдущей главе, читай его, если предыдущую уже прочёл.

**Главы 20–31 (теория), 6 разделов:**

| Раздел | Читать, когда |
|---|---|
| Зачем это знать | ориентируешься |
| Нумерованные разделы (`21.1`…`21.8`) | суть темы |
| Чего по этой теме нет в учебном курсе | **понять, где часть I молчит** |
| Решение: что брать и когда | нужен вывод, а не разбор |
| Чеклист | перед сдачей |
| Источники | нужна первичная документация Photon |

Если нужен только вывод — бери `Решение: что брать и когда`, это 1–3 К символов
вместо 45 К.

## 5. Рецепты

Во всех командах:

```bash
D="РУКОВОДСТВО - Сетевые приложения на Unity.md"
```

Разделы конкретной главы с диапазонами:

```bash
grep '^ch-08' guide/MAP.txt
```

Найти главу по слову в заголовке раздела:

```bash
grep -i 'миграц\|reconnect\|ConnectionToken' guide/MAP.txt
```

Где в документе вообще встречается API (с номерами строк, ограниченно):

```bash
grep -n 'Runner.LagCompensation' "$D" | head -20
```

Сколько раз — чтобы понять, стоит ли вообще искать:

```bash
grep -c 'OnChangedRender' "$D"
```

Прочитать раздел по диапазону из `MAP.txt` (здесь — `Реализация по шагам` главы 08):

```bash
sed -n '6287,6770p' "$D"
```

Искать внутри одной главы, не по всему документу:

```bash
sed -n '6191,6931p' "$D" | grep -n 'AddPlayerAreaOfInterest'
```

Вытащить только код из раздела:

```bash
sed -n '4663,5035p' "$D" | perl -ne 'if(/^```csharp/){$i=1;next} if(/^```/){$i=0;next} print if $i'
```

Правила чеклиста по одной главе (нумерация правил — `**NN.i.**`):

```bash
grep -n '^\*\*08\.' "$D"
```

Проверить цитату кода в исходниках — что фрагмент дословный. Ищи внутри
`Assets/Game` или `Assets/Scripts`, иначе попадёшь в сам SDK Photon, который
лежит рядом в `Assets/Photon`:

```bash
grep -rn --include='*.cs' 'Runner.LagCompensation' "06 - Компенсация задержек/_src/Assets/Game"
```

Пересобрать карту после правки документа:

```bash
perl guide/map.pl "РУКОВОДСТВО - Сетевые приложения на Unity.md" > guide/MAP.txt
```

**Про `Read` и `Grep`.** `Read` с `offset`/`limit` по этому файлу работает и даёт
номера строк — это нормальный способ прочесть диапазон. Но `Grep` по корню папки
без `glob` зацепит и документ, и `guide/*.md`, и 10 копий исходников: каждое
совпадение найдётся четырежды. Ограничивай: `glob: "*.md"` для текста,
`glob: "**/_src/**/*.cs"` для кода.

## 6. Перед тем как отдать сетевой код

Порядок, а не набор:

1. Ядро — `sed -n '401,485p' "$D"`. Подтверди, что твоя топология и версия SDK
   те же, для которых писано правило.
2. Чеклист главы по теме: `grep '^ch-99' guide/MAP.txt`, затем диапазон нужной
   главы. 351 правило в формате «Всегда / Никогда», сгруппированы по главам.
3. Раздел `Антипаттерны` той главы, по которой писал.
4. Раздел `Настройки, без которых не работает` — больше половины «сетевой код не
   работает» это не код, а `NetworkProjectConfig`, `AssembliesToWeave`,
   `ProvideInput` или незаполненное поле префаба.
5. `92.13. Что считать «готовым» сетевым компонентом` — `sed -n '13999,14022p' "$D"`.

## 7. Приоритет при конфликте

1. **Код в исходниках `_src`** — это то, что есть на самом деле. Главы цитируют
   его дословно; если расходится — прав исходник, а главу надо поправить.
2. **Часть II (главы 20–31)** — выведена из официальной документации Photon,
   каждый факт со ссылкой, версионная рамка актуальнее. При конфликте с частью I
   по вопросам режимов, тайминга, лимитов и цен права часть II.
3. **Часть I (главы 01–15)** — Fusion 2.0.5, Host Mode. Это приёмы, проверенные
   кодом, но в узкой рамке.
4. **Твоя память о Fusion** — последняя по приоритету. API между Fusion 1 и 2
   менялся несоответствующе (`[Networked(OnChanged=)]` → `[OnChangedRender]` и
   далее), и путаница версий — главный источник неработающего кода. Нужна подпись —
   смотри главу 90, а не память.

Если в руководстве ответа нет — так и скажи. Раздел `Чего по этой теме нет в
учебном курсе` в каждой главе части II существует именно для этого.

## 8. Как ссылаться в ответе пользователю

Ссылайся на главу и раздел, и давай строки, чтобы он мог проверить:
«гл. 06, `Реализация по шагам`, строки 4663–5035». В единый документ ведут якоря
`#ch-06`, они все проверены. На отдельные файлы — обычной ссылкой:
`[гл. 06](guide/06-chapter.md)`.

Код из руководства — дословный из учебных проектов. Места, где приём
рекомендован, но в проекте не реализован, в тексте помечены
`⚠️ в проекте не реализовано` — не выдавай их за проверенный код.

## 9. Границы

Чего в руководстве нет, и об этом надо говорить прямо, а не достраивать:

- **Shared Mode и WebGL на практике.** Разобраны теоретически (главы 20, 21);
  кода под них в курсе нет. Photon рекомендует для WebGL именно Shared, то есть
  приёмы части I под веб по умолчанию не переносятся.
- **Fusion 2.1.** Свободный tick rate 8–256 Гц, Send Priority, Forecast Physics —
  описаны по документации в главах 21 и 23, но кода на 2.1 нет: курс на 2.0.5.
- **Quantum, Voice, PUN.** Только обзорно, глава 26.
- **Цены и лимиты CCU** верны на дату сборки (ноябрь 2026) — перепроверяй.
- **Dedicated server** — глава 27 про выбор и стоимость, а не пошаговый деплой.

## 10. Если документ пересобран

`MAP.txt` и все диапазоны строк в этом файле действительны для текущей сборки
(14 864 строки, 325 якорей). После любой правки `guide/*.md` и пересборки единого
документа диапазоны сдвинутся. Тогда:

1. Перегенерируй карту: `perl guide/map.pl "<документ>" > guide/MAP.txt`.
2. Проверь, что ядро всё ещё там, где написано в §2:
   `grep -n 'Модель мира Fusion 2\|Границы применимости' "<документ>"`.
3. Обнови числа в §2, §3 и §6 этого файла.

Пока это не сделано, считай номера строк здесь ориентировочными и находи разделы
через `grep` по `MAP.txt`, а не по памяти.
